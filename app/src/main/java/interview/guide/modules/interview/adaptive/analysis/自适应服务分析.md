## 三、方法功能详解

### 3.1 `evaluateAndDecideSafely` — 对外安全入口

**功能**：供 `InterviewSessionService.submitAnswer()` 调用，在每轮答题后执行自适应评估。全程 try-catch 包裹，任何异常都捕获并返回 null，**保证不中断主答题流程**。

**算法流程**：

```
1. persistenceService.findBySessionId(sessionId) → 查会话 Entity
2. 会话不存在 → log.warn → return null（安全退出）
3. 从 Entity 读取 llmProvider、difficulty、abilityProfileJson
4. 调用 evaluateAndDecide(llmProvider, difficulty, profileJson, question, answer)
5. 调用 persistResult() 将评估结果写回数据库
6. return AdaptiveInterviewResultDTO
7. catch any Exception → log.warn → return null
```

**安全设计的两层含义**：
- 会话不存在时不抛异常，返回 null
- 评估过程中 LLM 调用失败、DB 写入失败等所有异常统一捕获，返回 null

---

### 3.2 `attachAdaptiveAnalysis` — 报告增强

**功能**：供 `InterviewSessionService.generateReport()` 调用，在基础评估报告上附加能力画像和自适应追踪链。

**算法流程**：

```
1. persistenceService.findBySessionId(sessionId) → 查会话 Entity
2. 会话不存在 → 返回原始 report（不抛异常）
3. abilityProfileService.parseProfile(entity.abilityProfileJson) → AbilityProfileDTO
4. parseTrace(entity.adaptiveTraceJson) → List<AdaptiveTraceDTO>
5. 使用 InterviewReportDTO 11 参数全量构造器覆盖原报告
6. return 新报告
```

**关键设计**：用 11 参数构造器（含 `abilityProfile` 和 `adaptiveTrace`）替代 `AnswerEvaluationService` 产出的 9 参数版本（这两个字段为 null）。

---

### 3.3 `evaluateAndDecide` — 核心编排方法

**功能**：按固定顺序编排三个子服务，完成一轮完整的自适应评估+决策。

**算法流程（三步流水线）**：

```
步骤1：turnEvaluationService.evaluateTurn(llmProvider, question, answer)
  └── LLM 即时评估 → TurnEvaluationDTO（得分、深度等级、缺失知识点、分类、追问建议）

步骤2：abilityProfileService.updateProfile(previousProfileJson, evaluation)
  └── 加权移动平均合并 → AbilityProfileDTO（各维度画像、平均分、强弱项摘要）

步骤3：try {
    adaptiveDecisionService.decideNextStep(llmProvider, difficulty, question, answer, evaluation, profile)
    → LLM 驱动决策（主路径）
  } catch (Exception e) {
    adaptiveDecisionService.fallbackDecision(question, evaluation, difficulty)
    → 本地规则兜底（不依赖 LLM）
  }
  └── AdaptiveDecisionDTO（动作、目标分类、难度、原因、追问文本）

返回：new AdaptiveInterviewResultDTO(evaluation, profile, decision)
```

**容错机制**：步骤 3 的 LLM 调用失败时降级到本地规则兜底，保证流程不中断。

---

### 3.4 `persistResult` — 持久化

**功能**：将本轮评估结果写入数据库，更新追踪链。

**执行流程**：

```
1. parseTrace(previousTraceJson) → 反序列化历史追踪链
2. 追加本轮记录：new AdaptiveTraceDTO(questionIndex, category, evaluation, decision)
3. persistenceService.updateAnswerEvaluation(sessionId, questionIndex, score, feedback)
   → 将即时评分写入 InterviewAnswerEntity
4. abilityProfileService.toJson(profile) + toJson(trace)
   → 序列化画像和追踪链
5. persistenceService.updateAdaptiveState(sessionId, profileJson, traceJson)
   → 写入 InterviewSessionEntity
6. catch any Exception → log.warn（不向上抛出）
```

**追踪链追加机制**：每轮记录 `questionIndex + category + TurnEvaluationDTO + AdaptiveDecisionDTO`，形成完整的时间线。

---

### 3.5 `parseTrace` — JSON 反序列化

**功能**：将追踪链 JSON 字符串反序列化为 `List<AdaptiveTraceDTO>`。

**容错**：null 或空白输入 → `List.of()`；Jackson 异常 → `List.of() + log.warn`。

---

### 3.6 `toJson` — JSON 序列化

**功能**：将追踪链列表序列化为 JSON 字符串。异常声明 `throws JacksonException`，由调用方 `persistResult` 统一捕获。

---

### 3.7 `buildInstantFeedback` — 反馈文本构建

**功能**：组装给面试者的即时反馈文本。

**格式**：`"即时评估：{决策原因}"`，追问建议不为空时追加 `" 建议追问：{追问建议}"`。决策原因为空时兜底为 `"已完成本轮即时评估。"`。

## 六、异常处理策略总结

| 方法 | 异常处理策略 |
|------|------------|
| `evaluateAndDecideSafely` | 全量 try-catch，任何异常返回 null，不中断主流程 |
| `attachAdaptiveAnalysis` | 会话不存在返回原始报告，不抛异常 |
| `evaluateAndDecide` | LLM 决策失败降级到 `fallbackDecision`（本地规则），不抛异常 |
| `persistResult` | 全量 try-catch，DB 写入失败仅 log.warn，不向上抛出 |
| `parseTrace` | 反序列化失败返回空列表 + log.warn |
| `toJson` | 声明 `throws JacksonException`，由 `persistResult` 统一 catch |
| `buildInstantFeedback` | 无异常，空值全部有兜底逻辑 |
