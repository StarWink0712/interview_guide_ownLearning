## 4 个 Prompt 模板

这是 **StringTemplate 格式**（`.st` 文件），运行时用 `{变量名}` 占位符替换为实际值。分两组，对应两路出题：

---

### 出题时怎么拼 Prompt？

每次调用 LLM 需要两个 Prompt：**系统提示词**（设定角色） + **用户提示词**（具体数据）。

```
发送给 LLM 的消息 = [System Prompt] + [User Prompt]

System: "你是一位技术面试官，请根据简历出题..."
User  : "简历内容：张三的简历... 出6道题，难度中级"
```

---

### 方向题（Skill）— 2 个模板

**系统模板**（`interview-question-skill-system.st`）：
```
角色：你是一位技术面试官，擅长设计考察基础和深度的题目
任务：根据问题分布生成面试题
出题标准：
  - 使用经验 → 核心原理 → 边界/优化 递进追问
  - 基础30% / 进阶50% / 专家20%
约束：
  - 题数必须精确
  - type 字段用给定的分类 key
  - 不要调用工具，直接用提供的参考内容
```

**用户模板**（`interview-question-skill-user.st`）：
```
请生成 {questionCount} 个主问题，每个带 {followUpCount} 个追问
难度：{difficultyDescription}
方向：{skillName}（{skillDescription}）
问题分布表：{allocationTable}
已考知识点：{historicalSection}
参考题库：{referenceSection}
JD描述：{jdSection}
输出格式：topicSummary 必填（10字内知识点摘要）
```

---

### 简历题（Resume）— 2 个模板

**系统模板**（`interview-question-resume-system.st`）：
```
角色：你是一位专注项目经历追问的技术面试官
任务：根据简历生成针对项目经历和技术决策的深度问题
出题标准：
  - 只能针对简历中明确提到的项目提问，严禁编造
  - 重点考察：项目背景、技术选型理由、挑战与方案、个人贡献
  - 追问递进：使用经验 → 核心原理 → 边界/优化
难度分布：基础30% / 进阶50% / 专家20%
约束：
  - 禁止使用"你在'XXX项目'中提到..."
  - 题数必须精确
```

**用户模板**（`interview-question-resume-user.st`）：
```
请生成 {questionCount} 个针对项目经历的面试问题，每个带 {followUpCount} 个追问
方向：{skillName}
难度：{difficultyDescription}
候选人简历：
---简历内容开始---
{resumeText}
---简历内容结束---
已考知识点：{historicalSection}
输出格式：topicSummary 必填
```

---

### 为什么分 System 和 User？

这是 LLM 的通用做法：

```
System：设定规则（角色、约束、格式要求）→ 不变的部分，每次出题都一样
User  ：给出数据（简历内容、题目数量、难度、历史题目）→ 变化的，每次不同
```

System 给模型建立"我是面试官"的身份认知和出题规范，User 给具体的输入数据。两者拼成完整的一条请求发给 LLM。

---

### 运行时效果

以简历题为例，实际拼出来的完整 Prompt：

```
System:
你是一位专注项目经历追问的技术面试官。
只能针对简历中明确提到的项目提问，严禁编造。
出题标准：基础30%、进阶50%、专家20%...

User:
请生成 6 个针对项目经历的面试问题。
方向：Java后端开发
难度：中级
候选人简历：
张三，5年Java开发经验，主导过电商支付系统重构...
已考知识点：HashMap底层实现（不要重复）
输出格式：topicSummary 必填
```

LLM 收到后按 System 的约束、用 User 的数据，返回 6 道结构化面试题。
