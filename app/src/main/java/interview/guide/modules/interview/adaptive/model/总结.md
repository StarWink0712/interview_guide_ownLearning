1\. TurnEvaluationDTO — 单轮即时评估结果

```java
public record TurnEvaluationDTO(
    int questionIndex,              // 题号
    int score,                      // 本轮得分 0-100
    int depthLevel,                 // 回答深度等级 1-5
    List<String> missingKeyPoints,  // 缺失的关键知识点
    String followUpSuggestion,      // 追问建议
    String category                 // 本轮评估的能力分类
) {}
```

**作用**：代表 LLM 对面试者**单次答题**的即时评估。每次面试者提交一道题的答案后，`TurnEvaluationService.evaluateTurn()` 调用 LLM 产出这个对象。

**字段详解**：

- `questionIndex` — 被评估的是第几题
- `score` — 0-100 的整数得分，标准化阶段会钳位到 \[0, 100]
- `depthLevel` — 回答深度，1（浅层记忆）到 5（深度理解+实践），会被钳位到 \[1, 5]
- `missingKeyPoints` — 面试者遗漏的关键知识点列表，标准化时过滤空值并截断到最多 10 个
- `followUpSuggestion` — LLM 给出的追问建议文本，指导下一轮追问方向
- `category` — 本轮题目属于哪个能力分类（如"算法能力"、"系统设计"），LLM 可能返回空，标准化时会用原题的 category 兜底

**数据流向**：

- 被 `AbilityProfileService.updateProfile()` 消费 → 合并到能力画像中
- 被 `AdaptiveDecisionService` 的两个决策方法消费 → 作为决策依据
- 被封装到 `AdaptiveInterviewResultDTO` 和 `AdaptiveTraceDTO` 中

## 2. AbilityDimensionDTO — 单个能力维度的累积画像

```java
public record AbilityDimensionDTO(
    String category,           // 能力分类名称
    int score,                 // 该维度加权平均分
    double confidence,         // 置信度 0.25~1.0
    int questionCount,         // 已评估次数
    String recentPerformance,  // 最近表现标签
    List<String> weakKeywords  // 薄弱关键词（最多 8 个）
) {}
```

**作用**：代表面试者在**某一个能力维度**上的累积表现。它不是单次评估的快照，而是多轮评估通过**加权移动平均**合并后的结果。

**字段详解**：

- `category` — 能力分类名称，如"算法能力"、"系统设计"、"并发编程"，是维度的唯一标识
- `score` — 加权移动平均分。公式：`(previousScore × previousCount + 本轮得分) / (previousCount + 1)`。这样早期表现和近期表现都被合理计入，不会因为某一次超常或失常而剧烈波动
- `confidence` — 置信度，起始 0.25，每多评估一次 +0.15，上限 1.0。评估次数越多，对这个维度的判断越有把握。1 次评估信心不足（0.4），5 次就接近满信心（1.0）
- `questionCount` — 该维度已经被评估了多少道题，等同于采样数
- `recentPerformance` — 最近一次该维度得分的等级标签："优秀"（≥85）、"稳定"（≥70）、"一般"（≥55）、"薄弱"（<55）。只反映最近一轮，不反映历史平均
- `weakKeywords` — 从历史多轮评估中累积的薄弱关键词。通过 `mergeWeakKeywords` 方法将过去的 `weakKeywords` 与本轮 `missingKeyPoints` 合并去重，保留插入顺序，上限 8 个

**数据流向**：

- 被 `AbilityProfileDTO.dimensions` 聚合 → 各维度组成完整画像
- 自身不独立存储，始终作为 AbilityProfileDTO 的组成部分

## 3. AbilityProfileDTO — 面试者整体能力画像

```java
public record AbilityProfileDTO(
    List<AbilityDimensionDTO> dimensions,  // 各能力维度列表
    int averageScore,                      // 所有维度平均分
    String summary                         // 强弱项摘要文本
) {}
```

**作用**：代表面试者**跨所有能力维度**的完整能力画像。每次答题后被 `AbilityProfileService.updateProfile()` 更新一版。

**字段详解**：

- `dimensions` — 按插入顺序排列的维度列表。使用 `LinkedHashMap` 保证顺序稳定性，每个维度对应一个能力分类。比如面试过"算法能力"和"系统设计"两个分类后，列表就有两个元素
- `averageScore` — 对所有 `dimensions` 中各维度 `score` 取平均值再四舍五入。反应面试者的综合水平
- `summary` — 文字摘要，格式 `"当前强项：X，待加强：Y"`，取最高分和最低分维度。维度为空时显示 `"暂无能力画像"`

**数据流向**：

- 由 `AbilityProfileService.updateProfile()` 产出 → 被 `AdaptiveDecisionService.decideNextStep()` 作为决策依据（序列化为 JSON 注入 LLM Prompt）
- 通过 `AbilityProfileService.toJson()` 序列化为 JSON 字符串 → 存入数据库 `InterviewSessionEntity.abilityProfileJson`
- 通过 `AbilityProfileService.parseProfile()` 反序列化 → 在报告生成时注入到 `InterviewReportDTO`

## 4. AdaptiveDecisionDTO — 下一步策略决策

```java
public record AdaptiveDecisionDTO(
    String action,          // 决策动作
    String targetCategory,  // 目标能力分类
    String nextDifficulty,  // 下一题难度
    String reason,          // 决策原因
    String nextQuestion     // 追问/下一题文本（可为 null）
) {}
```

**作用**：决定面试**接下来要做什么**。由 `AdaptiveDecisionService` 通过 LLM 主路径或本地规则兜底产出。

**字段详解**：

- `action` — 6 种预定义动作之一：
  | 动作                  | 含义      | 触发场景                   |
  | ------------------- | ------- | ---------------------- |
  | `FOLLOW_UP`         | 追问当前题目  | 回答有缺失，需要确认深度           |
  | `NEXT_CATEGORY`     | 切换到下一分类 | 当前回答达标，换方向             |
  | `RAISE_DIFFICULTY`  | 提升难度    | 回答优秀，junior→mid→senior |
  | `LOWER_DIFFICULTY`  | 降低难度    | 回答过差，降级考察              |
  | `DEEP_DIVE_PROJECT` | 深挖项目经验  | 适合追问项目细节               |
  | `END_PHASE`         | 结束当前阶段  | 该阶段考察完毕                |
  非法值会被 `normalizeAction()` 统一回退为 `FOLLOW_UP`
- `targetCategory` — 下一题应该考察哪个能力分类。LLM 可能返回 null，标准化时用原题分类兜底
- `nextDifficulty` — 下一题的难度等级（junior/mid/senior）。空值时保持当前难度不变
- `reason` — 决策理由文本，同时作为给面试者的即时反馈展示
- `nextQuestion` — 追问题目文本，仅在 `FOLLOW_UP` 动作时有值。`NEXT_CATEGORY` 时下一题由出题服务重新生成。空白字符串转为 null

**数据流向**：

- 由 `AdaptiveDecisionService.decideNextStep()`（LLM 主路径）或 `fallbackDecision()`（本地兜底）产出
- 被封装到 `AdaptiveInterviewResultDTO` 和 `AdaptiveTraceDTO` 中
- `reason` 字段被用于构建给面试者的即时反馈文本

***

## 5. AdaptiveInterviewResultDTO — 单轮三合一聚合结果

```java
public record AdaptiveInterviewResultDTO(
    TurnEvaluationDTO turnEvaluation,    // 本轮即时评估
    AbilityProfileDTO abilityProfile,    // 更新后的能力画像
    AdaptiveDecisionDTO adaptiveDecision // 下一步策略决策
) {}
```

**作用**：`AdaptiveInterviewService.evaluateAndDecide()` 的**一次性返回值**，将一轮完整自适应流程的三个产出打包在一起，避免多次调用或参数传递混乱。

**字段详解**：

- `turnEvaluation` — 来自 `TurnEvaluationService`，本轮答得怎么样
- `abilityProfile` — 来自 `AbilityProfileService`，合并本轮后的最新画像
- `adaptiveDecision` — 来自 `AdaptiveDecisionService`，接下来该怎么做

**数据流向**：

- 由 `AdaptiveInterviewService.evaluateAndDecide()` 产出
- 在 `persistResult()` 中拆解使用：`turnEvaluation` 用于写答题评分，`abilityProfile` 序列化存库，`adaptiveDecision` 用于构建反馈文本和追踪链
- 在 `evaluateAndDecideSafely()` 中直接返回给上层 `InterviewSessionService`

***

## 6. AdaptiveTraceDTO — 单轮决策追踪快照

```java
public record AdaptiveTraceDTO(
    int questionIndex,                    // 题号
    String category,                      // 题目分类
    TurnEvaluationDTO turnEvaluation,     // 该轮评估结果
    AdaptiveDecisionDTO adaptiveDecision  // 该轮决策结果
) {}
```

**作用**：完整记录**某一轮答题**从评估到决策的全过程。每轮答题后创建一条，追加到列表中，最终序列化为 JSON 存入数据库，用于在报告中展示完整的自适应决策历程。

**字段详解**：

- `questionIndex` — 第几轮答题
- `category` — 该题的能力分类
- `turnEvaluation` — 该轮的 LLM 评估快照（得分、缺失知识点等）
- `adaptiveDecision` — 该轮 LLM 产出的下一步策略快照（动作、原因等）

**数据流向**：

- 由 `AdaptiveInterviewService.persistResult()` 逐轮追加创建
- 历史追踪链从数据库 `adaptiveTraceJson` 反序列化 → 追加本轮 → 序列化覆盖写回
- 在 `attachAdaptiveAnalysis()` 中反序列化注入到 `InterviewReportDTO` → 最终展示在面试报告里

***

### 整体关系一句话总结

```
TurnEvaluationDTO（本轮答得怎么样）
    │
    ▼ 合并入
AbilityDimensionDTO（某个维度累积表现）→ 聚合为 AbilityProfileDTO（完整画像）
    │                                              │
    │                                  序列化为 JSON 存库 / 注入 LLM Prompt
    │
    ▼ 传给决策服务
AdaptiveDecisionDTO（下一步怎么做）
    │
    ▼ 三合一打包
AdaptiveInterviewResultDTO（本轮完整结果）
    │
    ▼ 逐轮追加
AdaptiveTraceDTO（本轮追踪快照）→ List 序列化存库 → 报告展示
```
