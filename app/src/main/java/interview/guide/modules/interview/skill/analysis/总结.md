       
## interview.skill 包分析

这个包负责**面试方向（Skill）的管理**——定义每个面试方向考什么、怎么分配题目、以及给 LLM 参考什么资料。

---

### 整体架构

```
classpath:skills/
  ├── java-backend/
  │   ├── SKILL.md          ← 方向名称、描述、prompt role（front matter）
  │   ├── skill.meta.yml    ← 展示配置 + 分类定义（含参考资料绑定）
  │   └── references/       ← 知识点参考文件（注入 Prompt 帮助 LLM 出题）
  │       ├── java-basic.md
  │       ├── concurrency.md
  │       └── mysql.md
  ├── python-backend/
  ├── system-design/
  ├── _shared/references/   ← 跨方向共享的参考文件
  └── ...
```

启动时，`InterviewSkillService` 扫描 `classpath:skills/*/SKILL.md`，解析所有预设方向。

---

### 3 个文件职责

| 文件 | 职责 |
|------|------|
| `InterviewSkillProperties` | 纯数据结构定义（5 个内部类，YAML 反序列化目标） |
| `InterviewSkillService` | 核心业务逻辑（加载、分类分配、参考注入、JD 解析） |
| `InterviewSkillController` | REST API（列出方向、查看详情、JD 解析） |

---

### InterviewSkillProperties — 数据结构

纯 POJO，定义 Skill 的配置模型：

```
SkillDefinition（运行时聚合）
  ├── name, description（来自 SKILL.md front matter）
  ├── persona（SKILL.md body，LLM 出题时的角色设定）
  ├── displayName, display（来自 skill.meta.yml）
  └── List<CategoryDef>（来自 skill.meta.yml）
        ├── key       → "JAVA_BASIC"
        ├── label     → "Java基础"
        ├── priority  → "CORE" / "ALWAYS_ONE" / null
        ├── ref       → "java-basic.md"  （绑定的参考文件）
        └── shared    → 参考文件是否跨方向共享
```

**举例**：`java-backend` 方向下，"并发编程"分类绑定了 `concurrency.md`，出题时该文件内容会被注入 Prompt。

---

### InterviewSkillService — 核心服务

#### 启动加载（@PostConstruct）

```
① 扫描 classpath:skills/*/SKILL.md
② 解析每个文件的 front matter（YAML）→ name/description
③ 提取 body → persona（LLM 角色设定）
④ 加载 skill.meta.yml → displayName、分类定义
⑤ 构建 categoryRefIndex（分类 key → 参考文件映射）
⑥ 构建 cachedReferenceFileList（JD 解析用的文件清单）
⑦ 缓存到 presetRegistry（TreeMap，按 key 排序）
```

#### 分类分配算法（calculateAllocation）

出题时决定 10 道题怎么分给各个分类。**三级优先级**：

```
ALWAYS_ONE → 必保 1 题（如"自我介绍"）
CORE       → 核心分类，优先分配多余名额
NORMAL     → 普通分类，填坑用

例：10 题分配给 [Java基础(CORE), 并发(CORE), JVM(NORMAL), 自我介绍(ALWAYS_ONE)]

Phase 1: 自我介绍 1 题 → 剩 9 题
Phase 2: Java基础 1 题, 并发 1 题, JVM 1 题 → 剩 6 题
Phase 3: CORE 轮转 → Java基础 +1, 并发 +1 → 剩 4 题
         再转→ Java基础 +1, 并发 +1 → 剩 2 题
         再转→ Java基础 +1, 并发 +1 → 剩 0 题

结果: {自我介绍:1, Java基础:4, 并发:4, JVM:1}
```

#### 参考内容注入（buildReferenceSection）

出题和评估时，把分类绑定的参考文件内容注入 Prompt：

```
skill.categories 中每个分类:
  if (有 ref 配置):
    从 classpath 加载参考文件 → 拼入 Prompt 的 "### 分类名" 区块
  if (总长度超过 12000 字符):
    截断

用途：
  - 出题：buildReferenceSection(skill, allocation) → 12000 字符上限
  - 评估：buildEvaluationReferenceSection(skillId) → 6000 字符上限
```

#### JD 解析（parseJd）

用户粘贴职位描述，AI 自动提取面试分类：

```
① 校验 JD 长度 ≥ 50 字
② 获取默认 ChatClient
③ 渲染系统 Prompt（含 referenceFileList，让 LLM 知道有哪些可用参考文件）
④ 用户 Prompt = 清洗后的 JD 文本
⑤ structuredOutputInvoker.invoke() → 结构化输出
⑥ 返回 List<CategoryDTO>（key、label、priority、ref）
```

#### custom Skill 构建（buildCustomSkill）

JD 解析结果 → 匹配本地参考文件 → 构建自定义 SkillDTO：

```
LLM 返回的分类 key → 查 categoryRefIndex → 匹配到本地参考文件
                                         → 纠正 LLM 可能返回的错误 ref
```

---

### InterviewSkillController — REST API

| 接口 | 方法 | 说明 |
|------|------|------|
| `GET /api/interview/skills` | `listSkills()` | 列出所有预设方向 |
| `GET /api/interview/skills/{id}` | `getSkill(id)` | 获取单个方向详情 |
| `POST /api/interview/skills/parse-jd` | `parseJd(request)` | AI 解析 JD 提取分类（IP 限流 5 次/秒） |

---

### 在整个面试流程中的位置

```
创建面试时
  frontend: 用户选择面试方向（java-backend / custom + JD）
      │
      ▼
  InterviewQuestionService.generateQuestionsBySkill()
      │
      ├── skillService.getSkill(skillId)           ← 获取方向定义
      ├── skillService.calculateAllocation()       ← 计算题目分配
      ├── skillService.buildReferenceSection()     ← 注入参考资料到 Prompt
      └── skillService.buildCustomSkill()          ← JD 解析结果构建自定义方向

评估时
  AnswerEvaluationService.evaluateInterview()
      │
      └── skillService.buildEvaluationReferenceSectionSafe(skillId)
          ← 注入评估参考基线到 Prompt
```

**一句话总结**：这个包就是面试的"考纲管理系统"——定义每个方向考什么分类、怎么分配题数、给 LLM 参考什么资料，以及支持用户粘贴 JD 自动生成考纲。
