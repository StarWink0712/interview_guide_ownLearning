## 项目数据库操作场景详解

### 📌 为什么需要数据库？

AI 面试平台需要存储各种业务数据，以便：
- **持久化用户数据**：简历、面试记录、知识库文档
- **状态跟踪**：异步任务处理状态（向量化、分析、评估）
- **历史查询**：回顾过去的面试、查看分析结果
- **去重管理**：避免重复上传相同文件

---

### 📊 核心表详解

#### 1. LLM Provider 配置

| 表名 | `llm_provider` | `llm_global_setting` |
|------|---------------|---------------------|
| **用途** | 存储多个 LLM 服务商配置 | 存储默认 Provider 设置 |
| **关键字段** | id, baseUrl, apiKey(加密), model, embeddingModel | defaultChatProviderId, defaultEmbeddingProviderId |
| **操作场景** | 用户添加/修改/删除 Provider | 应用启动时初始化、切换默认 Provider |

```sql
-- 示例数据
INSERT INTO llm_provider (id, base_url, api_key_nonce, api_key_ciphertext, model, embedding_model, supports_embedding, enabled) 
VALUES ('dashscope', 'https://dashscope.aliyuncs.com/...', 'nonce123', 'cipher456', 'qwen-plus', 'text-embedding-v3', true, true);
```

**操作场景**：
- ✅ 用户通过 API 添加新的 LLM 服务商
- ✅ 修改服务商的 API Key
- ✅ 启用/禁用某个服务商
- ✅ 切换默认使用的服务商

---

#### 2. 简历管理

| 表名 | `resumes` | `resume_analysis` |
|------|-----------|-------------------|
| **用途** | 存储简历文件信息 | 存储 AI 分析结果 |
| **关键字段** | fileHash(唯一), originalFilename, storageKey, resumeText, analyzeStatus | resumeId, overallScore, strengths, improvements |
| **操作场景** | 上传简历、去重检查、查询简历 | 存储评分结果、查看分析报告 |

```sql
-- 上传简历时
INSERT INTO resumes (file_hash, original_filename, storage_key, resume_text, analyze_status) 
VALUES ('abc123...', '张三_简历.pdf', 'file/abc123.pdf', '张三是一名Java开发...', 'PENDING');

-- 异步分析完成后
UPDATE resumes SET analyze_status = 'COMPLETED' WHERE id = 1;

INSERT INTO resume_analysis (resume_id, overall_score, strengths, improvements) 
VALUES (1, 85, '[''项目经验丰富'']', '[''需要加强算法'']');
```

**操作场景**：
- ✅ 用户上传简历 → 插入 `resumes` 表
- ✅ 计算文件哈希 → 检查是否已存在（去重）
- ✅ 异步分析完成 → 更新 `analyzeStatus` 为 `COMPLETED`
- ✅ 保存 AI 评分结果 → 插入 `resume_analysis` 表
- ✅ 查询历史简历 → 按 `uploadedAt` 排序

---

#### 3. 面试会话

| 表名 | `interview_sessions` | `interview_answers` |
|------|---------------------|---------------------|
| **用途** | 存储面试会话状态 | 存储每个问题的答案 |
| **关键字段** | sessionId, skillId, difficulty, questionsJson, overallScore, status | sessionId, questionIndex, userAnswer, aiFeedback, score |
| **操作场景** | 创建会话、更新进度、保存评估结果 | 记录答案、AI 反馈、评分 |

```sql
-- 创建面试会话
INSERT INTO interview_sessions (session_id, skill_id, difficulty, questions_json, status) 
VALUES ('uuid-123', 'java-backend', 'mid', '[{"question":"..."}]', 'CREATED');

-- 提交答案
INSERT INTO interview_answers (session_id, question_index, user_answer, ai_feedback, score) 
VALUES ('uuid-123', 0, 'Java多线程...', '回答正确', 85);

-- 更新会话状态
UPDATE interview_sessions 
SET status = 'IN_PROGRESS', current_question_index = 1 
WHERE session_id = 'uuid-123';

-- 保存评估结果
UPDATE interview_sessions 
SET overall_score = 82, overall_feedback = '表现不错', status = 'EVALUATED' 
WHERE session_id = 'uuid-123';
```

**操作场景**：
- ✅ 用户开始面试 → 创建 `interview_sessions` 记录
- ✅ AI 生成题目 → 保存到 `questionsJson` 字段
- ✅ 用户提交答案 → 插入 `interview_answers` 记录
- ✅ AI 评估答案 → 更新 `interview_answers` 的 `aiFeedback` 和 `score`
- ✅ 面试完成 → 更新会话状态，保存总分和评价
- ✅ 查看历史面试 → 按 `createdAt` 排序查询

#### 4. 知识库管理

| 表名 | `knowledge_bases` | `rag_chat_sessions` | `rag_chat_messages` |
|------|-------------------|---------------------|---------------------|
| **用途** | 存储知识库文档 | 存储 RAG 聊天会话 | 存储聊天消息 |
| **关键字段** | fileHash(唯一), name, category, vectorStatus, chunkCount | sessionId, knowledgeBaseIds | sessionId, role, content |
| **操作场景** | 上传文档、向量化、查询 | 创建聊天会话 | 记录对话历史 |

```sql
-- 上传知识库文档
INSERT INTO knowledge_bases (file_hash, name, category, vector_status) 
VALUES ('def456...', 'Java并发编程.pdf', 'Java', 'PENDING');

-- 向量化完成
UPDATE knowledge_bases 
SET vector_status = 'COMPLETED', chunk_count = 150 
WHERE id = 1;

-- 创建 RAG 聊天会话
INSERT INTO rag_chat_sessions (session_id, knowledge_base_ids) 
VALUES ('uuid-456', '[1, 2, 3]');

-- 记录消息
INSERT INTO rag_chat_messages (session_id, role, content) 
VALUES ('uuid-456', 'user', 'Java 线程池怎么用？');
```

**操作场景**：
- ✅ 用户上传文档 → 插入 `knowledge_bases` 表
- ✅ 异步向量化 → 将文档分块并转换为向量
- ✅ 向量化完成 → 更新 `vectorStatus` 为 `COMPLETED`
- ✅ 用户提问 → 向量搜索相关文档片段
- ✅ RAG 生成回答 → 保存到 `rag_chat_messages` 表

### 🔄 典型业务流程中的数据库操作

#### 流程 1：简历上传与评分

```
用户上传简历
    ↓
1. 计算文件哈希 (SHA-256)
    ↓
2. 查询数据库：SELECT * FROM resumes WHERE file_hash = ?
    ↓
3. 如果已存在 → 返回已有简历信息
   如果不存在 → INSERT INTO resumes (...)
    ↓
4. 文件存储到 RustFS/S3
    ↓
5. 解析文件内容（Apache Tika）
    ↓
6. 发送异步任务到 Redis Stream
    ↓
7. 后台消费者接收任务 → 调用 AI 分析简历
    ↓
8. 保存分析结果：INSERT INTO resume_analysis (...)
    ↓
9. 更新简历状态：UPDATE resumes SET analyze_status = 'COMPLETED'
```

#### 流程 2：模拟面试

```
用户开始面试
    ↓
1. INSERT INTO interview_sessions (session_id, skill_id, difficulty, status = 'CREATED')
    ↓
2. AI 生成题目 → 保存到 questionsJson
    ↓
3. 返回第一题
    ↓
用户提交答案
    ↓
4. INSERT INTO interview_answers (session_id, question_index, user_answer)
    ↓
5. 发送异步任务到 Redis Stream
    ↓
6. 后台消费者 → AI 评估答案
    ↓
7. UPDATE interview_answers SET ai_feedback = ?, score = ?
    ↓
8. UPDATE interview_sessions SET current_question_index = ?
    ↓
9. 返回下一题
    ↓
用户完成所有题目
    ↓
10. 更新会话状态：UPDATE interview_sessions SET status = 'COMPLETED'
    ↓
11. 发送评估任务 → AI 生成综合评价
    ↓
12. UPDATE interview_sessions SET overall_score = ?, overall_feedback = ?
```

#### 流程 3：知识库问答

```
用户上传文档
    ↓
1. INSERT INTO knowledge_bases (file_hash, name, vector_status = 'PENDING')
    ↓
2. 发送向量化任务到 Redis Stream
    ↓
3. 后台消费者 → 分块 → Embedding → 存储到 pgvector
    ↓
4. UPDATE knowledge_bases SET vector_status = 'COMPLETED', chunk_count = ?
    ↓
用户提问
    ↓
5. INSERT INTO rag_chat_sessions (session_id, knowledge_base_ids)
    ↓
6. 插入用户消息：INSERT INTO rag_chat_messages (session_id, role = 'user', content)
    ↓
7. 问题向量化 → 搜索相似文档片段
    ↓
8. RAG 生成回答
    ↓
9. 保存回答：INSERT INTO rag_chat_messages (session_id, role = 'assistant', content)
```

### 💡 总结

| 问题 | 答案 |
|------|------|
| **为什么需要数据库？** | 持久化用户数据、跟踪状态、历史查询、去重管理 |
| **存储什么数据？** | 简历、面试会话、知识库文档、LLM 配置、用户操作记录 |
| **主要操作场景？** | 上传文件、创建会话、保存答案、AI 分析结果、查询历史 |
| **数据库类型？** | PostgreSQL（支持 JSON、向量搜索 pgvector） |
| **状态管理？** | 使用枚举字段（PENDING、IN_PROGRESS、COMPLETED）跟踪异步任务 |

**简单来说**：数据库是这个 AI 面试平台的"记忆"，记住用户上传的所有简历、每次面试的记录、每个知识库的文档，以及 AI 分析和评估的结果。
