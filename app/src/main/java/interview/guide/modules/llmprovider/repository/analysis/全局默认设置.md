LlmGlobalSettingRepository 详解

### 📌 接口作用

**LlmGlobalSettingRepository** 是全局设置的数据库操作接口，负责管理 `llm_global_setting` 表。

***

### 🗂️ 对应的数据库表

```sql
-- llm_global_setting 表结构
CREATE TABLE llm_global_setting (
    id BIGINT PRIMARY KEY,
    default_chat_provider_id VARCHAR(64) NOT NULL,      -- 默认聊天模型 Provider ID
    default_embedding_provider_id VARCHAR(64) NOT NULL, -- 默认向量化模型 Provider ID
    created_at TIMESTAMP NOT NULL,
    updated_at TIMESTAMP NOT NULL
);

-- 示例数据（只有一条记录）
INSERT INTO llm_global_setting (id, default_chat_provider_id, default_embedding_provider_id) 
VALUES (1, 'dashscope', 'dashscope');
```

***

### 🎯 单例模式设计

这个表采用**单例模式**，只有一条记录（`id = 1`）：

```java
public class LlmGlobalSettingEntity {
    // 固定的单例 ID
    public static final Long SINGLETON_ID = 1L;
    
    @Id
    private Long id;  // 始终为 1
    
    private String defaultChatProviderId;       // 如 "dashscope"
    private String defaultEmbeddingProviderId;  // 如 "dashscope"
}
```

**为什么只有一条记录？**

- 全局设置是系统级别的配置，整个应用只需要一份
- 所有用户共享相同的默认 Provider 设置
- 简化管理，不需要为每个用户单独配置

```
│         LlmProviderConfigService                                  │

│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 📝 代码示例

```java
@Service
public class LlmProviderConfigService {

    private final LlmGlobalSettingRepository globalSettingRepository;

    // 读取全局设置
    public LlmGlobalSettingEntity getGlobalSetting() {
        return globalSettingRepository.findById(1L)
            .orElseThrow(() -> new BusinessException(ErrorCode.GLOBAL_SETTING_NOT_FOUND));
    }

    // 更新默认 Chat Provider
    public void updateDefaultChatProvider(String providerId) {
        LlmGlobalSettingEntity setting = getGlobalSetting();
        setting.setDefaultChatProviderId(providerId);
        globalSettingRepository.save(setting);  // 更新单例记录
    }

    // 更新默认 Embedding Provider
    public void updateDefaultEmbeddingProvider(String providerId) {
        LlmGlobalSettingEntity setting = getGlobalSetting();
        setting.setDefaultEmbeddingProviderId(providerId);
        globalSettingRepository.save(setting);
    }
}
```

### 💡 两个 Repository 的对比

| 接口                             | 管理的表                 | 记录数          | 用途                 |
| ------------------------------ | -------------------- | ------------ | ------------------ |
| **LlmProviderRepository**      | `llm_provider`       | 多条（可添加多个服务商） | 管理所有 LLM 服务商配置     |
| **LlmGlobalSettingRepository** | `llm_global_setting` | 单条（id=1）     | 管理全局默认 Provider 设置 |

### 🎯 总结

| 问题                               | 答案                                                       |
| -------------------------------- | -------------------------------------------------------- |
| **这是全局设置接口吗？**                   | ✅ 是的                                                     |
| **管理什么数据？**                      | 全局默认 Chat Provider 和 Embedding Provider 的 ID             |
| **有几条记录？**                       | 只有 1 条（单例模式，id=1）                                        |
| **谁使用它？**                        | LlmProviderRegistry 读取默认配置，LlmProviderConfigService 更新配置 |
| **和 LlmProviderRepository 的区别？** | 后者管理多个服务商，前者只管理全局默认设置                                    |

**简单来说**：这个接口就像是系统的"全局设置面板"，只有一个开关（id=1），控制整个应用默认使用哪个 LLM 服务商。
