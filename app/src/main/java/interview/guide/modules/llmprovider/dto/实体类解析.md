详细讲解一下**llmprovider/dto**文件夹下的各个DTO实体类：

## 1. **ProviderDTO** - Provider配置数据传输对象
```java
public record ProviderDTO(
    String id,                    // Provider唯一标识
    String baseUrl,              // 服务基础URL
    String maskedApiKey,         // 脱敏的API密钥（不暴露真实密钥）
    String model,                // 聊天模型
    String embeddingModel,       // 向量模型
    Integer embeddingDimensions, // 向量维度
    boolean supportsEmbedding,   // 是否支持向量功能
    Double temperature,          // 温度参数
    boolean defaultChatProvider, // 是否为默认聊天Provider
    boolean defaultEmbeddingProvider // 是否为默认向量Provider
)
```
**作用**：向前端返回Provider的完整配置信息，**关键安全设计**是使用`maskedApiKey`而不是真实API密钥。

## 2. **CreateProviderRequest** - 创建Provider请求
```java
public record CreateProviderRequest(
    @NotBlank String id,           // 必填：Provider ID
    @NotBlank String baseUrl,      // 必填：服务地址
    @NotBlank String apiKey,        // 必填：API密钥
    @NotBlank String model,        // 必填：聊天模型
    String embeddingModel,         // 可选：向量模型
    Integer embeddingDimensions,   // 可选：向量维度
    Boolean supportsEmbedding,     // 可选：是否支持向量
    Double temperature            // 可选：温度参数
)
```
**特点**：
- 使用`@NotBlank`注解进行参数校验
- 提供了简化的构造函数
- 所有创建Provider的必填字段

## 3. **UpdateProviderRequest** - 更新Provider请求
```java
public record UpdateProviderRequest(
    String baseUrl,              // 可选：服务地址
    String apiKey,                // 可选：API密钥
    String model,                // 可选：聊天模型
    String embeddingModel,       // 可选：向量模型
    Integer embeddingDimensions, // 可选：向量维度
    Boolean supportsEmbedding,   // 可选：是否支持向量
    Double temperature          // 可选：温度参数
)
```
**特点**：
- 所有字段都是可选的，支持**部分更新**
- 仅更新非null的字段
- 提供了简化的构造函数

## 4. **DefaultProviderDTO** - 默认Provider配置
```java
public record DefaultProviderDTO(
    String defaultProvider,           // 默认聊天Provider ID
    String defaultEmbeddingProvider    // 默认向量Provider ID
)
```
**特点**：
- 支持单独设置默认聊天或向量Provider
- 提供了单一设置的构造函数

## 5. **ProviderTestResult** - 连通性测试结果
```java
public record ProviderTestResult(
    boolean success,    // 测试是否成功
    String message,     // 测试结果消息
    String model       // 测试使用的模型
)
```
**作用**：返回Provider或ASR配置的连通性测试结果。

## 设计模式和架构思想

### 1. **数据分离设计**
- **Request对象**：接收前端请求数据
- **DTO对象**：返回给前端的数据
- **使用脱敏字段**：避免敏感信息泄露

### 2. **不可变对象**
- 大量使用`record`类型，保证数据不可变
- 提供线程安全的数据传递

### 3. **验证机制**
- `@NotBlank`注解确保必填字段
- 前后端双重验证

### 4. **部分更新支持**
- Update系列所有字段可选
- 支持增量更新，提高灵活性

### 5. **统一响应格式**
- 所有DTO都配合`Result<T>`使用
- 保持API响应的一致性
