我用一个具体例子走一遍完整流程。

***

## 加密过程（你输入 API Key → 得到密文）

假设你的 API Key 是 `sk-abc123`（11字节）。

### 第一步：生成 12 字节随机 nonce

```java
byte[] nonce = new byte[12];        // 12 字节 = 96 位
secureRandom.nextBytes(nonce);      // 填入随机值
// 例如：nonce = [a3, 7f, 1c, ..., 9e]（12个随机字节）
```

### 第二步：初始化 AES-GCM 加密器

```java
Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
cipher.init(Cipher.ENCRYPT_MODE, secretKey, new GCMParameterSpec(128, nonce));
```

这里传入了三样东西：

- `secretKey`：256 位（32字节）的 AES 密钥，存在服务端内存里(从配置文件里面读取)
- `nonce`：刚才的 12 字节随机数，告诉 GCM "用这个当计数器起点"
- `GCM_TAG_BITS = 128`：要求生成 128 位认证标签

### 第三步：加密

```java
byte[] ciphertext = cipher.doFinal("sk-abc123".getBytes(UTF_8));
```

`doFinal()` 内部做了两件事：

```
明文 "sk-abc123"（11字节）
        │
        ▼
   AES-256 加密（用 secretKey）
        │
        ▼
   11 字节加密结果 + 16 字节认证标签
        │
        ▼
   输出 ciphertext = 27 字节
```

**密文长度 = 明文长度 + 16 字节（128位 GCM 标签）**

| 明文    | 密文             |
| ----- | -------------- |
| 11 字节 | 27 字节（11 + 16） |
| 20 字节 | 36 字节（20 + 16） |
| 32 字节 | 48 字节（32 + 16） |

### 第四步：Base64 编码后分开存储

```java
nonceBase64     = Base64(nonce)       // 12字节 → 16字符，如 "ox98Hf3k..."
ciphertextBase64 = Base64(ciphertext) // 27字节 → 36字符，如 "dGhpcyBp..."
```

存入数据库两条字段：`api_key_nonce` 和 `api_key_ciphertext`。

***

## 为什么每次相同明文得到不同密文？

因为 **nonce 每次随机**。看这个对比：

| 次数  |    nonce（随机）   | 明文          | 密钥 | 密文           |
| --- | :------------: | ----------- | -- | ------------ |
| 第1次 | `a3,7f,1c,...` | `sk-abc123` | 相同 | `xYz...AAA=` |
| 第2次 | `f2,8d,44,...` | `sk-abc123` | 相同 | `mNo...BBB=` |
| 第3次 | `c1,3e,99,...` | `sk-abc123` | 相同 | `pQr...CCC=` |

nonce 不同 → 加密器的内部状态不同 → 输出完全不同。这是 GCM 模式的安全特性，防止攻击者通过"相同密文 = 相同明文"来推测内容。

***

## 解密过程（密文 → 还原 API Key）

必须同时拿到 **nonce + ciphertext + secretKey**：

```java
// 1. Base64 解码回去
byte[] nonce       = Base64解码(nonceBase64);       // → 12字节
byte[] ciphertext  = Base64解码(ciphertextBase64);  // → 27字节

// 2. 用同一个 nonce 和密钥初始化解密器
Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
cipher.init(Cipher.DECRYPT_MODE, secretKey, new GCMParameterSpec(128, nonce));

// 3. 解密 + 自动验证认证标签
byte[] plainText = cipher.doFinal(ciphertext);
// → "sk-abc123"
```

**nonce 的作用就像锁的钥匙孔形状**——加密时用某个形状锁定，解密时必须用完全相同的形状才能打开。nonce 本身不是秘密（它和密文一起存储），但没有它就无法解密，因为解密器不知道当初加密用的什么 nonce。

### 认证标签验证

如果密文被人篡改了哪怕 1 位：

```
cipher.doFinal(被篡改的密文) → 抛出 AEADBadTagException
                              → 解密失败，拒绝返回结果
```

这保证了**完整性**——你拿到的明文一定是当初加密的原版，没有被中间人改动过。

***

## 一句话总结

```
加密：nonce(随机) + 明文 + 密钥 → AES-GCM → 密文(明文+16字节标签)
解密：密文 + 同一个nonce + 同一个密钥 → AES-GCM → 明文（标签验证通过才输出）

nonce 每次随机 → 同一明文每次密文不同 → 无法通过密文反推明文规律
```

加密：
secretKey(配置文件) + nonce(随机12字节) → AES-GCM → 密文(明文长度+16字节标签)
存储：nonce 和 密文 分开存，各自 Base64 编码

解密：
Base64解码(nonce) + Base64解码(密文) + secretKey → AES-GCM → 明文
标签验证自动完成，篡改过则直接抛异常
