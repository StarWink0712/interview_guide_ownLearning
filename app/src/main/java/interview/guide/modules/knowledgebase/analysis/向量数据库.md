## 📚 向量存储基础知识

### 1. **什么是向量存储？**

向量存储是一种专门用于存储和查询向量数据的数据库，它是**向量检索**的核心组件。在 RAG（检索增强生成）系统中，向量存储负责：

- **存储文档向量**：将文本转换为高维向量并存储
- **相似度搜索**：根据查询向量找到最相似的文档
- **元数据管理**：存储文档的额外信息（如知识库ID）

### 2. **向量存储的核心概念**

#### 2.1 **嵌入（Embedding）**
- **定义**：将文本转换为高维向量的过程
- **维度**：向量的长度（如 1024 维）
- **模型**：如 text-embedding-v3、OpenAI embeddings

#### 2.2 **相似度计算**
- **余弦相似度**：计算向量之间的夹角余弦值（-1 到 1）
- **欧氏距离**：计算向量之间的直线距离
- **内积**：计算向量的点积

#### 2.3 **索引结构**
- **HNSW（Hierarchical Navigable Small World）**：层次化可导航小世界图
- **IVF（Inverted File Index）**：倒排文件索引
- **Flat**：暴力搜索（精确但慢）

#### 3.1 **文档向量化流程**
```java
public void vectorizeAndStore(Long knowledgeBaseId, String content) {
    // 1. 删除旧向量数据
    deleteByKnowledgeBaseId(knowledgeBaseId);
    
    // 2. 文本分块
    List<Document> chunks = textSplitter.apply(List.of(new Document(content)));
    
    // 3. 添加元数据
    chunks.forEach(chunk -> chunk.getMetadata().put("kb_id", knowledgeBaseId.toString()));
    
    // 4. 分批向量化并存储
    for (int i = 0; i < batchCount; i++) {
        List<Document> batch = chunks.subList(start, end);
        vectorStore.add(batch);  // 向量化并存储
    }
}
```

#### 3.2 **相似度搜索流程**
```java
public List<Document> similaritySearch(String query, List<Long> knowledgeBaseIds, int topK, double minScore) {
    // 1. 构建搜索请求
    SearchRequest.Builder builder = SearchRequest.builder()
        .query(query)
        .topK(topK)
        .similarityThreshold(minScore);
    
    // 2. 添加过滤条件
    if (knowledgeBaseIds != null && !knowledgeBaseIds.isEmpty()) {
        builder.filterExpression(buildKbFilterExpression(knowledgeBaseIds));
    }
    
    // 3. 执行搜索
    return vectorStore.similaritySearch(builder.build());
}
```

## 🔧 具体实现细节

### 1. **文本分块策略**

#### 1.1 **分块器配置**
```java
// TokenTextSplitter 默认配置
this.textSplitter = TokenTextSplitter.builder().build();
// 每个 chunk 约 800 tokens，基于标点边界切分（无重叠）
```

#### 1.2 **分块逻辑**
```java
// 将长文档切分成多个小块
List<Document> chunks = textSplitter.apply(List.of(new Document(content)));
```

**为什么需要分块？**
- **API 限制**：避免超出模型最大输入长度
- **语义完整性**：保持每个块的语义完整性
- **检索精度**：小块更容易匹配到相关内容

### 2. **批量处理策略**

#### 2.1 **批量大小限制**
```java
// 阿里云 DashScope API 限制 batch size <= 10
private static final int MAX_BATCH_SIZE = 10;
```

#### 2.2 **批量处理逻辑**
```java
// 分批向量化并存储
int batchCount = (totalChunks + MAX_BATCH_SIZE - 1) / MAX_BATCH_SIZE;
for (int i = 0; i < batchCount; i++) {
    int start = i * MAX_BATCH_SIZE;
    int end = Math.min(start + MAX_BATCH_SIZE, totalChunks);
    List<Document> batch = chunks.subList(start, end);
    vectorStore.add(batch);  // 每批最多 10 个 chunks
}
```

### 3. **元数据管理**

#### 3.1 **元数据添加**

```java
// 为每个 chunk 添加知识库 ID
```

```java
// 构建过滤表达式
private String buildKbFilterExpression(List<Long> knowledgeBaseIds) {
    String values = knowledgeBaseIds.stream()
        .map(String::valueOf)
        .map(id -> "'" + id + "'")
        .collect(Collectors.joining(", "));
    return "kb_id in [" + values + "]";
}
```
