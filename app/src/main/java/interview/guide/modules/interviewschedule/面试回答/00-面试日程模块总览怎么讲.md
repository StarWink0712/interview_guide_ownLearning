# 面试日程模块总览怎么讲

## 1. 一句话定位

`interviewschedule` 模块负责真实面试日程的录入、解析、展示、状态管理和提醒。它把用户收到的面试邀请，从一段邮件、短信或聊天文本，沉淀成平台内可管理、可提醒、可跟进的面试日程。

面试中可以这样开场：

> 这个模块补齐的是 AI 面试平台里的“真实求职日程管理”闭环。用户不只是来平台模拟面试，还会收到真实公司的面试邀约。日程模块支持手动创建，也支持粘贴邀约文本后自动解析公司、岗位、时间、会议链接等信息，再把日程展示到日历和列表中，并提供状态流转、过期自动处理、站内提醒和邮件提醒。

## 2. 这个模块解决什么问题

没有日程模块时，用户的求职链路是割裂的：

```text
简历分析在平台
模拟面试在平台
真实面试时间在微信、邮箱、日历 App
复习提醒靠用户自己记
```

日程模块把这些串起来：

```text
收到邀约
  -> 粘贴文本智能解析
  -> 回填日程表单
  -> 创建 PENDING 日程
  -> 生成站内/邮件提醒计划
  -> 前端日历和列表展示
  -> 面试完成/取消/改期/过期自动处理
```

面试表达：

> 它不是单纯 CRUD，而是把“真实面试邀约”接入平台，让用户可以围绕具体公司、岗位和时间去准备模拟面试。

## 3. 目录下有哪些核心部分

| 部分 | 代表类 | 职责 |
| --- | --- | --- |
| 日程接口 | `InterviewScheduleController` | 提供解析、创建、查询、更新、删除、状态变更接口 |
| 日程服务 | `InterviewScheduleService` | 日程 CRUD、状态更新、DTO 转换、提醒同步 |
| 邀约解析 | `InterviewParseService` | 规则解析优先，失败后 AI 兜底 |
| 状态定时器 | `ScheduleStatusUpdater` | 每小时把过期 PENDING 日程批量改为 CANCELLED |
| 日程实体 | `InterviewScheduleEntity` | 映射 `interview_schedule` 表 |
| 日程仓库 | `InterviewScheduleRepository` | JPA CRUD、状态查询、时间范围查询、批量状态更新 |
| 提醒接口 | `InterviewReminderController` | 站内提醒列表、未读数、已读操作 |
| 提醒服务 | `InterviewReminderService` | 提醒计划生成、取消、认领、状态流转 |
| 提醒调度 | `InterviewReminderScheduler` | 定时扫描到期提醒并写入 Redis Stream |
| 提醒消费 | `InterviewReminderStreamConsumer` | 消费提醒任务，邮件发送或站内状态流转 |
| 邮件发送 | `SmtpReminderEmailSender` | 构建并发送真实 HTML 邮件 |

## 4. Controller 暴露哪些接口

日程接口基路径：

```text
/api/interview-schedule
```

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/parse` | 解析面试邀约文本，不写数据库 |
| `POST` | `/` | 创建面试日程，默认 PENDING |
| `GET` | `/{id}` | 查询单个日程 |
| `GET` | `/` | 按时间范围、状态或全量查询 |
| `PUT` | `/{id}` | 更新日程业务字段，不改状态 |
| `DELETE` | `/{id}` | 删除日程 |
| `PATCH/PUT` | `/{id}/status` | 更新日程状态 |

提醒接口基路径：

```text
/api/interview-schedule/reminders
```

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/in-app` | 查询站内提醒 |
| `GET` | `/unread-count` | 查询未读提醒数量 |
| `PATCH` | `/{id}/read` | 单条标记已读 |
| `PATCH` | `/read-all` | 全部标记已读 |

## 5. 业务主链路

```text
用户打开日程页
  -> GET /api/interview-schedule
  -> 日历/列表展示已有日程

用户粘贴邀约文本
  -> POST /api/interview-schedule/parse
  -> InterviewParseService 规则解析或 AI 解析
  -> 返回 CreateInterviewRequest
  -> 前端回填表单

用户确认创建
  -> POST /api/interview-schedule
  -> InterviewScheduleService.create
  -> 保存 interview_schedule
  -> InterviewReminderService.synchronizeReminders
  -> 生成站内/邮件提醒计划

到提醒时间
  -> 站内提醒可被前端查询展示
  -> dispatch-enabled=true 时进入 Redis Stream 异步投递

面试结束或取消
  -> updateStatus
  -> 状态变更
  -> 取消未完成提醒
```

## 6. 模块亮点

| 亮点 | 说明 |
| --- | --- |
| 邀约解析 | 先用正则解析飞书、腾讯会议、Zoom，失败后用 LLM 兜底 |
| 表单回填 | 解析结果不是直接入库，而是返回 `CreateInterviewRequest` 给前端确认 |
| 状态生命周期 | PENDING、COMPLETED、CANCELLED、RESCHEDULED，过期 PENDING 自动取消 |
| 提醒计划 | 每个 PENDING 日程生成提前一天、提前一小时的提醒 |
| 双渠道提醒 | 站内提醒默认生成，填写邮箱后额外生成邮件提醒 |
| 异步投递 | 到期提醒通过定时扫描和 Redis Stream 投递，避免事务里调用 SMTP |
| DTO 隔离 | Controller 返回 DTO，不直接暴露 Entity |

## 7. 当前实现边界

| 边界 | 当前情况 | 优化方向 |
| --- | --- | --- |
| 用户隔离 | 日程和站内提醒当前没有 `userId` | 接入登录后按用户过滤 |
| 状态机 | 状态更新接口允许改成任意枚举值 | 增加合法状态流转校验 |
| 查询能力 | `getAll` 是时间、状态、全量三选一 | 支持组合查询、分页和排序 |
| AI 解析 | AI 解析手动剥 JSON，不走 `StructuredOutputInvoker` | 迁移到结构化输出调用器 |
| 解析平台 | 规则只覆盖飞书、腾讯会议、Zoom | 扩展更多邮件模板和平台 |
| 邮件投递 | 自动派发默认关闭，需要 SMTP 配置 | 增加端到端邮件送达监控 |

## 8. 两分钟面试表达模板

> `interviewschedule` 是面试日程管理模块，它的价值是把用户真实求职过程中的面试邀约接入平台。用户可以手动创建日程，也可以粘贴面试邀请文本，后端通过规则解析和 AI 解析提取公司、岗位、面试时间、会议链接和轮次，然后返回给前端回填表单，用户确认后再创建日程。
>
> 日程创建后默认是 PENDING 状态，Service 会保存数据库并同步提醒计划。提醒分站内和邮件两个渠道，站内默认生成提前一天和提前一小时两条提醒；如果用户填写了邮箱，会再生成两条邮件提醒。提醒投递不是在日程事务里直接发邮件，而是先持久化计划，到期后由定时任务认领并写入 Redis Stream，消费者再执行 SMTP 投递或站内状态流转。
>
> 后台还有一个状态定时器，每小时把面试时间已过但仍为 PENDING 的日程批量改为 CANCELLED，并取消相关活跃提醒。这个模块的重点不是普通 CRUD，而是“邀约解析、日程生命周期、提醒计划和异步投递”的完整闭环。

## 9. 一句话总结

> 这个模块把真实面试邀约变成了平台内可解析、可管理、可提醒、可追踪状态的求职日程资产。
