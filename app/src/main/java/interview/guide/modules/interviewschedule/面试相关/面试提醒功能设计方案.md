# 邮件与站内面试提醒设计方案

该功能已经搭建完成，详细代码入口见：

```text
modules/interviewschedule/reminder/README.md
```

## 完整架构

```text
日程创建/修改
  → InterviewReminderService 同步提醒计划
  → interview_reminder 表
      ├─ 24 小时前：IN_APP + 可选 EMAIL
      └─ 1 小时前：IN_APP + 可选 EMAIL

每分钟扫描到期任务
  → 悲观锁认领并标记 QUEUED
  → Redis Stream
  → InterviewReminderStreamConsumer
      ├─ EMAIL：SmtpReminderEmailSender
      │    → JavaMailSender
      │    → 真实 SMTP HTML 邮件
      └─ IN_APP：标记到达
  → 失败最多重试 3 次
```

## 防重复设计

数据库唯一约束：

```text
schedule_id + channel + timing
```

同一日程、同一渠道、同一提醒时点只保留一条计划。修改时间或邮箱时更新原计划并重置状态，不会无边界新增重复任务。

## 日程联动

- PENDING 日程创建/修改：生成或刷新提醒。
- 关闭提醒：取消活动任务。
- 完成、取消、改期或删除：取消尚未完成的提醒。
- 自动过期任务：批量取消关联提醒。
- 重新设置为 PENDING：重新生成提醒计划。

## 站内提醒

前端 `ReminderBell` 每分钟读取未读数量，打开时显示到期提醒，支持单条已读和全部已读。当前项目没有用户系统，因此提醒暂时全局可见；接入认证后应增加 `userId` 隔离。

## 邮件提醒

邮件实现不是日志占位，而是：

```text
MimeMessage
  → MimeMessageHelper UTF-8
  → HTML 模板
  → JavaMailSender.send(message)
```

SMTP 地址、账号、密码、TLS、发件人和三个超时均通过配置注入。自动派发默认关闭，设置 `APP_INTERVIEW_REMINDER_DISPATCH_ENABLED=true` 后启用。

## 面试回答

> 我把提醒拆成计划、调度、队列和渠道四层。日程事务只负责写提醒计划，不在事务中调用 SMTP。定时器每分钟用悲观锁批量认领到期任务，再通过 Redis Stream 异步投递。消费者调用 JavaMailSender 发送真实 HTML 邮件，失败复用统一消费模板最多重试三次。站内提醒直接持久化并由前端轮询未读数。唯一约束防止重复计划，状态机和悲观锁减少重复调度；日程改期、取消和删除都会同步撤销旧提醒。
