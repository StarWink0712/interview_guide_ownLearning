### 三、完整业务流程（两大主线 + 一个后台任务）

#### 主线一：智能解析面试邀约文本

````
Step 1: 前端用户粘贴面试邀请文本
│  触发条件：用户在面试日程页面点击"解析"按钮，粘贴邮件/短信/聊天记录
│  请求：POST /api/interview-schedule/parse
│  入参：{ "rawText": "【字节跳动】面试邀请：Java 后端...", "source": null }
│
▼
Step 2: Controller.parse() 接收请求
│  @PostMapping("/parse") @Valid → 校验 rawText 不为空
│  调用 parseService.parse(rawText, source)
│
▼
Step 3: InterviewParseService.parse() 核心解析（三阶段降级）
│
│  ┌── 阶段1：规则解析（优先，毫秒级） ─────────────────────────┐
│  │  tryRuleParsing(rawText, source)                          │
│  │                                                           │
│  │  如果 source 指定了平台 → 直接用该平台的正则解析器           │
│  │  如果 source 为 null → 自动识别：                           │
│  │    含"飞书""meeting.feishu.cn"    → parseFeishu()         │
│  │    含"腾讯会议""会议号"            → parseTencent()        │
│  │    含"Zoom""zoom.us"              → parseZoom()           │
│  │    都不匹配 → 依次尝试三种格式（兜底）                       │
│  │                                                           │
│  │  提取的字段（正则匹配）：                                    │
│  │    公司名 → PATTERN 模式匹配                               │
│  │    岗位   → PATTERN 模式匹配                               │
│  │    时间   → 匹配后走 parseDateTime() 统一格式              │
│  │    会议链接 → URL 正则                                     │
│  │    轮次   → 中文数字映射（"二面"→2）                       │
│  │                                                           │
│  │  各平台差异：                                               │
│  │   飞书：结构化信息最全，可直接提取公司/岗位/时间/链接         │
│  │   腾讯：仅有时间+会议号+密码，公司/岗位可选                  │
│  │   Zoom：仅链接+时间，公司/岗位完全缺失（需走 AI）            │
│  │                                                           │
│  │  判断成功（isValidResult）：                                │
│  │  companyName≠null && position≠null && interviewTime≠null  │
│  │  → 返回 ParseResponse(success=true, confidence=0.95)      │
│  └───────────────────────────────────────────────────────────┘
│                           ↓ 失败
│  ┌── 阶段2：AI 解析（降级兜底，秒级） ────────────────────────┐
│  │  parseWithAI(rawText, provider)                            │
│  │                                                            │
│  │  1) Prompt 安全清洗：PromptSanitizer.sanitize()            │
│  │     移除用户输入中的恶意指令，防止 Prompt 注入               │
│  │                                                            │
│  │  2) 构建 Prompt：填充当前日期 + 清洗后文本                   │
│  │     PARSE_PROMPT 模板要求 LLM 返回纯 JSON，不许包 ```json   │
│  │                                                            │
│  │  3) 调用 LLM：                                             │
│  │     llmProviderRegistry.getChatClientOrDefault(provider)   │
│  │     → chatClient.prompt().user(prompt).call().content()    │
│  │                                                            │
│  │  4) 剥离 Markdown 代码块壳：                                │
│  │     LLM 返回 "我来帮你解析：```json\n{...}\n```"            │
│  │     → 正则提取 ``` ... ``` 中间的部分 → 纯 JSON 字符串      │
│  │                                                            │
│  │  5) JSON → Map → CreateInterviewRequest：                  │
│  │     objectMapper.readValue() → Map<String, Object>         │
│  │     逐个字段安全提取（处理空值、格式异常）                    │
│  │     companyName → request.setCompanyName()                 │
│  │     position → request.setPosition()                       │
│  │     interviewTime → 兼容 16/19 位格式                       │
│  │     interviewType → 直接赋值                                │
│  │     meetingLink → 直接赋值                                  │
│  │     roundNumber → Integer.parseInt()，异常时默认1           │
│  │     interviewer / notes → 直接赋值                          │
│  │                                                            │
│  │  成功 → ParseResponse(success=true, confidence=0.8)        │
│  └───────────────────────────────────────────────────────────┘
│                           ↓ 失败
│  ┌── 阶段3：全部失败 ────────────────────────────────────────┐
│  │  ParseResponse(success=false, data=null,                   │
│  │                 confidence=0.0, reason="解析失败")          │
│  └───────────────────────────────────────────────────────────┘
│
▼
Step 4: 前端收到 ParseResponse
│  成功 → 前端把 data（CreateInterviewRequest）回填到创建表单
│         用户检查/补充 → 点击"确认创建"
│  失败 → 前端提示"无法解析，请手动填写"
````

#### 主线二：日程 CRUD + 状态生命周期

```
┌─────────────────────────────────────────────────────────────────┐
│                      日程全生命周期                               │
│                                                                 │
│  ┌──────────┐   创建    ┌──────────┐   完成    ┌───────────┐   │
│  │ 解析结果  │ ───────→ │ PENDING  │ ───────→ │COMPLETED  │   │
│  │(Request) │  POST /  │ 待面试    │ PATCH /  │ 已完成     │   │
│  └──────────┘          └──────────┘  status   └───────────┘   │
│                              │                                  │
│                              │ PATCH /status (主动取消)         │
│                              │ 或 Scheduled 定时 (过期取消)      │
│                              ▼                                  │
│                         ┌──────────┐                           │
│                         │CANCELLED │                           │
│                         │ 已取消    │                           │
│                         └──────────┘                           │
│                                                                 │
│  期间 CRUD 操作：                                                │
│  GET  /{id}         查看单个日程（详情/编辑回显）                  │
│  GET  /             列表查询（支持状态筛选/时间范围/全量）          │
│  PUT  /{id}         更新（忽略 id 和 status，防篡改）             │
│  DELETE /{id}       物理删除                                    │
└─────────────────────────────────────────────────────────────────┘
```

**各操作详细流程：**

```
✅ POST /api/interview-schedule （创建日程）
   Controller.create(request)
     → scheduleService.create(request)
       → new InterviewScheduleEntity()
       → BeanUtils.copyProperties(request, entity)  // 同名字段批量复制
       → entity.setStatus(PENDING)                   // 初始状态
       → repository.save(entity)                      // @PrePersist 自动填时间戳
       → toDTO(entity)                                // Entity → DTO
       → 返回 InterviewScheduleDTO

✅ GET /api/interview-schedule/{id} （查询单个）
   Controller.getById(id)
     → scheduleService.getById(id)
       → getByIdOrThrow(id)
         → repository.findById(id)
            .orElseThrow(BusinessException(ErrorCode.INTERVIEW_SCHEDULE_NOT_FOUND, ...))
       → toDTO(entity) → 返回

✅ GET /api/interview-schedule?status=PENDING&start=...&end=... （列表查询）
   Controller.getAll(status, start, end)
     → scheduleService.getAll(status, start, end)
       ├─ start!=null && end!=null → repository.findByInterviewTimeBetween()  //日历视图
       ├─ status!=null              → repository.findByStatus(InterviewStatus.valueOf())
       └─ 都不传                     → repository.findAll()
       → entities.stream().map(this::toDTO).collect(toList())
       → 返回 List<InterviewScheduleDTO>

✅ PUT /api/interview-schedule/{id} （更新日程）
   Controller.update(id, request)
     → scheduleService.update(id, request)
       → getByIdOrThrow(id)                      // 先查是否存在
       → BeanUtils.copyProperties(request, entity, "id", "status") // 忽略id和status
       → repository.save(entity)                  // @PreUpdate 自动更新 updatedAt
       → toDTO(entity) → 返回

✅ DELETE /api/interview-schedule/{id} （删除日程）
   Controller.delete(id)
     → scheduleService.delete(id)
       → repository.deleteById(id)                // 物理删除
       → 不存在时 JPA 抛 EmptyResultDataAccessException，由全局异常处理器兜底

✅ PATCH/PUT /api/interview-schedule/{id}/status?status=COMPLETED （状态变更）
   Controller.updateStatus(id, status)
     → scheduleService.updateStatus(id, status)
       → getByIdOrThrow(id)                       // 查实体
       → entity.setStatus(status)                 // 直接 set 目标状态
       → repository.save(entity)
       → toDTO(entity) → 返回

   注意：update() 方法明确忽略 status 字段，状态变更必须走这个独立接口。
   这防止了客户端通过通用更新接口绕过业务规则修改状态。
```

#### 后台任务：定时清理过期日程

```
@Scheduled(cron = "0 0 * * * ?")   ← 每小时整点触发（10:00, 11:00, 12:00...）

ScheduleStatusUpdater.updateExpiredInterviews()
  └→ repository.updateStatusByStatusAndInterviewTimeBefore(
        CANCELLED,           // 目标状态
        PENDING,             // 当前状态
        LocalDateTime.now()) // 截止时间
     
     SQL: UPDATE interview_schedule
          SET status = 'CANCELLED'
          WHERE status = 'PENDING'
            AND interview_time < NOW()

     → 返回受影响行数 updated
     → if (updated > 0) → log.info("已将 N 条过期面试标记为已取消")

触发条件：@EnableScheduling（App.java）+ @Scheduled（定时器）→ 无需任何代码显式调用
```

### 四、异常处理机制

| 异常场景                | 处理方式                                    | 错误码                                   | 触发位置                                 |
| ------------------- | --------------------------------------- | ------------------------------------- | ------------------------------------ |
| 日程 ID 不存在           | `BusinessException`                     | `INTERVIEW_SCHEDULE_NOT_FOUND (9001)` | `getByIdOrThrow()`                   |
| 解析文本为空              | 返回 `ParseResponse(success=false)`       | 无（非异常情况）                              | `parse()` 入口                         |
| 规则正则匹配失败            | 降级到 AI 解析                               | 无                                     | `tryRuleParsing()` → `parseWithAI()` |
| LLM 返回空内容           | 返回 null → 最终 `success=false`            | 无                                     | `parseWithAI()`                      |
| LLM 返回的不是有效 JSON    | catch 后返回 null，记录日志                     | 无                                     | `parseWithAI()` try-catch            |
| 前端传了非法 status 值     | `IllegalArgumentException` → 全局异常处理器    | 通用 1xxx                               | `InterviewStatus.valueOf()`          |
| 时间格式解析失败            | 返回 null，不阻断流程                           | 无                                     | `parseDateTime()`                    |
| deleteById 的 id 不存在 | `EmptyResultDataAccessException` → 全局兜底 | 通用                                    | `delete()`                           |
| 用户输入含恶意 Prompt      | `PromptSanitizer.sanitize()` 清洗         | 无                                     | `parseWithAI()` 第一步                  |
| 数据边界破坏              | 添加 `DATA_BOUNDARY_INSTRUCTION` + 分隔符包裹  | 无                                     | `parseWithAI()` Prompt 组装            |

### 七、设计亮点总结

1. **解析策略逐级降级**：规则→AI→失败，兼顾性能（毫秒级）和灵活性（非结构化文本）
2. **防御性编程**：所有 AI 输出都经过"剥壳→反序列化→逐字段安全提取"三步骤，绝不会因 LLM 的一次不规范输出导致崩溃
3. **状态独立管理**：更新接口显式忽略 `id` 和 `status`，状态变更必须走专用接口，防止客户端篡改
4. **批量操作**：定时清理使用 `@Modifying` + `@Query` 一条 SQL 更新所有过期记录，而非逐条查询再 save
5. **安全防护**：用户输入经 PromptSanitizer 清洗 + 分隔符包裹 + 数据边界指令，防止 Prompt 注入
6. **实体隔离**：对外只返回 DTO，内部使用 Entity，中间通过 `BeanUtils.copyProperties` 转换
