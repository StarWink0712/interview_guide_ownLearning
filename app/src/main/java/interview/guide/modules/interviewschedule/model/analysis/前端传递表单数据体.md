不是数据库实体，是"前端发来的表单"

`CreateInterviewRequest` **不是** 数据库实体——它没有一个 `@Entity` 注解。它的角色是**前端请求体**，用来接收用户填写的面试日程表单数据。

***

### 不同后缀的含义

项目中 MVC 三层各自用不同的类名后缀，数据流向如下：

```
前端表单（浏览器）
    ↓ 用户填写后提交
CreateInterviewRequest（请求体 — 当前这个类）
    ↓ Controller 接收，传给 Service
InterviewScheduleService 转换
    ↓
InterviewScheduleEntity（数据库实体）
    ↓
Service 返回
    ↓
InterviewScheduleDTO/Response（返回给前端的数据）
```

| 后缀               | 当前类                       | 与数据库的关系               |
| ---------------- | ------------------------- | --------------------- |
| `Request`        | `CreateInterviewRequest`  | **毫无关系**，只定义前端应该传什么字段 |
| `Entity`         | `InterviewScheduleEntity` | **一一对应**，定义表结构        |
| `DTO`/`Response` | 暂无（用 Entity 直接转）          | **只给前端看**，隐藏敏感字段      |

### `CreateInterviewRequest` 的两个特点

**1. 有** **`@NotBlank`** **/** **`@NotNull`** **校验注解**但**没有** **`@Entity`** **/** **`@Table`** **/** **`@Column`**

```java
@NotBlank(message = "公司名称不能为空")   ← 校验规则
private String companyName;               ← 没有 @Column，不映射表
```

**2. 字段名和 Entity 几乎一样**但不是同一个东西

| Request（前端传入）                   | Entity（数据库存储）                                    |
| ------------------------------- | ------------------------------------------------ |
| `companyName`（用户填）              | `companyName` + `@Column(name = "company_name")` |
| `interviewTime`（用户填）            | `interviewTime` + `@Column(nullable = false)`    |
| 没有 `id`、`createdAt`、`updatedAt` | 有 `id`、`createdAt`、`updatedAt`                   |

### 完整的数据流转

```java
// Controller：接收请求体
@PostMapping
public Result<Void> createSchedule(@Valid @RequestBody CreateInterviewRequest request) {
    interviewScheduleService.create(request);
    return Result.success();
}

// Service：把 Request 转成 Entity
@Service
public class InterviewScheduleService {
    public void create(CreateInterviewRequest request) {
        InterviewScheduleEntity entity = new InterviewScheduleEntity();
        entity.setCompanyName(request.getCompanyName());      // Request → Entity
        entity.setPosition(request.getPosition());
        entity.setInterviewTime(request.getInterviewTime());
        // id/createdAt/updatedAt 由 @GeneratedValue + @PrePersist 自动处理
        repository.save(entity);
    }
}
```

### 一句话总结

> **`CreateInterviewRequest`** **= 前端传过来的表单**，只负责定义"用户必须填什么字段"和"校验规则"，不涉及任何数据库操作。`@Entity` 才是绑定数据库表的那个。

对，完全正确。两个作用：

1. **接收**：Spring 自动把前端传来的 JSON 反序列化成这个 Java 对象
2. **约束**：`@NotBlank`、`@NotNull` 等注解在后端做二次校验——即使用户在前端绕过了校验（比如改浏览器请求），后端也能拦住

```java
// 前端传的 JSON：
{
    "companyName": "字节跳动",
    "position": "",                  // 空字符串，@NotBlank 拦截
    "interviewTime": null            // null，@NotNull 拦截
}

// Spring 解析成 CreateInterviewRequest 对象后，发现校验失败
// → 直接抛出 MethodArgumentNotValidException
// → GlobalExceptionHandler 捕获 → 返回 Result(code=400, message="岗位不能为空, 面试时间不能为空")
```

**通俗点讲：`CreateInterviewRequest`** **就是一张"请在这里填信息"的表单，`@NotBlank`** **就是表上写的"此字段必填"。** 不经过这张表，后端的 Service 就不知道前端传了什么。
