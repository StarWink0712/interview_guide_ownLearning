
          
## 详细查缓存流程

[`getSession(Long sessionId)`](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/java/interview/guide/modules/voiceinterview/service/VoiceInterviewService.java#L225-L242) 是带缓存穿透保护的两段式查询：

### 第一步：查 Redis（第 231-238 行）

```java
String cacheKey = getSessionCacheKey(sessionId);                // ① 拼 Key
RBucket<VoiceInterviewSessionEntity> bucket =                     // ② 获取 Bucket
    redissonClient.getBucket(cacheKey);
VoiceInterviewSessionEntity cached = bucket.get();                // ③ 取值

if (cached != null) {
    return cached;  // 命中 → 直接返回，不查数据库
}
```

**缓存 Key 的格式**：
```
voice:interview:session:42
```
由 `getSessionCacheKey` 拼出：`"voice:interview:session:" + sessionId`。

**缓存中存储的数据格式**：不是 JSON 字符串，而是 **Java 序列化的 `VoiceInterviewSessionEntity` 对象**。

Redisson 的 `RBucket<V>` 使用 **Kryo（Redisson 默认高性能序列化）** 将整个 Entity 对象序列化为二进制字节流存入 Redis，取出时反序列化回 `VoiceInterviewSessionEntity`。所以从 Redis 拿到的是一个**可以直接使用的完整对象**，字段包括 `roleType`、`currentPhase`、`status`、`startTime`、`evaluateStatus` 等全部属性。

**缓存的写入**在 [`cacheSession`](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/java/interview/guide/modules/voiceinterview/service/VoiceInterviewService.java#L666-L671) 中：

```java
bucket.set(session, Duration.ofHours(CACHE_TTL_HOURS));  // TTL = 1 小时
```

**Redis 中实际存储形式**（以示例说明）：

```
Key:   voice:interview:session:42
Type:  String (二进制，Kryo 序列化后的字节数组)
Value: <二进制 blob，包含 VoiceInterviewSessionEntity 的所有字段>
TTL:   3600 秒（1 小时）
```

> 如果用 `redis-cli GET voice:interview:session:42`，看到的是一串乱码，因为 Kryo 序列化后是不可读的二进制格式。

### 第二步：查数据库（第 241 行）

```java
return sessionRepository.findById(sessionId).orElse(null);
```

Redis 没命中（Key 不存在或已过期）才查 PostgreSQL。这里还有一个细节是**查完数据库不写回缓存**——也就是说：

- `cacheSession` 只在新创建或更新会话时主动调用（`createSession`、`endSession`、`pauseSession` 末尾等）
- 如果缓存被动过期（1 小时 TTL 到期），下次 `getSession` 只查数据库，不会自动重建缓存

### 缓存何时被清除

[`invalidateSessionCache`](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/java/interview/guide/modules/voiceinterview/service/VoiceInterviewService.java#L678-L683) 直接 `bucket.delete()` 删除 Key，调用场景包括暂停/恢复会话时先清缓存再重建。

### 总结

| 项目 | 内容 |
|------|------|
| Redis Key | `voice:interview:session:{sessionId}`（如 `voice:interview:session:42`） |
| 存储格式 | Kryo 序列化的 `VoiceInterviewSessionEntity` 完整对象 |
| TTL | 1 小时（`CACHE_TTL_HOURS`） |
| 命中 | 返回反序列化的 Entity，不查数据库 |
| 未命中 | 查 PostgreSQL，**不自动回写缓存** |
| 写入时机 | 创建/结束/暂停/恢复会话时主动调用 `cacheSession` |
| 清除时机 | 暂停/恢复时先 `invalidateSessionCache` 再重建 |
