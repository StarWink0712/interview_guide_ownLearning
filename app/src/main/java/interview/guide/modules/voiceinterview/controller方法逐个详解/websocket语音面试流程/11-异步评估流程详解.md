# 异步评估流程详解

## 概述

面试结束后，系统通过 Redis Stream 消息队列自动触发异步评估任务。评估将面试中的全部对话消息送入 LLM 进行全面评估，生成包含总分、逐题评分、优势、改进建议和参考答案的评估报告。评估完成后前端通过轮询接口获取结果并渲染评估面板。整个评估流程中触发和执行完全解耦——面试结束只入队不等待，消费者后台执行不阻塞 HTTP 响应。

## 一、评估触发

评估任务在 `VoiceInterviewService.endSession()` 的末尾被触发。此时数据库中的 `evaluateStatus` 已被设为 `PENDING`：

```java
voiceEvaluateStreamProducer.sendEvaluateTask(sessionId);
```

这一步通过 Redis Stream 的 `XADD` 命令将 sessionId 入队到 `voice:evaluate:stream`。`VoiceEvaluateStreamProducer` 继承自 `AbstractStreamProducer<KnowledgeBaseTask>`，封装了 Stream 的写入细节。`VoiceEvaluateStreamConsumer` 继承自 `AbstractStreamConsumer<KnowledgeBaseTask>`，在后台线程中轮询消费。消费者实现了失败重试——如果评估过程中发生异常，最多重试 3 次，超过后标记 `evaluateStatus=FAILED`。消费者在消费前还会检查会话的 `evaluateStatus`，如果已经是 COMPLETED（例如用户通过 `POST /evaluation` 手动触发并已完成），直接 ACK 消息跳过重复评估。

## 二、VoiceInterviewEvaluationService.generateEvaluation() 核心流程

这是评估执行的完整代码，分为七个有序步骤：

```java
public void generateEvaluation(Long sessionId) {
    try {
        log.info("开始生成语音面试评估: sessionId={}", sessionId);

        // 第一步：查询会话实体和对话消息
        VoiceInterviewSessionEntity session = getSession(sessionId);
        List<VoiceInterviewMessageEntity> messages = messageRepository
            .findBySessionIdOrderBySequenceNumAsc(sessionId);

        // 第二步：无消息 → 保存空评估（兜底设计，防止前端轮询永远等不到 COMPLETED）
        if (messages.isEmpty()) {
            log.warn("语音面试会话无对话记录，生成空评估结果: sessionId={}", sessionId);
            saveEmptyEvaluationTransactional(sessionId, session);
            return;
        }

        // 第三步：构建 QaRecord 列表——AI 提问和用户回答的配对
        List<QaRecord> qaRecords = buildQaRecords(messages);

        // 第四步：获取 LLM ChatClient（会话指定的 Provider 或全局默认）
        String provider = session.getLlmProvider();
        ChatClient chatClient = llmProviderRegistry.getChatClientOrDefault(provider);

        // 第五步：构建评估参考上下文（技能方向的知识点、考察维度等）
        String referenceContext = skillService.buildEvaluationReferenceSectionSafe(
            session.getSkillId());

        // 第六步：LLM 评估 —— ⚠️ 在 @Transactional 外部执行
        // 因为 LLM 调用是阻塞 I/O 操作，可能耗时数十秒，
        // 若在事务内会长时间占用数据库连接导致连接池耗尽
        EvaluationReport report = unifiedEvaluationService.evaluate(
            chatClient, String.valueOf(sessionId), qaRecords, null, referenceContext);

        // 第七步：持久化评估结果 —— @Transactional 事务内执行
        saveEvaluationTransactional(sessionId, session, report);

    } catch (BusinessException e) {
        throw e;  // 保留业务异常原样抛出
    } catch (Exception e) {
        log.error("生成语音面试评估失败: sessionId={}", sessionId, e);
        throw new BusinessException(ErrorCode.VOICE_EVALUATION_FAILED,
            "生成评估失败: " + e.getMessage());
    }
}
```

### 2.1 QaRecord 构建与分类推断

```java
private List<QaRecord> buildQaRecords(List<VoiceInterviewMessageEntity> messages) {
    List<QaRecord> records = new ArrayList<>();
    int index = 0;

    for (VoiceInterviewMessageEntity msg : messages) {
        String aiText = msg.getAiGeneratedText();
        String userText = msg.getUserRecognizedText();

        // 只要 AI 文本或用户文本任一非空就构建一条 QaRecord
        if ((aiText != null && !aiText.isBlank()) || (userText != null && !userText.isBlank())) {
            records.add(new QaRecord(
                index,
                aiText != null ? aiText.trim() : "",
                inferCategory(aiText),    // 从 AI 提问文本推断问题分类
                userText != null && !userText.isBlank() ? userText.trim() : null
            ));
            index++;
        }
    }
    return records;
}

// 从 AI 回复中通过关键词推断问题分类——用于评估报告中按分类统计得分
private String inferCategory(String aiText) {
    if (aiText == null) return "综合";
    if (aiText.contains("项目") || aiText.contains("实习") || aiText.contains("工作经历"))
        return "项目深挖";
    if (aiText.contains("自我介绍") || aiText.contains("介绍一下自己"))
        return "自我介绍";
    if (aiText.contains("职业规划") || aiText.contains("为什么") || aiText.contains("优缺点"))
        return "HR问题";
    return "技术问题";
}
```

语音面试的消息格式是"AI 先说话"的对话模式——AI 提问在前（`aiGeneratedText`），用户回答在后（`userRecognizedText`）。每条 QaRecord 的 question 字段是 AI 的提问文本，answer 字段是用户的回答文本。分类推断基于简单的关键词匹配，属于启发式分类而非精确分类——其目的是让评估报告能按分类汇总得分，即使分类不完全准确也不影响整体评估的参考价值。

### 2.2 持久化评估结果

```java
@Transactional
public void saveEvaluationTransactional(Long sessionId, VoiceInterviewSessionEntity session,
                             EvaluationReport report) {
    try {
        List<EvaluationReport.QuestionEvaluation> questionItems = report.questionDetails();
        List<EvaluationReport.ReferenceAnswer> refAnswerItems = report.referenceAnswers();

        VoiceInterviewEvaluationEntity entity = VoiceInterviewEvaluationEntity.builder()
            .sessionId(sessionId)
            .overallScore(report.overallScore())
            .overallFeedback(report.overallFeedback())
            // 四个 JSON 字段提供灵活性——无需为每个评估维度创建独立数据库列
            .questionEvaluationsJson(objectMapper.writeValueAsString(questionItems))
            .strengthsJson(objectMapper.writeValueAsString(report.strengths()))
            .improvementsJson(objectMapper.writeValueAsString(report.improvements()))
            .referenceAnswersJson(objectMapper.writeValueAsString(refAnswerItems))
            .interviewerRole(session.getRoleType())
            .interviewDate(session.getStartTime())
            .build();

        evaluationRepository.save(entity);
        log.info("评估结果已保存: sessionId={}, score={}", sessionId, entity.getOverallScore());
    } catch (Exception e) {
        log.error("保存评估结果失败: sessionId={}", sessionId, e);
        throw new BusinessException(ErrorCode.VOICE_EVALUATION_FAILED,
            "保存评估失败: " + e.getMessage());
    }
}
```

四个 JSON 字段的设计让评估实体不依赖固定的列结构——`questionEvaluationsJson` 存储逐题评估详情的 JSON 数组、`strengthsJson` 和 `improvementsJson` 存储字符串数组、`referenceAnswersJson` 存储参考答案数组。这种设计对语音面试尤为重要——对话轮数不固定，无法像文本面试那样为固定数量的题目设计固定列。

### 2.3 空评估：兜底设计

```java
@Transactional
public void saveEmptyEvaluationTransactional(Long sessionId, VoiceInterviewSessionEntity session) {
    try {
        VoiceInterviewEvaluationEntity entity = evaluationRepository.findBySessionId(sessionId)
            .orElseGet(() -> VoiceInterviewEvaluationEntity.builder().sessionId(sessionId).build());

        entity.setOverallScore(0);
        entity.setOverallFeedback("本次语音面试未形成有效对话记录，暂无可评估内容。");
        entity.setQuestionEvaluationsJson("[]");
        entity.setStrengthsJson("[]");
        entity.setImprovementsJson("[\"请先完成至少一轮有效问答后再生成评估。\"]");
        entity.setReferenceAnswersJson("[]");
        entity.setInterviewerRole(session.getRoleType());
        entity.setInterviewDate(session.getStartTime());

        evaluationRepository.save(entity);
    } catch (Exception e) {
        log.error("保存空评估结果失败: sessionId={}", sessionId, e);
        throw new BusinessException(ErrorCode.VOICE_EVALUATION_FAILED, "保存空评估失败");
    }
}
```

空评估是兜底设计，防止前端轮询永远等不到 COMPLETED 状态。如果面试中没有任何有效对话记录（例如用户创建会话后立即结束），无论如何都应该生成一条评估记录让轮询停止。

## 三、前端轮询获取评估结果

Controller 的 `getEvaluation()` 方法从会话实体读取 `evaluateStatus`：

```java
@GetMapping("/sessions/{sessionId}/evaluation")
public Result<VoiceEvaluationStatusDTO> getEvaluation(@PathVariable Long sessionId) {
    VoiceInterviewSessionEntity session = voiceInterviewService.getSession(sessionId);
    if (session == null) {
        throw new BusinessException(ErrorCode.VOICE_SESSION_NOT_FOUND, "会话不存在: " + sessionId);
    }

    AsyncTaskStatus status = session.getEvaluateStatus();
    VoiceEvaluationStatusDTO.VoiceEvaluationStatusDTOBuilder builder = VoiceEvaluationStatusDTO.builder()
            .evaluateStatus(status != null ? status.name() : null)
            .evaluateError(session.getEvaluateError());

    // 评估完成时附加完整详情——前端收到即可停止轮询并渲染评估面板
    if (status == AsyncTaskStatus.COMPLETED) {
        VoiceEvaluationDetailDTO evaluation = evaluationService.getEvaluation(sessionId);
        builder.evaluation(evaluation);
    }

    return Result.success(builder.build());
}
```

前端以 2-3 秒间隔轮询此接口。`evaluateStatus` 的四种状态决定了 UI 显示——PENDING 显示"评估排队中..."，PROCESSING 显示"AI 正在评估..."，COMPLETED 停止轮询并渲染评估详情，FAILED 显示错误信息和"重新评估"按钮。

## 四、手动触发评估

如果自动评估超时或失败，可通过 `POST /evaluation` 手动触发。Controller 做三级判断实现幂等保护：

```java
@PostMapping("/sessions/{sessionId}/evaluation")
public Result<VoiceEvaluationStatusDTO> generateEvaluation(@PathVariable Long sessionId) {
    VoiceInterviewSessionEntity session = voiceInterviewService.getSession(sessionId);
    if (session == null) {
        throw new BusinessException(ErrorCode.VOICE_SESSION_NOT_FOUND);
    }

    // 已完成 → 直接返回缓存结果（最快路径，不重复评估）
    if (session.getEvaluateStatus() == AsyncTaskStatus.COMPLETED) {
        VoiceEvaluationDetailDTO evaluation = evaluationService.getEvaluation(sessionId);
        return Result.success(VoiceEvaluationStatusDTO.builder()
                .evaluateStatus(AsyncTaskStatus.COMPLETED.name())
                .evaluation(evaluation).build());
    }

    // PENDING/PROCESSING → 返回当前状态，不重复入队
    if (session.getEvaluateStatus() == AsyncTaskStatus.PENDING
            || session.getEvaluateStatus() == AsyncTaskStatus.PROCESSING) {
        return Result.success(VoiceEvaluationStatusDTO.builder()
                .evaluateStatus(session.getEvaluateStatus().name()).build());
    }

    // FAILED 或 null → 触发新评估
    voiceInterviewService.triggerEvaluation(sessionId);
    return Result.success(VoiceEvaluationStatusDTO.builder()
            .evaluateStatus(AsyncTaskStatus.PENDING.name()).build());
}
```

三级判断的设计避免了以下问题：已完成评估被重新触发覆盖、进行中的评估被重复入队导致多次评估、失败状态的评估被忽略。每次请求只会触发一个有效动作。

---

## 五、总结

异步评估流程通过 Redis Stream 消息队列实现触发与执行的完全解耦——面试结束时只入队不等待，后台 `VoiceEvaluateStreamConsumer` 轮询消费并执行 LLM 评估，前端以固定间隔轮询 `GET /evaluation` 获取进度。核心设计包括：LLM 调用放在 `@Transactional` 外部执行避免长时间占用数据库连接；空对话的 `saveEmptyEvaluationTransactional()` 兜底评估防止前端轮询永远等不到 COMPLETED 状态；`QaRecord` 列表通过 `inferCategory()` 基于关键词推断问题分类；四个 JSON 字段设计灵活支持不定数量的对话轮数；`POST /evaluation` 的三级幂等判断（COMPLETED 返回缓存、PENDING/PROCESSING 不重复入队、FAILED/null 触发新任务）。评估结果通过 `VoiceEvaluationDetailDTO` 返回前端渲染——包含总分、逐题评分与反馈、优势列表、改进建议和参考答案。
