# 开场问题触发流程详解

## 概述

语音面试有一个独特的设计——WebSocket 连接建立后不是等用户先说话，而是 AI 面试官主动发出开场白和第一个面试问题。这个设计模拟了真实面试中的社交礼仪（面试官先打招呼），同时解决了"空白界面焦虑"——用户面对一个打开的麦克风但不知道说什么的尴尬。技术上开场问题在虚拟线程中异步执行，先推送文本让前端立即显示，再推送预缓存的 WAV 音频让用户听到 AI 的声音。

## 触发时机与前置条件

开场问题通过 `triggerOpeningQuestionIfNeeded()` 触发，在 `afterConnectionEstablished()` 的末尾被调用。它的执行是异步的——通过 `voicePipelineExecutor`（Java 21 虚拟线程池）提交，不阻塞欢迎消息的发送和 `afterConnectionEstablished` 的返回。

```java
private void triggerOpeningQuestionIfNeeded(String sessionId, WebSocketSession session) {
    voicePipelineExecutor.execute(() -> {
        try {
            if (session == null || !session.isOpen()) return;

            // 判读是否需要开场——查询对话历史记录
            // 如果有历史消息说明是重连/恢复场景，不重复发送开场问题
            List<String> history = getHistory(sessionId);
            if (history != null && !history.isEmpty()) return;

            // 从数据库获取会话实体——需要 skillId 来选择开场问题模板
            VoiceInterviewSessionEntity sessionEntity = getSessionEntity(sessionId);
            if (sessionEntity == null) {
                log.warn("Session entity not found when sending opening question: {}", sessionId);
                return;
            }

            // 根据技能方向选择开场问题模板
            String aiReply = buildOpeningQuestion(sessionEntity);
            if (aiReply == null || aiReply.isBlank()) return;
            if (!session.isOpen()) return;

            // 文本先行——前端立即可见
            sendTextMessage(session, aiReply);
            saveMessage(sessionId, null, aiReply);  // 保存到数据库，userText 为 null

            // 语音随后——从预热缓存或实时 TTS 获取 WAV 音频
            byte[] wavAudio = getOpeningWavAudio(aiReply);
            if (wavAudio.length > 0 && session.isOpen()) {
                sendAudio(session, wavAudio, aiReply);
            }

            log.info("Opening question sent for session {}", sessionId);
        } catch (Exception e) {
            // 开场问题失败不向用户报错——这是一个"尽力而为"的设计
            // 用户仍然可以主动说话，ASR 正常识别，LLM 正常回复
            log.error("Failed to send opening question for session {}", sessionId, e);
        }
    });
}
```

`getHistory()` 查询 `voice_interview_messages` 表判断是否有历史消息。这个判断让系统能区分"首次连接"和"重连恢复"两种场景——重连时不重复发开场问题，避免 AI 面试官"再次自我介绍"的尴尬体验。

## 开场问题模板的选择逻辑

`buildOpeningQuestion()` 实现了三级模板选择机制：

```java
private String buildOpeningQuestion(VoiceInterviewSessionEntity sessionEntity) {
    String skillId = sessionEntity.getSkillId() != null ? sessionEntity.getSkillId() : "";
    VoiceInterviewProperties.OpeningConfig opening = voiceInterviewProperties.getOpening();

    // 第一优先级：技能专属开场问题
    // 配置文件可为每个 skillId 定义不同的开场模板
    Map<String, String> skillQuestions = opening != null ? opening.getSkillQuestions() : null;
    if (skillQuestions != null) {
        String bySkill = skillQuestions.get(skillId);
        if (bySkill != null && !bySkill.isBlank()) return bySkill;
    }

    // 第二优先级：算法方向默认问题
    List<String> algorithmSkills = opening != null && opening.getAlgorithmSkills() != null
        ? opening.getAlgorithmSkills() : List.of();
    if (algorithmSkills.contains(skillId)) {
        String configured = opening != null ? opening.getAlgorithmQuestion() : null;
        return configured != null && !configured.isBlank()
            ? configured : DEFAULT_OPENING_QUESTION_ALGORITHM;
    }

    // 第三优先级：后端方向默认问题（兜底）
    String configured = opening != null ? opening.getBackendQuestion() : null;
    return configured != null && !configured.isBlank()
        ? configured : DEFAULT_OPENING_QUESTION_BACKEND;
}
```

三级优先级从高到低为：技能专属模板 → 算法/后端方向模板 → 硬编码兜底值。配置文件中的 `skillQuestions` Map 允许为每个技能定义专属的开场问题，例如 Java 后端可以是"请用 1 分钟介绍一个你深度参与的 Java 项目..."，算法方向可以是"请你口述一道算法题..."。如果配置未命中，则根据 `algorithmSkills` 列表判断使用算法还是后端默认模板。默认模板也有硬编码兜底值，确保即使配置完全缺失系统仍能正常运行。

## 文本先行、音频随后

发送策略遵循"文本先行、音频随后"——先 `sendTextMessage()` 让前端立即显示文字，再 `getOpeningWavAudio()` 获取音频后 `sendAudio()` 推送。这个策略的核心思想是音频的传输和播放有延迟（WAV 文件大小 + 网络传输 + 浏览器解码），而文本几乎瞬间到达。先显示文本确保用户在音频到达前就能看到问题内容。

### 音频缓存获取

```java
private byte[] getOpeningWavAudio(String text) {
    // 优先从预热缓存获取——ConcurrentHashMap 线程安全
    byte[] cached = openingAudioCache.get(text);
    if (cached != null && cached.length > 0) return cached;

    // 缓存未命中 → 实时 TTS 合成 → 回填缓存供后续使用
    byte[] wav = synthesizeToWav(text);  // TTS 合成 PCM → 转换 WAV
    if (wav.length > 0) openingAudioCache.put(text, wav);
    return wav;
}
```

## 应用启动时的音频预热缓存

`@PostConstruct warmupOpeningAudioCache()` 在应用启动后通过虚拟线程异步执行，把配置中所有开场问题模板预先 TTS 合成为 WAV 存入 `openingAudioCache`（ConcurrentHashMap）：

```java
@PostConstruct
void warmupOpeningAudioCache() {
    voicePipelineExecutor.execute(() -> {
        try {
            VoiceInterviewProperties.OpeningConfig opening = voiceInterviewProperties.getOpening();
            if (opening == null) return;

            // 收集所有可能用到的开场问题模板
            LinkedHashSet<String> allTemplates = new LinkedHashSet<>();
            if (opening.getSkillQuestions() != null) {
                allTemplates.addAll(opening.getSkillQuestions().values());
            }
            allTemplates.add(opening.getAlgorithmQuestion());
            allTemplates.add(opening.getBackendQuestion());

            // 逐一合成并缓存
            for (String template : allTemplates) {
                preloadOpeningAudio(template);
            }
            log.info("Opening audio cache warmed: {} entries", openingAudioCache.size());
        } catch (Exception e) {
            // 预热失败不阻塞应用启动——首次命不中时可以实时合成
            log.warn("Opening audio cache warmup skipped: {}", e.getMessage());
        }
    });
}

private void preloadOpeningAudio(String text) {
    if (text == null || text.isBlank()) return;
    byte[] wavAudio = synthesizeToWav(text);
    if (wavAudio.length > 0) openingAudioCache.put(text, wavAudio);
}
```

预热在虚拟线程中异步执行，不阻塞应用启动的完成。如果预热过程中某个模板合成失败（网络问题），只记录 warning 不影响其他模板的预热。未成功预热的模板在首次被需要时会走 `getOpeningWavAudio()` 的实时合成路径并回填缓存。这个预热设计的核心价值是消除首次用户体验中的 TTS 合成延迟——用户点击"开始面试"后 WebSocket 连接建立，开场问题音频从缓存直接命中，3 秒内即可开始播放。

## PCM 到 WAV 的手动格式转换

TTS 服务返回的是原始 PCM 音频（24kHz 16bit 单声道），但浏览器通常不支持直接播放原始 PCM——需要 WAV 容器格式。`convertPcmToWav()` 通过手动构造 44 字节的 WAV 文件头来封装 PCM 数据：

```java
private byte[] convertPcmToWav(byte[] pcmData) {
    int sampleRate = 24000;       // Qwen TTS 输出的采样率
    int bitsPerSample = 16;       // 每个样本 16bit
    int numChannels = 1;          // 单声道
    int byteRate = sampleRate * numChannels * bitsPerSample / 8;
    int blockAlign = numChannels * bitsPerSample / 8;
    int dataSize = pcmData.length;
    int fileSize = dataSize + 36;

    byte[] wavData = new byte[dataSize + 44];
    int pos = 0;

    // RIFF 头：标识这是一个 WAV 文件
    wavData[pos++] = 'R'; wavData[pos++] = 'I'; wavData[pos++] = 'F'; wavData[pos++] = 'F';
    writeIntLE(wavData, pos, fileSize); pos += 4;
    wavData[pos++] = 'W'; wavData[pos++] = 'A'; wavData[pos++] = 'V'; wavData[pos++] = 'E';

    // fmt 块：描述音频格式
    wavData[pos++] = 'f'; wavData[pos++] = 'm'; wavData[pos++] = 't'; wavData[pos++] = ' ';
    writeIntLE(wavData, pos, 16); pos += 4;          // 块大小 16 字节
    writeShortLE(wavData, pos, (short) 1); pos += 2; // 格式 PCM
    writeShortLE(wavData, pos, (short) numChannels); pos += 2;
    writeIntLE(wavData, pos, sampleRate); pos += 4;
    writeIntLE(wavData, pos, byteRate); pos += 4;
    writeShortLE(wavData, pos, (short) blockAlign); pos += 2;
    writeShortLE(wavData, pos, (short) bitsPerSample); pos += 2;

    // data 块：PCM 音频数据本体
    wavData[pos++] = 'd'; wavData[pos++] = 'a'; wavData[pos++] = 't'; wavData[pos++] = 'a';
    writeIntLE(wavData, pos, dataSize); pos += 4;

    // 将 PCM 数据原样拷贝到头部之后
    System.arraycopy(pcmData, 0, wavData, 44, pcmData.length);
    return wavData;
}
```

所有整数以小端序（Little Endian）写入——WAV 文件格式要求。手动构造而非引入第三方库，避免了像 javax.sound 这样的 JDK 内部 API 或额外的音频处理依赖。

## 总结

开场问题的设计体现了语音面试"AI 主动引导"的交互理念。通过三级模板选择机制（技能专属 → 方向模板 → 兜底）实现灵活可配置的开场白，通过 `@PostConstruct` 预热缓存消除首次用户的 TTS 合成延迟（`openingAudioCache` 在应用启动时并行合成所有模板为 WAV），通过"文本先行、音频随后"的发送策略确保前端立即可见文本、音频随后播放，通过 `getHistory()` 判断历史消息区分首次连接和重连恢复场景避免重复开场。整个流程在虚拟线程中异步执行不影响 WebSocket 握手完成和 ASR 启动，失败时只记日志不报错（"尽力而为"设计——开场问题失败不应阻止用户面试）。
