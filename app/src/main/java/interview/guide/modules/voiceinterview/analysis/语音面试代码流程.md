# 语音面试功能完整技术文档

## 一、功能概述

语音面试是一个**实时双向语音对话系统**，实现了用户语音 → ASR语音识别 → LLM大模型生成回复 → TTS语音合成 → AI语音推送的完整管线。前端通过WebSocket与后端实时通信，后端协调阿里云DashScope的三大AI服务（ASR/LLM/TTS）完成智能面试。

```
    → 保存到 PostgreSQL（VoiceInterviewSessionRepository）
  → 返回 SessionResponseDTO（含 sessionId + webSocketUrl）
```

```json
  "resumeId": 123,
  "introEnabled": true,
  "techEnabled": true,
  "projectEnabled": true,
  "hrEnabled": true,
```

**响应格式**：

### 阶段2：建立WebSocket连接

```
前端 connectWebSocket(sessionId, webSocketUrl, handlers)
  → new WebSocket(webSocketUrl)
  → 握手：WebSocketConfig → HttpSessionHandshakeInterceptor
  → 后端 VoiceInterviewWebSocketHandler.afterConnectionEstablished()
    → 1. extractSessionId(session) 从URI提取sessionId
    → 2. 设置消息大小限制 256KB
    → 3. ConcurrentWebSocketSessionDecorator 包装（防并发写入冲突）
    → 4. sessions.put(sessionId, safeSession)  // 保存WebSocket会话
    → 5. sessionStates.put(sessionId, new SessionState())  // 初始化运行时状态
    → 6. startDashScopeStt(sessionId, safeSession)  // 启动ASR
    → 7. sendMessage(safeSession, welcomeMessage)  // 发送欢迎消息
    → 8. triggerOpeningQuestionIfNeeded(sessionId, safeSession)  // 发送开场问题
```

**启动ASR的详细调用链**：

```
startDashScopeStt(sessionId, session)
  → QwenAsrService.startTranscription(sessionId, onFinal, onPartial, onError)
    → 构建 OmniRealtimeParam（model, url, apiKey）
    → 创建 OmniRealtimeCallback（onOpen, onEvent, onClose）
    → 创建 OmniRealtimeConversation(param, callback)
    → sessions.put(sessionId, new AsrSession(...))
    → 新线程：conversation.connect()
    → 更新Session配置（VAD、语言、采样率）
```

**开场问题的调用链**：

```
triggerOpeningQuestionIfNeeded(sessionId, session)
  → voicePipelineExecutor.execute(() -> {  // 虚拟线程异步
      → getHistory(sessionId)  // 检查是否有历史消息（防止重连时重复开场）
      → getSessionEntity(sessionId)  // 从数据库加载会话实体
      → buildOpeningQuestion(sessionEntity)  // 构建开场问题文本
        → 优先使用 skillQuestions[skillId]  // 技能专属问题
        → 其次 algorithmSkills 包含 skillId → algorithmQuestion
        → 否则使用 backendQuestion
      → sendTextMessage(session, aiReply)  // 文本先行
      → saveMessage(sessionId, null, aiReply)  // 持久化到数据库
      → getOpeningWavAudio(aiReply)  // 获取WAV音频（缓存优先）
        → openingAudioCache.get(text)  // 命中缓存
        → 未命中 → synthesizeToWav(text)
          → QwenTtsService.synthesize(text)  // TTS合成
          → convertPcmToWav(pcm)  // PCM→WAV
      → sendAudio(session, wavAudio, aiReply)  // 推送音频
    })
```

### 阶段3：实时语音对话循环

这是面试的核心阶段，每个对话轮次包含以下步骤：

#### 3.1 用户说话 → 前端采集音频

```
前端 AudioRecorder 组件（麦克风录音）
  → MediaRecorder 录制 PCM 音频
  → 每隔约100ms 发送一个音频块
  → WebSocket.send(JSON.stringify({type:"audio", data: base64Audio, timestamp}))
```

#### 3.2 后端接收音频 → ASR识别

```
VoiceInterviewWebSocketHandler.handleTextMessage(session, message)
  → 解析JSON → type="audio"
  → handleUserAudio(sessionId, base64Audio)
    → 检查AI是否在说话/冷却期 → 是则丢弃（防回声）
    → Base64.decode(base64Audio) → byte[]
    → QwenAsrService.sendAudio(sessionId, audioData)
      → sessions.get(sessionId) 获取AsrSession
      → Base64.encode(audioData) → 发送到DashScope ASR WebSocket
      → ASR服务端VAD检测到静默 → 自动断句 → 回调onFinal
    → ASR连接断开时自动重连（restartDashScopeStt）
```

#### 3.3 ASR识别结果 → 防抖合并 → 提交LLM

```
QwenAsrService.handleServerEvent()
  → conversation.item.input_audio_transcription.completed → onFinal回调
  → conversation.item.input_audio_transcription.text/delta → onPartial回调

VoiceInterviewWebSocketHandler.handleSttResult(sessionId, text, isFinal)
  → 部分结果(isFinal=false)：
    → sendSubtitle(session, text, false)  // 推送实时字幕
  → 最终结果(isFinal=true)：
    → state.appendFinalSttSegment(text)  // 追加到合并缓冲区
    → sendSubtitle(session, mergeBufferPreview, false)  // 更新字幕

前端用户点击"提交"按钮 → WebSocket.send({type:"control", action:"submit"})
  → handleControl(sessionId, control) → case "submit"
    → flushMergedUtteranceToLlm(sessionId)
      → state.takeMergeBufferAndClear()  // 取出合并后的完整文本
      → voicePipelineExecutor.execute(() -> triggerLlmResponse(...))  // 虚拟线程
```

#### 3.4 LLM生成回复 → 流式输出

```
triggerLlmResponse(sessionId, session, state)
  → state.aiSpeaking.set(true)  // 标记AI正在说话（丢弃麦克风输入）
  → getSessionEntity(sessionId)  // 从DB加载会话
  → getHistory(sessionId)  // 从DB加载对话历史

  【流式模式（默认开启）】：
  → DashscopeLlmService.chatStreamSentences(userText, onToken, onSentence, sessionEntity, history)
    → buildPromptContext(userInput, session, history)
      → VoiceInterviewPromptService.generateSystemPromptWithContext(skillId, resumeText)
        → 技能角色指令 + 语音输出约束 + 简历上下文 + 防注入安全指令
      → PromptSanitizer.sanitize(wrapWithDelimiters("input", userInput))
    → llmProviderRegistry.getVoiceChatClient(provider)  // 获取ChatClient
    → chatClient.prompt().system(systemPrompt).user(userPrompt).stream().content()
      → .doOnNext(token -> {
          // onToken回调：按180ms间隔推送实时文本给前端
          → sendTextMessage(session, normalizedText)
        })
      → .doOnNext(token -> {
          // onSentence回调：检测到完整句子（以。！？等结尾）
          → ttsSemaphore.acquire()
          → CompletableFuture.supplyAsync(() -> ttsService.synthesize(sentence))
          → ttsFutures.add(future)
        })
      → .blockLast()

  【非流式模式】：
  → DashscopeLlmService.chat(userText, sessionEntity, history)
    → chatClient.prompt().system(systemPrompt).user(userPrompt).call()
    → optimizeForVoice(content)  // 去Markdown、截断长回复
```

#### 3.5 TTS语音合成 → 音频推送

```
【分块推送模式（chunkedAudioEnabled=true）】：
→ 按顺序遍历 ttsFutures
  → ttsFutures.get(i).get()  // 等待该句TTS完成
  → convertPcmToWav(pcm)  // PCM→WAV（添加44字节WAV头）
  → sendAudioChunk(session, wavAudio, index, isLast)
  → 前端逐块播放（AudioContext + AudioBufferSourceNode）

【合并推送模式（chunkedAudioEnabled=false）】：
→ 收集所有 ttsFutures 的 PCM 结果
→ 合并为一个完整的 PCM byte[]
→ convertPcmToWav(mergedPcm)
→ sendAudio(session, wavAudio, aiReply)
  → 前端一次性播放完整WAV

→ AI说话结束：
  → state.aiSpeaking.set(false)
  → state.aiSpeakEndAt.set(now + 800ms)  // 冷却期防回声
```

### 阶段4：面试阶段自动转换

```
VoiceInterviewService.shouldTransitionToNextPhase(session, phaseStartTime, questionCount)
  → Duration.between(phaseStartTime, LocalDateTime.now())  // 计算已持续时间
  → getPhaseConfig(currentPhase)  // 获取阶段配置
    → properties.getPhase().getIntro()/getTech()/getProject()/getHr()
  → 规则1：达到最大时长 → 强制转换
  → 规则2：达到最大问题数 → 建议转换
  → 规则3：达到建议时长 && 问题数达标 → 建议转换
```

### 阶段5：结束面试

```
前端点击"结束面试" → WebSocket.send({type:"control", action:"end_interview"})
  → handleControl() → case "end_interview"
    → VoiceInterviewService.endSession(sessionId)
      → 更新Session状态为COMPLETED
      → 设置结束时间
      → 保存到数据库

WebSocket连接关闭：
  → afterConnectionClosed()
    → sessions.remove(sessionId)
    → sessionStates.remove(sessionId)
    → QwenAsrService.stopTranscription(sessionId)  // 关闭ASR连接
    → interviewService.endSessionIfInProgress(sessionId)  // 防止状态泄漏
```

### 阶段6：异步评估生成

```
前端 voiceInterviewApi.generateEvaluation(sessionId)
  → POST /api/voice-interview/sessions/{id}/evaluation
  → VoiceInterviewController.generateEvaluation()
    → 检查评估状态（已完成/进行中/新任务）
    → VoiceInterviewService.triggerEvaluation(sessionId)
      → 更新evaluateStatus = PENDING
      → VoiceEvaluateStreamProducer.send(sessionId)
        → Redis Stream XADD（异步任务入队）

VoiceEvaluateStreamConsumer 消费（后台线程）：
  → markProcessing(payload) → evaluateStatus = PROCESSING
  → processBusiness(payload)
    → VoiceInterviewEvaluationService.generateEvaluation(sessionId)
      → 加载会话和消息
      → buildQaRecords(messages)  // 构建QaRecord列表
      → llmProviderRegistry.getChatClientOrDefault(provider)
      → skillService.buildEvaluationReferenceSectionSafe(skillId)
      → UnifiedEvaluationService.evaluate(chatClient, sessionId, qaRecords, ...)
        → 分批评估 + 结构化输出 + 降级兜底
      → saveEvaluationTransactional(sessionId, session, report)  // 事务内保存
  → markCompleted(payload) → evaluateStatus = COMPLETED

前端轮询 voiceInterviewApi.getEvaluation(sessionId)
  → GET /api/voice-interview/sessions/{id}/evaluation
  → 返回 {evaluateStatus: "COMPLETED", evaluation: {...}}
```

| 模式   | `commit`                   | 手动控制合成时机         |
| 超时   | 30秒                        | CountDownLatch保护 |

## 九、关键设计决策

### 9.1 流式并发TTS

LLM流式输出期间，每检测到一个完整句子（以`。！？；`等结尾），立即启动TTS合成。LLM生成与TTS合成并行执行，TTS并发数由 `maxConcurrentTtsPerSession` 控制（默认3），使用Semaphore限流。

### 9.2 AI回声冷却

AI说话期间设置 `aiSpeaking=true`，丢弃所有麦克风输入。AI说完后额外冷却800ms（`AI_SPEAK_COOLDOWN_MS`），防止扬声器尾音被麦克风拾取触发STT。

### 9.3 STT防抖合并

ASR的VAD可能将一次完整发言切成多段。每段 `completed` 结果追加到 `mergeBuffer`，前端用户点击"提交"时才统一取出触发LLM。

### 9.4 开场问题预缓存

应用启动时（`@PostConstruct`），在虚拟线程中将所有开场问题模板预合成为WAV音频缓存到内存，避免首次面试时的TTS延迟。

### 9.5 暂停超时检测

`@Scheduled(fixedRate=30000)` 定时检查，4分30秒无活动发警告，5分钟自动暂停会话并断开WebSocket。
