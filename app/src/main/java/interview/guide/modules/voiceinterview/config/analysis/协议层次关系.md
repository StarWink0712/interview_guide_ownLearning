### 📊 协议层次关系

```
┌─────────────────────────────────────────┐
│           应用层 (Application)           │
│      HTTP  |  WebSocket  |  gRPC       │  ← 同层次
├─────────────────────────────────────────┤
│           表示层 (Presentation)           │
│              SSL/TLS                     │
├─────────────────────────────────────────┤
│           传输层 (Transport)             │
│           TCP  |  UDP                   │  ← WebSocket/HTTP 底层
├─────────────────────────────────────────┤
│           网络层 (Network)               │
│              IP                         │
└─────────────────────────────────────────┘
```

### 🔧 RPC 的灵活性

RPC（远程过程调用）是一种**通信范式**，不是具体协议：

```
RPC 可以基于：
  ├── HTTP/1.1 (短连接或长连接)
  ├── HTTP/2 (多路复用)
  ├── HTTP/3 (QUIC - 基于 UDP)
  ├── WebSocket
  ├── TCP (自定义协议)
  └── gRPC (HTTP/2 + Protocol Buffers)
```

### 🌏 gRPC 的具体例子

```
gRPC 协议栈：
┌─────────────────────────────────┐
│  应用层: gRPC (方法调用)         │
├─────────────────────────────────┤
│  表示层: Protocol Buffers 序列化  │
├─────────────────────────────────┤
│  传输层: HTTP/2 (多路复用)        │  ← 可以用 Netty 实现
├─────────────────────────────────┤
│  网络层: TCP                     │
└─────────────────────────────────┘

Netty 的作用：
  ├── 底层网络通信 (Socket)
  ├── HTTP/2 协议实现
  ├── 编解码器
  └── 性能优化（零拷贝、直接内存）
```

### 📚 常见 RPC 框架的协议选择

| RPC 框架 | 底层协议 | 序列化 |
|---------|---------|--------|
| **gRPC** | HTTP/2 | Protocol Buffers |
| **Dubbo** | TCP (Netty) / HTTP | Hessian / JSON |
| **Thrift** | TCP / HTTP | Thrift 二进制 |
| **Spring Cloud Feign** | HTTP | JSON |

### 💡 一句话总结

> **协议是分层的：**
> - **应用层协议**（HTTP、WebSocket、gRPC）定义了**数据格式和语义**
> - **传输层协议**（TCP、UDP）负责**数据的可靠传输**
> - **Socket** 是操作**传输层**的**编程接口**
> - **RPC** 是一种**架构模式**，可以通过各种底层协议实现
