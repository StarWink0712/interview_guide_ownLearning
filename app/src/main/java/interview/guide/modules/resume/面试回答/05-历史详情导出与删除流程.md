# 历史详情、PDF 导出与删除流程

## 1. 模块基础讲解

简历上传和分析完成后，用户需要查看历史、进入模拟面试、导出报告、删除数据。这些由 `ResumeHistoryService` 和 `ResumeDeleteService` 负责。

主要接口：

| 接口 | 方法 | 作用 |
|---|---|---|
| `/api/resumes` | GET | 简历列表 |
| `/api/resumes/{id}/detail` | GET | 简历详情、分析历史、面试历史 |
| `/api/resumes/{id}/export` | GET | 导出最新分析 PDF |
| `/api/resumes/{id}` | DELETE | 删除简历 |
| `/api/resumes/{id}/reanalyze` | POST | 重新分析 |

删除流程：

```text
查找 ResumeEntity
  -> 删除对象存储文件
  -> 删除关联面试会话
  -> 删除分析记录
  -> 删除简历实体
```

PDF 导出基于最新分析结果，如果没有分析结果会抛 `RESUME_ANALYSIS_NOT_FOUND`。

## 2. 基础面试问题

### Q1：简历详情页展示什么？

`ResumeDetailDTO` 包含：

1. 简历基本信息。
2. 对象存储 URL。
3. 解析后的简历文本。
4. 当前分析状态和错误。
5. 分析历史列表。
6. 关联面试历史列表。

这体现了简历模块和模拟面试模块的业务联动。

### Q2：PDF 导出怎么实现？

`ResumeHistoryService.exportAnalysisPdf()` 查询简历和最新分析结果，然后调用 `PdfExportService.exportResumeAnalysis()` 生成 PDF bytes。Controller 设置 `Content-Disposition` 和 `application/pdf` 返回给浏览器下载。

### Q3：删除简历会删除哪些数据？

删除对象存储中的原始文件、关联面试会话、简历分析记录、简历实体。面试会话删除会自动删除面试答案。

### Q4：重新分析做了什么？

`reanalyze()` 会获取简历文本，若数据库没有文本则从对象存储下载并重新解析；然后把状态置为 `PENDING`，清空错误信息，再发送新的异步分析任务。

## 3. 进阶面试问题

### Q1：PDF 导出为什么不直接在 Controller 生成？

Controller 应只负责 HTTP 协议细节。业务查询和 PDF 生成由 Service 完成，符合分层设计，也便于复用和测试。

### Q2：删除对象存储失败为什么继续删除数据库？

这是以用户数据删除体验为优先的设计。对象存储删除失败可能是临时故障，如果因此阻止数据库删除，用户会感觉删除失败。当前做法是记录 warn，继续删除数据库。

风险是留下孤儿文件，所以生产应增加删除失败补偿机制。

### Q3：删除简历时异步分析任务还在跑怎么办？

如果消费者后续处理消息，会发现 `resumeRepository.findById(resumeId)` 为空，抛 `AsyncTaskCancelledException`，任务会被标记取消并 ACK，不会无限重试。

如果分析已经进入 LLM 调用阶段，当前没有强制中断能力，可能等调用结束后再次查简历时发现已删除并取消。

### Q4：详情页返回 `resumeText` 有什么风险？

简历文本包含个人信息。当前详情 DTO 直接包含 `resumeText`，适合本人查看或后台调试，但生产环境需要权限校验、脱敏和最小化返回。普通列表页不应返回全文。

## 4. 技术延伸问题

### Q1：如何做删除补偿？

可以新增 `file_delete_failures` 表：

```text
fileKey
businessType
businessId
errorMessage
retryCount
nextRetryAt
status
```

对象存储删除失败时写入，定时任务重试，直到成功或进入人工处理。

### Q2：如何做 PDF 导出异步化？

如果 PDF 很复杂或需要批量导出，可以：

1. 创建导出任务。
2. 后台生成 PDF 并上传对象存储。
3. 前端轮询导出任务状态。
4. 完成后返回下载链接。

当前单份简历报告同步导出可以接受。

### Q3：如何做分析报告版本化？

导出时可以把 `analysisId`、模型版本、Prompt 版本写入 PDF 页脚或元数据，保证报告可追溯。

## 5. 改进方案问题

### Q1：历史和导出流程优点是什么？

1. 详情页聚合简历、分析历史和面试历史。
2. PDF 导出基于最新分析，体验完整。
3. 删除流程覆盖对象存储、面试会话、分析记录。
4. 重新分析可复用已有文本或重新解析文件。

### Q2：当前不足是什么？

1. 列表无分页。
2. PDF 导出异常在 Controller 中返回 500，没有统一 `Result` 错误体。
3. 删除对象存储失败缺少补偿。
4. 删除没有软删除和审计。
5. 详情返回全文缺少脱敏和权限。

### Q3：如何优化导出接口？

1. 统一异常处理，不在 Controller catch 泛型 Exception。
2. 文件名清理，避免特殊字符问题。
3. 支持按 `analysisId` 导出历史版本。
4. 增加导出水印或生成时间。
5. 大报告异步导出。

## 6. 故障处理问题

### Q1：PDF 导出失败怎么办？

排查：

1. 简历是否存在。
2. 是否有最新分析结果。
3. `PdfExportService` 是否支持当前字符和模板。
4. 文件名是否包含异常字符。
5. 日志中的 `EXPORT_PDF_FAILED` 具体原因。

### Q2：删除后文件还在对象存储怎么办？

说明 `deleteResume()` 过程中对象存储删除失败但数据库删除继续。短期可以手动删除 fileKey；长期应做删除失败补偿任务。

### Q3：重新分析失败怎么办？

排查：

1. `resumeText` 是否为空。
2. 对象存储文件是否还能下载。
3. Tika 重新解析是否成功。
4. Stream 是否成功入队。
5. LLM 分析是否失败。
