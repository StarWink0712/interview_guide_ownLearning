# 简历模块总览与业务闭环

## 1. 模块基础讲解

`resume` 模块是 AI 面试平台求职者闭环的入口模块。它负责把用户上传的一份简历，转换成可存储、可去重、可解析、可 AI 分析、可导出报告、可关联模拟面试的业务资产。

从业务闭环看，它不是简单文件上传，而是：

```text
简历上传
  -> 文件校验与类型检测
  -> 文件内容哈希去重
  -> Apache Tika 解析文本
  -> RustFS/S3 对象存储
  -> PostgreSQL 保存简历元数据和文本
  -> Redis Stream 异步触发 AI 分析
  -> LLM 结构化评分
  -> 保存分析历史
  -> 前端查看详情/导出 PDF/进入模拟面试
```

模块主要分层：

| 层次 | 代表类 | 职责 |
|---|---|---|
| Controller | `ResumeController` | 上传、列表、详情、导出、删除、重新分析 |
| 上传编排 | `ResumeUploadService` | 文件校验、去重、解析、存储、入库、发送异步任务 |
| 文件解析 | `ResumeParseService` | 委托 Tika 解析文本，支持从对象存储下载后解析 |
| AI 分析 | `ResumeGradingService` | Prompt 模板 + Spring AI + 结构化输出重试 |
| 异步执行 | `AnalyzeStreamProducer/Consumer` | Redis Stream 投递和消费简历分析任务 |
| 持久化 | `ResumePersistenceService` | 保存简历和分析结果，文件 hash 去重 |
| 历史查询 | `ResumeHistoryService` | 列表、详情、分析历史、面试历史、PDF 导出 |
| 删除 | `ResumeDeleteService` | 删除对象存储文件、面试会话、简历和分析记录 |

面试时建议从业务价值讲起：

> 这个模块是整个 AI 面试平台的入口。用户上传简历后，系统不只是保存文件，而是解析简历文本、异步调用 AI 做多维评分和优化建议，再把分析结果沉淀为后续模拟面试和知识补弱的输入。

## 2. 基础面试问题

### Q1：简历模块的核心功能是什么？

核心功能包括：上传简历、解析文本、文件去重、对象存储、异步 AI 分析、查看分析历史、导出 PDF 报告、删除简历和关联面试数据。

一句话回答：

> 简历模块把用户上传的文件转化成平台后续 AI 面试流程可使用的结构化资产，是求职者闭环的第一个入口。

### Q2：为什么简历分析要异步？

因为简历分析包含文件解析、对象存储、LLM 调用和结构化输出解析，耗时和失败概率都比普通 CRUD 高。如果同步放在上传接口里，用户等待时间长，也容易 HTTP 超时。

当前实现是上传接口快速返回简历 ID 和 `PENDING` 状态，后台通过 Redis Stream 执行分析，前端通过状态轮询查看结果。

### Q3：简历上传后前端拿到什么？

新简历返回：

```text
resume.id
resume.filename
resume.analyzeStatus=PENDING
storage.fileKey
storage.fileUrl
storage.resumeId
duplicate=false
```

重复简历如果已有分析结果，会直接返回历史 `analysis` 和存储信息，`duplicate=true`。

### Q4：模块里有哪些关键技术？

1. 文件校验和 MIME 类型检测。
2. SHA-256 文件 hash 去重。
3. Apache Tika 文档解析。
4. RustFS/S3 兼容对象存储。
5. Redis Stream 异步任务。
6. Spring AI + StructuredOutputInvoker 结构化 JSON 输出。
7. MapStruct Entity/DTO 映射。
8. iText/PdfExportService 导出 PDF。

## 3. 进阶面试问题

### Q1：这个模块为什么不是普通上传 CRUD？

普通上传只保存文件。这个模块把上传动作变成一条 AI 业务链路：

1. 通过 hash 去重避免重复分析。
2. 通过 Tika 提取简历文本，让 AI 能理解文件内容。
3. 通过异步队列隔离耗时 LLM 分析。
4. 通过分析历史保留多次评分结果。
5. 通过关联面试历史形成后续模拟面试闭环。

所以它体现的是 AI 应用落地链路，而不是文件表 CRUD。

### Q2：模块如何和其他业务模块联动？

1. 和 `interview` 模块联动：简历详情会展示关联面试历史，删除简历时也删除关联面试会话。
2. 和 `asynctask` 模块联动：分析任务会写入统一异步任务表，支持状态查询、重试、取消。
3. 和 `aiobservability` 间接联动：`ResumeGradingService` 通过 `StructuredOutputInvoker` 调用 LLM，结构化输出调用会记录 AI 调用日志。
4. 和 `infrastructure/file` 联动：解析、存储、hash、校验都复用基础设施层。

### Q3：简历分析结果为什么单独建 `ResumeAnalysisEntity`？

因为同一份简历可能多次分析，例如用户重新分析、Prompt 版本变化、模型变化。单独建分析表可以保留历史记录，而不是覆盖旧结果。

`ResumeEntity` 保存简历原始资产和当前分析状态，`ResumeAnalysisEntity` 保存每次 AI 评分结果。

### Q4：当前模块有哪些真实边界？

需要诚实说明：

1. 简历去重基于文件内容 hash，不是语义级去重。
2. AI 分析结果依赖 LLM，不能保证绝对客观。
3. 重新分析不会记录 Prompt/模型版本到分析表。
4. 列表查询没有分页。
5. 删除对象存储失败时仍继续删除数据库，可能留下孤儿文件。

## 4. 技术延伸问题

### Q1：如果不用 Redis Stream，怎么实现异步分析？

可以选择：

| 方案 | 优点 | 缺点 |
|---|---|---|
| `@Async` | 简单 | 进程重启任务丢失，缺少 pending 恢复 |
| 定时任务扫表 | 数据库状态可靠 | 延迟高，DB 压力大 |
| RabbitMQ | 专业消息队列，死信/延迟成熟 | 增加中间件复杂度 |
| Kafka | 高吞吐可回放 | 对单任务状态查询不直接 |
| Redis Stream | 接入成本低，支持消费者组和 PEL | 需要自己管理重试和状态 |

当前项目已有 Redis，并且任务量属于中等规模，所以 Redis Stream 是合理选择。

### Q2：如果要支持多版本简历怎么办？

可以把 hash 去重从“阻止重复入库”改成“识别相同文件版本”，新增：

```text
candidateId
resumeVersion
isActive
source
```

同一个用户可以上传多个版本简历，平台保留版本对比和历史分析。

### Q3：如果要做岗位定制化分析怎么办？

当前评分是通用技术简历审计。岗位定制化可以增加：

1. jobDescription 字段。
2. 岗位技能要求解析。
3. 简历与 JD 匹配度评分。
4. 针对 JD 的改写建议。
5. 不同岗位 Prompt 模板。

## 5. 改进方案问题

### Q1：模块当前优点是什么？

1. 业务链路完整，从文件上传到 AI 分析结果落库。
2. 文件 hash 去重减少重复计算。
3. 异步任务隔离 LLM 耗时。
4. 上传失败有对象存储补偿。
5. 分析历史独立存储，支持多次分析。
6. Prompt 模板配置化，不写死在 Service 中。

### Q2：模块当前可以怎么优化？

1. 简历列表增加分页和排序。
2. 上传接口返回 `taskId`，让前端直接查统一异步任务状态。
3. 分析结果记录 Prompt 版本、模型、Provider、耗时。
4. 重复简历支持“强制重新分析”参数。
5. 删除流程增加对象存储删除失败补偿任务。
6. 对简历文本和 chunk preview 类敏感字段做脱敏和权限控制。

### Q3：如果要做生产级简历中心，还缺什么？

1. 用户/租户隔离。
2. 简历版本管理。
3. 批量上传和批量分析。
4. OCR 支持扫描版 PDF。
5. 分析结果人工反馈和模型评估。
6. 数据保留与删除合规。

## 6. 故障处理问题

### Q1：用户上传后一直分析中，怎么排查？

1. 查 `resumes.analyzeStatus` 是否为 `PENDING/PROCESSING`。
2. 查 `async_tasks` 是否有对应 `RESUME_ANALYZE` 任务。
3. 查 Stream 消息是否已入队。
4. 查 `AnalyzeStreamConsumer` 是否启动。
5. 查 LLM 调用是否失败或超时。
6. 查 `resume_analyses` 是否已生成结果但状态没更新。

### Q2：上传失败怎么定位？

按链路排查：

1. 文件是否为空或超过 10MB。
2. MIME 类型是否在允许列表。
3. Tika 是否能提取文本。
4. RustFS/S3 是否可用。
5. 数据库保存是否失败。
6. Redis Stream 入队是否失败。

### Q3：重复简历为什么没有重新分析？

因为当前逻辑基于文件 hash 去重。相同文件再次上传时，会返回历史分析结果或当前分析状态，不重复入队。如果想重新分析，需要调用 `/api/resumes/{id}/reanalyze`。
