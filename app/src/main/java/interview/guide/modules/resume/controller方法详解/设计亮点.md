---

## 一、三层去重防护体系

这是最亮眼的设计。不仅做了一层哈希比对，而是三层防线：

```
应用层：FileHashService 计算 SHA-256 → 命中则跳过解析/存储/AI分析，直接返回历史结果
  +
数据库层：ResumeEntity.fileHash 上挂了 @Column(unique=true) + @Index(unique=true) 唯一约束
  +
业务层：Controller 根据返回 Map 中的 duplicate=true/false 分支处理，重复时提示"检测到相同简历"
```

去重命中后还会调用 `resume.incrementAccessCount()` 累加访问次数，相当于埋了一个热度统计。

---

## 二、同步+异步混合架构

上传链路拆得干净，同步部分只做必要的事，AI 分析彻底异步化：

```
同步（HTTP 请求线程，1-3秒）:
  文件校验 → 类型检测 → 去重检查 → 文本解析 → RustFS 存储 → 数据库落库
  
异步（Redis Stream 消费者，不限时）:
  AnalyzeStreamConsumer → ResumeGradingService → LLM 结构化评分 → 持久化分析结果
```

请求返回 `analyzeStatus=PENDING`，前端轮询 `getResumeDetail` 看状态变化。这样的好处是用户上传完立刻看到响应，不用干等 LLM 的几秒甚至十几秒。

[AnalyzeStreamConsumer.processBusiness()](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/java/interview/guide/modules/resume/listener/AnalyzeStreamConsumer.java#L156-L181) 中有一个精妙的检查：

```java
if (resume.getAnalyzeStatus() == AsyncTaskStatus.COMPLETED
```

## 四、结构化输出的中间 DTO 模式

[ResumeGradingService](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/java/interview/guide/modules/resume/service/ResumeGradingService.java) 没有直接用 `ResumeAnalysisResponse` 接收 AI 输出，而是定义了一套内部 `record` 作为中间载体：

```
LLM 输出
  → BeanOutputConverter<ResumeAnalysisResponseDTO>  (内部 record，只做反序列化)
    → convertToResponse()  (手动字段映射，去掉原始文本等内部字段)
```

## 六、补偿事务机制

[ResumeUploadService](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/java/interview/guide/modules/resume/service/ResumeUploadService.java) 中文件存储和数据库落库之间做了补偿：

```java
// 步骤5: 上传 RustFS 成功
String fileKey = storageService.uploadResume(file);
// 步骤6: 入库
try {
    savedResume = persistenceService.saveResume(...);

    compensateUploadedResume(fileKey, e);  // 入库失败 → 删除已上传的文件

```

RustFS 是外部存储不在数据库事务管控范围内，所以手动补偿保证一致性。

## 十、限流的分层策略

| 方法 | GLOBAL | IP | 理由 |
|------|--------|-----|------|
| `uploadAndAnalyze` | 5/s | 5/s | 上传有文件大小限制 + AI 成本 |
| `reanalyze` | 2/s | 2/s | 比上传更严，手动重试不应频繁 |
| 查询/导出/删除 | 无 | 无 | 低频操作 |

两个维度独立计数，AOP + Redis Lua 脚本实现滑动窗口，不占用应用内存。
