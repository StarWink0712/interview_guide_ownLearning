就是原文件。从 [FileStorageService 的上传方法](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/java/interview/guide/infrastructure/file/FileStorageService.java#L112-L134) 可以看到：

```java
private String uploadFile(MultipartFile file, String prefix) {
    // ...
    PutObjectRequest putRequest = PutObjectRequest.builder()
            .bucket(storageConfig.getBucket())
            .key(fileKey)
            .contentType(file.getContentType())   // 保留原始 MIME 类型
            .contentLength(file.getSize())        // 原始文件大小
            .build();

    s3Client.putObject(putRequest,
        RequestBody.fromInputStream(file.getInputStream(), file.getSize()));  // 原封不动传进去
}
```

就是 `file.getInputStream()` 直接往里放，不做任何转码或格式转换。上传的是 PDF 就是 PDF 的二进制流，DOCX 就是 DOCX 的二进制流。

---

对象存储存两样东西：

| 存储内容 | 格式 | 存在哪 |
|----------|------|--------|
| **原始文件本身** | PDF/DOCX/TXT/MD 等，原样不动 | RustFS (MinIO/S3) |
| **解析后的纯文本** | `resumeText` 字段，String | PostgreSQL `resumes` 表 |

上传一个 `张三的简历.pdf` 后：

```
RustFS (MinIO):
  interview-guide/resumes/2025/06/a1b2c3d4_ZhangSanDeJianLi.pdf   ← 原始 PDF 字节

PostgreSQL:
  resumes 表 某行：
    storage_key: "resumes/2025/06/a1b2c3d4_ZhangSanDeJianLi.pdf"
    storage_url: "http://localhost:9000/interview-guide/resumes/..."
    resume_text: "张三，男，25岁，3年Java开发经验..."              ← 解析后的纯文本
    content_type: "application/pdf"
```

原始文件留着的意义：用户后续可以下载、重新解析（比如换了解析策略需要重新提取文本时，直接从 RustFS 把原始文件拉回来再跑一次 Tika），以及 PDF 导出报告时可能用到。

所以回答就是：**存的是原文件格式，不做任何转换，与此同时数据库里另存了一份解析好的纯文本供 AI 评分使用**。
