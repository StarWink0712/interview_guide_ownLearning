# 面试中如何讲 PdfExportService 模块

---

## 一、一段话总结（口头回答模板）

> 我负责了面试平台的 PDF 导出模块 `PdfExportService`，基于 iText 8 实现了简历分析报告和模拟面试报告的 PDF 文件生成。核心解决了三个问题：第一个是**中文字体渲染**——iText 默认不支持中文，我通过在 resources 下内嵌了朱雀仿宋字体文件，加载时做 `FORCE_EMBEDDED` 强制嵌入，保证 PDF 在任何设备上打开都能正常显示中文；第二个是**文本清洗**——用户输入和 LLM 返回中可能包含 emoji 等特殊字符，这些字符在 PDF 字体中不存在会导致渲染异常，我用正则 `[\p{So}\p{Cs}]` 在写入前过滤掉；第三个是**结构化排版**——评分用三色阶梯（绿≥80、黄≥60、红<60）的表格呈现，简历分析的维度评分用 iText 的 `Table` 布局，面试报告的问答详情逐条展开，包含问题、回答、评分、反馈和参考答案。配置上保持了项目风格，用 `@Service` + `@RequiredArgsConstructor` 做依赖注入，`@Slf4j` 做日志，JSON 字段用 Jackson 的 `ObjectMapper` 反序列化，异常统一走 `BusinessException(ErrorCode.EXPORT_PDF_FAILED)`。

## 二、面试中怎么展开讲？——分步讲解思路

### 第 1 步：先讲背景和定位（10 秒）

**你要传递的信息**：

- 这是一个基础设施层的服务，放在 `infrastructure/export` 包下
- 负责把评估结果导出为 PDF 文件，两类报告：简历分析报告 + 模拟面试报告
- 被 `ResumeHistoryService` 和 `InterviewHistoryService` 调用

**口头表达示例**：

> PDF 导出服务放在 infrastructure 层，定位是纯技术基础设施，不涉及业务逻辑。它接收简历实体和分析结果、或者面试会话实体，输出 PDF 字节数组，调用方拿到 byte[] 后可以直接返回给前端下载，或者上传到 S3。

---

### 第 2 步：讲核心难点——中文乱码怎么解决（重点，40 秒）

**你要传递的信息**：

- iText 默认不支持中文，必须自行加载中文字体
- 字体文件内嵌到 jar 包里（`resources/fonts/`），部署时不用额外配置
- `FORCE_EMBEDDED` 保证 PDF 在任何设备打开都正常显示

**口头表达示例**：

> 这个模块最大的坑是中文字体。iText 默认只支持西文字体，如果你不显式加载中文字体，导出后所有中文都是空白或者乱码。我的解决方案是在 `resources/fonts/` 下放了一个朱雀仿宋的 ttf 文件，启动时通过 `ClassLoader.getResourceAsStream` 读成字节数组，然后用 `PdfFontFactory.createFont` 创建字体对象，编码选 `IDENTITY_H`（Unicode 编码），嵌入策略选 `FORCE_EMBEDDED`，这样字体数据会内嵌到 PDF 文件里。好处是无论对方用什么设备打开 PDF，即使他的系统没装这个字体，也能正常显示。缺点是 PDF 文件会大几 MB，但对于面试报告这种单份下载的场景完全可接受。

---

### 第 3 步：讲第二个难点——特殊字符导致字体渲染崩溃（30 秒）

**你要传递的信息**：

- LLM 返回和用户输入中可能包含 emoji（😀、👍 等）
- 这些 Unicode 字符在朱雀仿宋的字体文件中不存在
- iText 遇到不存在的字形会抛异常或者渲染成豆腐块
- 解决方案：写入前用正则 `[\p{So}\p{Cs}]` 过滤

**口头表达示例**：

> 还有一个坑是特殊字符。现在 LLM 特别喜欢在输出里加 emoji，比如在"优势亮点"里写个 ⭐。但这个 ⭐ 在朱雀仿宋的字体文件里根本没有对应的字形，iText 渲染时会抛异常。我做的处理是在 `sanitizeText` 方法里用正则把 Unicode 符号类 `\p{So}` 和代理对 `\p{Cs}` 全部过滤掉。这解决了 90% 的问题——虽然 emoji 没了，但文字内容完整保留，对阅读体验影响很小。如果要求更高，可以换一个字形覆盖更全的字体，或者在 `\p{So}` 部分只过滤 emoji 相关的码点范围，但这个正则已经够用了。

---

### 第 4 步：讲排版设计（展示代码质量，30 秒）

**你要传递的信息**：

- 结构化排版：标题 → 基本信息 → 评分 → 各维度/问答 → 评价
- 三色评分阶梯（绿/黄/红），直观可读
- 评分用 Table 布局，面试问答逐条展开

**口头表达示例**：

> 排版上我没有用模板引擎（比如 Thymeleaf 转 HTML 再转 PDF），而是直接用 iText 的 API 硬编码布局，因为 PDF 结构固定、字段清晰，不需要模板的灵活性带来的额外复杂度。
>
> 简历分析报告的结构是：居中大标题 → 基本信息和上传时间 → 总分（字号 18、加粗、颜色根据分数三色变化）→ 各维度评分表格（项目经验/技能匹配度等 5 个维度，用 Table 的两列布局）→ 简历摘要 → 优势亮点列表 → 改进建议（优先级标签 + 问题 + 建议）。
>
> 面试报告的结构类似，多了笔试详情——每道题包含题号、分类、问题原文、用户回答、得分、评价反馈、参考答案。每题一个区块，信息层次分明。
>
> 颜色用的三色阶梯：80 分以上绿色、60-80 分黄色、60 分以下红色。不是硬编码的 if-else 散落各处，而是抽了一个 `getScoreColor` 方法。

---

### 第 5 步：讲工程细节（加分项，20 秒）

**你要传递的信息**：

- JSON 字段反序列化（优势/改进存在数据库 JSON 字段里）
- 异常统一处理（`BusinessException`）
- 构造器注入（`@RequiredArgsConstructor`）
- 输出用 `ByteArrayOutputStream`，调用方灵活处理

**口头表达示例**：

> 工程细节上几个点。面试会话的优势和改进建议存在数据库的 JSON 字段里，导出时用 Jackson 的 `ObjectMapper.readValue` + `TypeReference<List<String>>` 反序列化，失败时 catch 不中断流程只打日志——宁可少一部分内容也不能让整份 PDF 导出失败。
>
> 异常处理统一走 `BusinessException(ErrorCode.EXPORT_PDF_FAILED)`，比如字体文件缺失或者创建字体失败，不是因为数据问题，是系统级问题，直接抛业务异常让全局异常处理器返回错误信息。
>
> 输出用的是 `ByteArrayOutputStream`，生成完 PDF 后返回 `byte[]`，调用方可以自由选择写到 HTTP Response、上传 S3、或者缓存到本地，不依赖任何特定输出目标。

### 第 6 步：如果有追问——准备几个可能的问题

#### Q1：为什么不用 HTML 模板转 PDF？比如 Flying Saucer 或者 wkhtmltopdf？

> HTML 转 PDF 的方案问题很多：CSS 兼容性差、分页不可控、中文字体更难处理、部署依赖外部二进制文件（wkhtmltopdf）。iText 直接操作 PDF 对象模型，分页、字体、颜色都能精确控制。虽然写起来比模板多几行代码，但结构固定、字段明确的场景下更可靠。

#### Q2：字体文件放在 resources 里会不会让 jar 包太大？

> 朱雀仿宋约 5MB，对于 Spring Boot 单体应用完全可以接受。如果对体积敏感，可以换成更小的中文字体（比如思源黑体的 subset），或者用系统自带的宋体回退方案——但后者会让部署环境有依赖，权衡下来内嵌字体是最稳妥的选择。

#### Q3：如果 PDF 内容超过一页怎么办？

> iText 的 `Document` 自动处理分页，不需要手动干预。我在代码里没有显式分页，但目前报告内容量通常 2~3 页，iText 的自动分页效果足够好。如果内容特别多，可以在章节间手动加 `AreaBreak` 做强制分页。

#### Q4：Score 的颜色映射为什么是 80/60 分界线？

> 这是一个常见的评分阶梯，80 分以上算优秀（绿色）、60-80 算合格（黄色）、60 以下不合格（红色），和大多数评分系统的标准一致。颜色逻辑抽在 `getScoreColor` 方法里，改规则只需动一处。
