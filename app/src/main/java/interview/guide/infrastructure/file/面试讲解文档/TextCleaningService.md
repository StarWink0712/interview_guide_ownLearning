## 二、执行步骤详解

1. **空值防护**：`null` 或 `isBlank()` 直接返回空字符串，避免后续正则抛出 `NullPointerException`。

2. **第一层：语义去噪（5 步正则清洗）**：

   | 步骤 | 目标 | 正则 | 说明 |
   |------|------|------|------|
   | 控制字符 | `[\u0000-\u0008\u000B\u000C\u000E-\u001F]` | 移除不可见字符，保留 `\n(0x0A)` 和 `\t(0x09)` |
   | 图片文件名行 | `(?m)^image\d+\.(png\|jpe?g\|...)\s*$` | 整行匹配，防止误删正文 |
   | 图片链接 | `https?://\S+?\.(png\|...)(\?\S*)?` | 大小写不敏感，支持查询参数 |
   | 文件协议路径 | `file:(//)?\S+` | Tika 解析 PDF 产生的临时文件路径 |
   | 分隔线 | `(?m)^\s*[-_*=]{3,}\s*$` | 至少 3 个连续符号，整行匹配 |

3. **第二层：格式规范化（3 步正则清洗）**：
   - **统一换行符**：`\r\n` → `\n`，`\r` → `\n`（兼容 Windows/Linux/Mac 换行格式）
   - **去行尾空格**：`(?m)[ \t]+$` 移除每行末尾的空格和制表符，保留空行以维持段落结构
   - **压缩空行**：`\n{3,}` → `\n\n`（最多保留 2 个换行符，即一个段落间距）

4. **最终处理**：`strip()` 去除首尾空白，返回清洗后的文本。

5. **辅助方法**：
   - `cleanTextWithLimit`：清洗 + 截断，防止超长文本
   - `cleanToSingleLine`：所有换行转空格，用于日志/标题等单行场景
   - `stripHtml`：去除 HTML 标签并解码常见 HTML 实体（`&nbsp;`、`&amp;` 等）

## 三、结构化详细总结

### 功能用途

作为 **RAG/AI 分析前的"保险层"**，对 Tika 解析后的原始文本进行清洗和规范化。核心价值在于**去除噪声内容**（Tika 解析 PDF 的图片引用、临时文件路径、分隔线等），确保送入 LLM 的文本干净、高质量。

### 核心算法

- **两层清洗架构**：语义去噪（去除无意义内容）+ 格式规范化（统一文字格式），职责分离清晰。
- **预编译正则**：所有 `Pattern` 实例声明为 `private static final`，在类加载时编译一次，避免每次方法调用时重复编译正则表达式——对高频调用（批量文件处理）有显著性能收益。
- **整行匹配策略**：图片文件名和分隔线使用 `(?m)` 标志 + `^...$` 锚定整行，避免误删正文中包含类似模式的内容。

### 关键实现细节

| 细节 | 说明 |
|------|------|
| `IMAGE_FILENAME_LINE` 的 `(?m)` | 多行模式，`^` 和 `$` 匹配行首行尾而非字符串首尾 |
| `CONTROL_CHARS` 保留 `\n` 和 `\t` | `\n` 保留用于段落结构，`\t` 保留用于表格对齐 |
| 禁止连续三个换行 | `\n{3,}` 替换为 `\n\n`，保证段落间最多一个空行 |
| HTML 实体映射 | `stripHtml` 支持 6 种常见实体，覆盖绝大多数 HTML 文档场景 |

### 潜在优化点

- 当前正则完全基于英文场景（`image\d+` 只匹配英文文件名），如果中文用户上传含中文图片名的文档，可能无法过滤。可增加中文/Unicode 文件名模式。
- `stripHtml` 中 HTML 解码列表不完整（仅 6 种），如有大量 HTML 文档需求可引入 `StringEscapeUtils.unescapeHtml4()`（Apache Commons Text）。
- 可增加 Markdown 语法清洗（如 `**粗体**` → 纯文本），当 LLM 不需要格式化标记时更友好。
- 正则匹配较消耗 CPU，若处理超长文本（> 10MB），可考虑分块处理或流式清洗。

## 四、一段话总结

TextCleaningService 是 RAG/AI 分析前的"文本保险层"，它采用两层清洗架构对 Tika 解析后的原始文本进行深度净化：第一层语义去噪通过五个预编译正则依次移除控制字符、图片文件名行（整行匹配防止误删正文）、图片链接、文件协议路径（Tika 的临时文件引用）和符号分隔线；第二层格式规范化统一换行符（\r\n 和 \r 转 \n）、去除行尾空格制表符、压缩连续空行（最多保留一个段落间距），最后 strip 首尾空白。所有 Pattern 均声明为 private static final，在类加载时编译一次，高频调用场景下零编译开销。辅助方法方面，cleanTextWithLimit 支持截断保护、cleanToSingleLine 将多行文本压缩为单行用于日志展示、stripHtml 能剥离 HTML 标签并解码六种常见 HTML 实体。整行匹配策略（(?m) 标志 + ^...$ 锚定）是设计上的一个关键取舍——宁可保留少量噪声，也绝不误删正文中碰巧包含类似模式的有意义内容，这体现了文本清洗场景下"保守过滤"的设计哲学。
