## UnifiedEvaluationService.java 详细分析

这是整个项目的**面试评估核心引擎**，文字面试和语音面试共用。它接收问答记录，调用 LLM（大语言模型）分析后生成 `EvaluationReport`。

---

### 一、整体架构

```
AnswerEvaluationService（文字面试）
          ↘
            UnifiedEvaluationService（核心评估引擎）
          ↗                     ↓
VoiceInterviewEvaluationService   EvaluationReport（最终产出）
```

调用方只需要传问答记录进来，`UnifiedEvaluationService` 内部自动完成分批、评估、汇总，最后返回一份完整的评估报告。

---

### 二、依赖关系

| 依赖 | 作用 |
|------|------|
| `StructuredOutputInvoker` | 调用 LLM 并要求**结构化输出**（自动重试 + JSON 修复） |
| `InterviewEvaluationProperties` | 读取 `app.interview.evaluation.*` 配置（批次大小、Prompt 路径） |
| `ResourceLoader` | 加载 `resources/prompts/` 下的 Prompt 模板文件 |
| `ChatClient` | 由调用方传入，代表具体的 LLM 客户端 |

---

### 三、三阶段评估流程（核心）

```
阶段 1：分批评估
  把 N 道题按 batchSize（默认 8）分成多批
  每批独立调用 LLM → 得到 BatchReportDTO（含逐题评分 + 综合评语）
  单批失败 → 零分兜底

阶段 2：合并批次
  把各批的逐题评分合并成一个列表（缺失补 0 分）
  综合评语拼接在一起（兜底数据）

阶段 3：二次汇总
  把所有批次的中间结果再喂给 LLM 一次
  让 LLM 生成一份统一的综合评语
  失败 → 降级使用阶段 2 的拼接结果
              ↓
          EvaluationReport
```

### 四、字段详解

#### 成员变量

```java
// Prompt 模板（从 .st 文件加载）
systemPromptTemplate       // 批次评估：系统角色设定
userPromptTemplate         // 批次评估：用户传入的问答内容
summarySystemPromptTemplate // 二次汇总：系统角色设定
summaryUserPromptTemplate   // 二次汇总：用户传入的中间结果

// 结构化输出转换器（告诉 LLM 按什么格式输出）
outputConverter            // 对应 BatchReportDTO 格式
summaryOutputConverter     // 对应 SummaryDTO 格式

// 其他
structuredOutputInvoker    // LLM 调用器（含重试）
evaluationBatchSize        // 每批几道题（默认 8）
resourceLoader             // 加载 Prompt 文件
```

#### 内部 record（纯 DTO）

```java
BatchReportDTO   // LLM 单批次返回：总分、反馈、优劣势、逐题评分
QuestionEvalDTO  // 单题结果：题号、分数、反馈、参考答案、关键要点
BatchResult      // 包装类：批次起止索引 + 对应的 BatchReportDTO
SummaryDTO       // 二次汇总返回：统一综合评语、优势、改进建议
```

### 五、关键方法详解

#### 1. 入口方法：`evaluate()`（五参数版本）

```java
public EvaluationReport evaluate(ChatClient chatClient, String sessionId,
    List<QaRecord> qaRecords, String resumeText, String referenceContext)
```

**处理步骤**：
1. 简历文本 > 3000 字符自动截断
2. 参考上下文 > 6000 字符自动截断
3. 分批发给 LLM 评估
4. 合并多批次结果
5. 二次汇总
6. 构建最终报告

四参数便捷版本就是不传 `referenceContext`，内部调用五参数版本传 `null`。

#### 2. 批次评估：`evaluateBatch()`

- 用 `buildQARecords()` 把 `QaRecord` 格式化成 LLM 能看懂的文本
- 用 `StringTemplate` 模板渲染 system/user prompt
- 调用 `structuredOutputInvoker.invoke()` 要求 LLM 按 `BatchReportDTO` 格式输出
- **失败返回 `null`**，不抛异常，由上层合并逻辑零分兜底

#### 3. 合并逐题评估：`mergeQuestionEvaluations()`

逐批次遍历，如果某批次评估失败（report 为 null）或某题缺少评估数据，自动填充零分兜底条目：

```java
new QuestionEvalDTO(
    result.startIndex() + i, 0,
    "该题未成功生成评估结果，系统按 0 分处理。", "", List.of()
)
```

#### 4. 二次汇总：`summarizeBatchResults()`

将各批次的分类得分、题目亮点、兜底反馈全部整理进 Prompt，让 LLM 做一次全局总结，产出一份统一的综合评语。LLM 调用失败时用 `fallbackFeedback` 兜底。

#### 5. 构建最终报告：`buildReport()`

这个方法是最终的数据聚合逻辑：

```
qaRecords + evaluations
    → 逐题生成 QuestionEvaluation（评分+反馈）和 ReferenceAnswer（参考答案+要点）
    → 按 category 分组计算每个分类的平均分
    → 所有已回答题目取平均分作为总分（未回答不参与计算）
    → 组装 EvaluationReport
```

**空值保护无处不在**：LLM 返回的 score、feedback、referenceAnswer 为 null 时全部用默认值兜底。

### 六、设计亮点

| 设计 | 说明 |
|------|------|
| **分批评估** | 一次面试可能有 20+ 道题，一次全丢给 LLM 效果差且有 token 限制。分批处理，每批 8 题，更精准 |
| **二次汇总** | 分批后各批各有自己的综合评语，再汇总一次让 LLM 产出全局视角的统一评语 |
| **双层降级** | 单批失败 → 零分兜底；汇总失败 → 用拼接结果兜底。保证系统在任何情况下都能返回有效报告 |
| **文字/语音共用** | 两种面试场景评估逻辑完全一致，复用同一份代码 |
| **结构化输出** | 使用 `BeanOutputConverter` 告诉 LLM 按固定 JSON 格式输出，再反序列化为 Java 对象 |
| **Prompt 模板化** | Prompt 内容放在 `.st` 文件中，修改 Prompt 不需要改代码，只需要改配置文件路径 |

---

### 七、完整调用链路

```
前端提交面试答案
    → Controller 接收请求
    → AnswerEvaluationService / VoiceInterviewEvaluationService
        → 构建 QaRecord 列表
        → 调用 UnifiedEvaluationService.evaluate(chatClient, sessionId, qaRecords, resumeText)
            → 阶段1：分批评估（每批调用 LLM）
            → 阶段2：合并批次结果
            → 阶段3：二次汇总（再次调用 LLM）
            → buildReport() 构建 EvaluationReport
    → Controller 返回 EvaluationReport JSON 给前端展示
```
