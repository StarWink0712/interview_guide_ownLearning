## 完整例子：用户说"请介绍一下 Spring 的 AOP 原理"

对，你理解得很准确。本质就是四个时间点：

```
用户开始说话
    │
    ▼
  ASR 合并等待  ← 从第一段识别结果出现，到用户点击提交的时间差
    │           （用户可能说了好几段话，ASR 分段返回，最后用户点提交）
    │
    ▼
  LLM 首 token  ← 从 LLM 开始调用，到第一个字出现（流式模式下才有这个指标）
    │
    ▼
  LLM 总耗时    ← LLM 把整段回答生成完
    │
    ▼
  TTS 合成      ← 把文字转成语音
    │
    ▼
 整轮总耗时      ← 上面四项加起来，就是用户听到语音回复前的全部等待时间
```

这些指标在 Dashboard 上的业务意义就是：**语音面试的用户体验瓶颈在哪？**

- LLM 慢 → 换更快的模型或缩短 prompt
- TTS 慢 → 换 TTS 服务商或用流式并发
- ASR 合并等待长 → 用户习惯，无需优化
- 整轮总耗时超过 10 秒 → 用户会感觉卡顿

private double resolveVoiceAverageTurnLatencyMs() {
