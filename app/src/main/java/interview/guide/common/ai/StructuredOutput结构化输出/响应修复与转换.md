是的，就是做 LLM 返回内容的 JSON 修复和转换。

### 执行流程

```
LLM 返回原始文本 → outputConverter.convert(content)
                        │
            ┌───────────┴───────────┐
            ▼                       ▼
       转换成功                   转换失败（抛异常）
            │                       │
            ▼                       ▼
      return 结果            repairUnescapedQuotesInJsonStrings(content)
                               修复 JSON 中未转义的引号
                                    │
                        ┌───────────┴───────────┐
                        ▼                       ▼
                 内容没变化                   内容有变化
                 （没有可修复的）             （确实修了）
                        │                       │
                        ▼                       ▼
                 直接抛异常             outputConverter.convert(repaired)
                                               │
                                   ┌───────────┴───────────┐
                                   ▼                       ▼
                              转换成功                   转换失败
                                   │                       │
                                   ▼                       ▼
                          log.warn("已在本地修复后解析成功")    再次抛异常
                          return 结果                     （原始异常 + 修复异常合并）
```

### 为什么需要这个？

LLM 返回 JSON 时经常出现这种问题：

```json
{"answer": "他说"你好"", "score": 85}
          ↑       ↑
    这两个中文引号或未转义的引号会让 JSON 解析器直接报错
```

`repairUnescapedQuotesInJsonStrings` 把它修成：

```json
{"answer": "他说\"你好\"", "score": 85}
```

然后 `outputConverter.convert()` 就能正常解析了。

### 关键设计细节

- **只修一次**：本地修复是"最后一道防线"，不会循环修复
- **内容无变化就不重试**：`repaired.equals(content)` 说明没有可修的问题，直接抛原始异常让外层重试循环接管
- **异常不丢失**：修复失败时用 `firstError.addSuppressed(repairError)` 把修复异常附在原始异常上，调试时能看到完整信息

### 在外层重试循环中的位置

```
invoke() 主流程：
  ┌─ 第 1 次 LLM 调用 → content
  │     └─ convertWithRepair(content)
  │           ├─ 直接转换成功 → 返回 ✅
  │           ├─ 本地修复成功 → 返回 ✅
  │           └─ 本地修复失败 → 抛异常 → 进入第 2 次重试
  │
  └─ 第 2 次 LLM 调用（带修复提示词）→ content
        └─ convertWithRepair(content)
              └─ ...
```

先尝试本地修（零成本），修不好才走重试（再调一次 LLM，有成本），设计上很合理。
