数据库模式优先，有两个核心原因：

### 1. 动态更新，无需重启
配置文件（ application.yml ）修改后必须重启应用才能生效。而数据库中的 Provider 配置可以通过管理界面增删改， 运行时即时生效 。 LlmProviderRegistry 也提供了 reload() 方法清空缓存，重新从数据库加载最新配置。

### 2. API Key 安全性
数据库模式的 API Key 是 加密存储 的（有 encryptionService.decrypt(...) 步骤），比明文写在 YAML 里更安全。即使数据库泄露，没有解密密钥也拿不到原始 Key。

简单说： YAML 是静态初始配置，数据库是生产环境动态管理的首选方案


    /**
     * Provider 数据访问层，用于从数据库读取 Provider 配置。
     * 可为 null（非数据库模式时使用配置文件）。
     * 优先走数据库存储的配置，而不是走配置文件的配置
     * 因为数据库是可以动态更新的，而配置文件修改较麻烦，项目不需要重启
     * apikey可以在数据库中加密存储，比明文写在yml中要安全。
     */
