## RateLimit.java 代码分析讲解

### 一、整体定位

这是一个**方法级限流注解**，作用于 Controller 层方法，与 [RateLimitAspect.java](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/java/interview/guide/common/aspect/RateLimitAspect.java) 配合使用，通过 AOP 拦截 + Redis Lua 脚本实现**滑动时间窗口限流**。

`RateLimit` 是定义在 [RateLimit.java](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/java/interview/guide/common/annotation/RateLimit.java) 中的一个方法级限流注解，通过 `@Repeatable` 机制支持在同一方法上标注多条规则，每条规则包含限流维度（`Dimension` 枚举，支持 GLOBAL 全局、IP 按客户端地址、USER 按用户 ID）、时间窗口内允许的最大请求数 `count`、窗口大小 `interval` 及时间单位 `timeUnit`（默认每秒）、以及可选的 `fallback` 降级方法名。当请求到达被标注了 `@RateLimit` 的 Controller 方法时，[RateLimitAspect.java](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/java/interview/guide/common/aspect/RateLimitAspect.java) 中的 `@Around` 环绕通知会拦截该请求，首先通过 `method.getAnnotationsByType(RateLimit.class)` 获取该方法上所有限流规则，然后逐条遍历每条规则，为每条规则生成一个 Redis Key（格式为 `ratelimit:{ClassName:MethodName}:dimension[:具体值]`，其中 Hash Tag `{ClassName:MethodName}` 确保同一方法的所有限流 Key 落在 Redis Cluster（分布式集群） 的同一个 slot（槽位）），接着调用预加载的 Lua 脚本 `rate_limit_single.lua`（通过 Redisson 的 `evalSha` 以 SHA1 摘要方式执行，减少网络传输开销），Lua 脚本内部实现滑动时间窗口算法，传入当前时间戳、窗口大小、最大令牌数和请求唯一 ID（UUID，用于去重防止网络重试重复计数），脚本返回剩余配额：若返回值大于 0 表示通过，继续检查下一条规则；若返回 null 或 0 表示该维度配额耗尽，立即进入 `handleRateLimitExceeded` 处理流程——优先通过反射查找并调用同一 Controller 类中通过 `fallback` 属性指定的降级方法（支持无参或参数列表与原方法一致两种形式），若未配置降级方法或降级执行失败，则抛出 `RateLimitExceededException` 异常，由全局异常处理器统一返回限流提示。所有规则全部通过后才执行 `joinPoint.proceed()` 调用原 Controller 方法。此外切面还内置了 NOSCRIPT 容错机制：当 Redis 重启导致缓存的 SHA1 摘要失效时，`evalSha` 会抛出包含 "NOSCRIPT" 的 `RedisException`，切面捕获后自动调用 `scriptLoad` 重新加载脚本并重试一次。整个组件被项目中 `ResumeController`、`InterviewController`、`KnowledgeBaseController`、`InterviewSkillController`、`LlmProviderController` 等 Controller 使用，形成了一套声明式、零业务侵入的分布式限流方案。

### 二、注解属性详解

#### 1. `dimension()` — 限流维度（53-60行）

```java
Dimension dimension() default Dimension.GLOBAL;
```

三个维度：

| 维度       | Redis Key 后缀   | 说明           |
| -------- | -------------- | ------------ |
| `GLOBAL` | `:global`      | 所有请求共用一个计数器  |
| `IP`     | `:ip:{客户端IP}`  | 按客户端 IP 分别计数 |
| `USER`   | `:user:{用户ID}` | 按登录用户分别计数    |

#### 2. `count()` — 窗口内允许的最大请求数（62-68行）

```java
double count();
```

没有默认值，**必须显式指定**。使用 `double` 类型以支持如 0.5（每2秒1次）的精细控制。

#### 3. `interval()` + `timeUnit()` — 时间窗口（70-84行）

```java
long interval() default 1;
TimeUnit timeUnit() default TimeUnit.SECONDS;
```

默认组合是 **每秒 count 次**。TimeUnit 支持 `MILLISECONDS / SECONDS / MINUTES / HOURS / DAYS`。

#### 4. `timeout()` — 等待超时（86-93行）

```java
long timeout() default 0;
```

当前版本切面中**暂未使用**（切面代码中没有等待逻辑），属于预留扩展字段。

#### 5. `fallback()` — 降级方法名（95-106行）

```java
String fallback() default "";
```

触发限流时，优先调用同一类中的降级方法（支持无参或参数列表一致），未指定则抛出 `RateLimitExceededException`。

### 三、`@Repeatable` 机制（26行、115-122行）

```java
@Repeatable(RateLimit.Container.class)
```

<details>
<summary>这是 Java 8 的可重复注解特性。`Container` 是编译器自动生成的容器注解，存储同一方法上的多个 `@RateLimit` 实例。</summary>

切面中通过 `method.getAnnotationsByType(RateLimit.class)` 获取所有规则数组，逐条检查，**所有规则必须全部通过**（AND 逻辑）。

使用示例：

```java
@RateLimit(dimension = Dimension.GLOBAL, count = 10, interval = 1, timeUnit = TimeUnit.MINUTES)
@RateLimit(dimension = Dimension.IP, count = 5, interval = 1, timeUnit = TimeUnit.SECONDS)
public Result<QueryResponse> queryKnowledgeBase(...) { ... }
```

</details>

### 四、切面执行流程（联动 RateLimitAspect）

切面核心逻辑在 [RateLimitAspect.around()](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/java/interview/guide/common/aspect/RateLimitAspect.java#L101-L135)：

```
请求到达 Controller 方法
        │
        ▼
  @Around 拦截 (RateLimitAspect)
        │
        ▼
  获取所有 @RateLimit 注解 ──► 逐条遍历
        │                        │
        │                  生成 Redis Key
        │                  格式: ratelimit:{ClassName:MethodName}:dimension[:具体值]
        │                        │
        │                  执行 Lua 脚本（滑动窗口）
        │                        │
        │              ┌─ 通过 ───┤─── 不通过 ──┐
        │              │          │             │
        │              ▼          │             ▼
        │         继续下一条       │      handleRateLimitExceeded()
        │              │          │             │
        ▼              ▼          │     ┌有fallback──┴──无fallback
  所有规则通过                  │     │                   │
        │                       │  调用降级方法    抛出 RateLimitExceededException
        ▼                       │
  执行原方法 (proceed)
```

**Redis Key 设计亮点**（236行）：使用 `{ClassName:MethodName}` 作为 Hash Tag，确保同一方法的所有限流 Key 落在同一个 Redis Cluster slot，避免跨 slot 操作。

**NOSCRIPT 容错**（182-197行）：Redis 重启后脚本缓存丢失，evalsha 抛出 `NOSCRIPT` 异常时自动 `scriptLoad` 重载并重试一次。

### 五、设计优点

1. **声明式**：注解驱动，业务代码零侵入
2. **多维度组合**：通过 `@Repeatable` 实现 GLOBAL + IP + USER 自由组合
3. **降级优雅**：限流时可走降级方法返回兜底结果，而不是直接抛异常
4. **滑动窗口**：使用 Lua 脚本实现真正的滑动窗口，而非固定窗口（避免边界突发）
5. **请求去重**：每次请求生成唯一 `requestId` 传入 Lua 脚本，防止网络重试导致重复计数
