# 面试官高频追问与标准答案

## 1. 你这个 `@RateLimit` 是做什么的？

答：

> 它是一个声明式限流注解，用在 Controller 方法上，保护高成本接口。比如简历上传、知识库查询、JD 解析、Provider 连接测试这些接口都会消耗文件解析、向量化或大模型调用资源，所以通过 `@RateLimit` 声明限流规则，再由 AOP 切面和 Redis Lua 脚本统一执行。

## 2. 这个注解为什么要用 `@Retention(RUNTIME)`？

答：

> 因为限流是在运行时由 AOP 切面执行的，切面需要通过反射读取方法上的 `@RateLimit` 配置。如果注解不保留到运行时，`method.getAnnotationsByType` 就拿不到规则。

## 3. 为什么要用 `@Repeatable`？

答：

> 因为一个接口通常需要多维度限流，比如 GLOBAL 限制接口整体吞吐，IP 限制单个客户端刷接口。`@Repeatable` 允许同一个方法上写多条 `@RateLimit`，每条规则独立配置，切面逐条执行。

## 4. 多条 `@RateLimit` 是什么关系？

答：

> AND 关系。所有规则都通过才执行原方法，任意一条规则不通过就触发降级或抛限流异常。比如全局没满但某个 IP 超限，也应该拒绝。

## 5. GLOBAL、IP、USER 三种维度分别解决什么？

答：

> GLOBAL 保护接口整体资源，防止总流量过大；IP 防止单个来源恶意刷新；USER 防止单个登录用户滥用资源。当前项目主要使用 GLOBAL 和 IP，USER 维度已经支持，但生产上需要认证模块提供可信 userId。

## 6. 这个限流为什么放在 Controller 层？

答：

> 限流越靠近入口越能节省资源。像文件上传和 AI 调用，如果等到 Service 里再拦截，可能已经做了参数绑定、文件接收甚至部分解析。Controller 方法级限流可以更早拒绝请求。

## 7. AOP 是怎么拦截的？

答：

> `RateLimitAspect` 使用 `@Around` 切点匹配带 `@RateLimit` 或 `@RateLimit.Container` 的方法。进入方法前，切面读取所有限流规则，逐条执行 Redis Lua 脚本。全部通过才 `joinPoint.proceed()`，否则进入限流处理。

## 8. 为什么切点要匹配 `RateLimit.Container`？

答：

> 因为 `@RateLimit` 是可重复注解。一个方法标多个 `@RateLimit` 时，编译器底层会放进 `RateLimit.Container`。切点同时匹配单注解和容器注解，保证两种写法都能被拦截。

## 9. 为什么不用本地内存限流？

答：

> 本地内存限流只在单 JVM 有效。如果后端多实例部署，每个实例各算各的，总流量可能超过预期。Redis 是共享存储，能实现跨实例的分布式限流。

## 10. 为什么不用简单 Redis INCR + EXPIRE？

答：

> `INCR + EXPIRE` 更像固定窗口，窗口边界可能出现流量突刺。另外多条 Redis 命令不是天然原子，处理过期、判断、扣减之间可能有并发问题。Lua 脚本可以把这些步骤放在 Redis 内部原子执行，并实现滑动窗口。

## 11. 为什么选择滑动窗口？

答：

> 固定窗口在边界处可能放大流量，比如上一秒末尾 5 次，下一秒开头又 5 次，短时间内相当于 10 次。滑动窗口每次都看最近 interval 时间内的请求，更平滑，更适合保护 AI 调用这类成本型接口。

## 12. Lua 脚本的数据结构是什么？

答：

> 每条限流规则对应一个 base key，Lua 内部派生两个 key：`:value` 是 String，保存当前可用令牌数；`:permits` 是 Sorted Set，保存窗口内请求记录，score 是时间戳。每次请求先删除窗口外记录并回收令牌，再判断是否可扣减。

## 13. Redis Key 为什么要带 `{ClassName:MethodName}`？

答：

> 这是 Redis Cluster Hash Tag。Redis Cluster 会对 `{}` 里的内容计算 slot，保证同一方法派生出的 `:value` 和 `:permits` 落在同一个 slot。这样 Lua 脚本操作多个 key 时不会跨 slot。

## 14. Lua 脚本返回什么？

答：

> 当前脚本返回 `1` 表示通过，返回 `0` 表示拒绝。代码注释里有“剩余配额”的说法，但以当前实现为准，它是通过/拒绝语义。如果后续需要剩余配额，可以调整 Lua 返回 `current_val - permits`。

## 15. `requestId` 是做什么的？

答：

> 当前每次请求生成一个 UUID，Lua 用它作为 Sorted Set member 的一部分，保证记录唯一。严格来说，它现在不是完整的 HTTP 幂等去重机制，因为外部重试会生成新的 UUID。如果要做到跨重试去重，需要客户端或网关传入稳定的 requestId。

## 16. `evalSha` 有什么好处？

答：

> 启动时先把 Lua 脚本加载到 Redis，拿到 SHA1。后续执行时只传 SHA1，不用每次传完整脚本文本，减少网络传输和脚本解析开销。

## 17. Redis 报 NOSCRIPT 怎么办？

答：

> Redis 重启或脚本缓存被清掉后，`evalSha` 会报 NOSCRIPT。代码捕获这个异常后重新 `scriptLoad`，更新 SHA1，然后重试一次。这是对脚本缓存失效的容错。

## 18. Redis 连接失败怎么办？

答：

> 当前代码只对 NOSCRIPT 做了显式容错，其他 Redis 异常会向上抛出。后续可以做成配置化策略：高成本 AI 接口 fail-closed，Redis 异常时返回服务繁忙；普通读接口可以 fail-open 或本地限流兜底。

## 19. 限流触发后怎么返回给前端？

答：

> 如果没有 fallback，切面抛 `RateLimitExceededException`，它继承 `BusinessException`，错误码是 8001。全局异常处理器捕获后返回统一 `Result.error(8001, "请求过于频繁，请稍后再试")`。项目统一业务异常返回 HTTP 200。

## 20. 为什么不用 HTTP 429？

答：

> HTTP 429 在语义上更标准，但当前项目统一约定业务错误都返回 HTTP 200，通过 Result 的 code 判断。这样前端处理更统一。如果做对外开放 API，我会考虑使用真实 429，同时 body 里保留业务错误码。

## 21. fallback 降级怎么找方法？

答：

> 切面先看注解里有没有配置 fallback 方法名。如果有，就在同一个 Controller 类中先找参数列表和原方法一致的方法，找不到再找无参方法。找到后通过反射调用；找不到或执行失败，就记录日志并抛限流异常。

## 22. fallback 适合什么接口？

答：

> 适合读接口或可降级接口，比如返回缓存、默认值、友好提示。不适合上传、创建、删除、配置修改这类写接口，因为这些操作需要明确成功或失败，不能用降级结果掩盖真实状态。

## 23. `timeout` 字段有没有生效？

答：

> 当前没有生效，是预留扩展字段。现在配额不足时立即拒绝或降级，并没有等待令牌。后续如果要实现，可以在切面里做短时间重试或排队，但要控制等待时间，避免拖垮请求线程。

## 24. IP 获取会不会被伪造？

答：

> 会有这个风险。代码兼容了 `X-Forwarded-For`、`X-Real-IP` 等代理头，但这些头如果直接暴露给公网客户端，是可以伪造的。生产应该由网关或 Nginx 覆盖这些头，后端只信任网关传来的真实 IP。

## 25. USER 维度现在安全吗？

答：

> 组件层支持 USER 维度，但要安全使用，需要认证过滤器把可信 userId 放到 request attribute。单纯信任 `X-User-Id` 请求头不够安全，所以当前项目主要使用 GLOBAL 和 IP。

## 26. 当前哪些接口用了限流？

答：

> 简历上传和重新分析、面试会话创建和答案提交、知识库查询/流式查询/上传/重新向量化、JD 解析、LLM Provider 管理和测试接口都用了。它们共同特点是成本较高、可能触发 AI 调用或影响系统全局配置。

## 27. 这个模块有哪些测试？

答：

> 有注解元数据测试，验证 RUNTIME、METHOD、Repeatable、默认值和多注解读取；有异常测试，验证 8001 错误码和继承关系；还有 Redis Lua 集成测试，验证令牌耗尽、多规则独立计数等，但因为需要真实 Redis，默认 `@Disabled`。

## 28. 如果让你优化这个限流组件，你会做什么？

答：

> 我会做五点：第一，让 `timeout` 真正生效或删除避免误解；第二，把 Redis 异常策略配置化，支持 fail-open/fail-closed；第三，Lua 返回剩余配额，便于日志和响应头提示；第四，USER 维度接入认证过滤器，只信任 request attribute；第五，增加管理端动态配置阈值，而不是所有 count 都写死在注解里。

## 29. 这个模块最能体现工程能力的点是什么？

答：

> 它不是简单计数器，而是声明式、分布式、可多维组合的限流组件。注解负责表达规则，AOP 做零侵入拦截，Redis Lua 保证原子滑动窗口，Hash Tag 考虑 Redis Cluster，异常进入统一业务响应，还预留了 fallback、USER 维度和 timeout 扩展点。

## 30. 一句话收尾

答：

> `@RateLimit` 这套设计把高成本接口保护从业务代码里抽出来，变成了一个可复用的基础设施能力，让 Controller 只声明规则，限流执行、分布式一致性和异常返回都由公共组件统一处理。
