# 企业级限流降级方法设计方案

## 一、面试回答框架

你可以按这个思路回答：「**当前项目采用同方法反射降级 → 扩展到多层级降级方案 → 引入业界成熟方案（Sentinel / Resilience4j）**」，体现由浅入深的思考。

---

## 二、当前项目采用的方案：同方法反射降级

这是最轻量的实现，作为切入点：

```java
@RateLimit(count = 10, fallback = "handleBusy")
public Result<List<Data>> query(String keyword) {
    // 正常业务逻辑
}

// 降级方法，返回兜底数据
public Result<List<Data>> handleBusy(String keyword) {
    return Result.error(429, "系统繁忙，请稍后再试");
}
```

**优点**：零依赖、实现简单。
**局限**：降级方法只能在同一类中、缺少熔断和统计能力。

**面试时要主动指出局限** → 然后引出更成熟的方案，这说明你有思考。

## 三、方案一：静态兜底数据降级

最实用、面试官最常问的场景。

```java
@RateLimit(count = 100, fallback = "getCachedList")
public Result<List<HotItemDTO>> getHotItems() {
    // 从数据库/ES实时查询
    return Result.success(itemService.queryRealtime());
}

public Result<List<HotItemDTO>> getCachedList() {
    // 不报错，返回缓存中的热门数据
    List<HotItemDTO> cached = cacheManager.get("home:hot_items");
    if (CollectionUtils.isEmpty(cached)) {
        // 连缓存都没有，返回预置的静态兜底数据
        return Result.success(buildDefaultHotItems());
    }
    return Result.success(cached);
}
```

**关键点**：即使是限流状态，用户仍然能得到**有价值的内容**，而不是错误提示。面试时强调「**宁可返回旧数据，也不返回错误页**」。

## 四、方案二：多级缓存穿透降级

这是企业级最经典的架构：

```
┌─ 用户请求 ─┐
     ↓
Nginx（本地缓存 1ms）
     ↓ 命中率 95%
Redis（分布式缓存 5ms）
     ↓ 命中率 99%
数据库（持久层 50ms）
     ↓ 触发限流
兜底数据（静态 JSON / CDN 边缘数据）
```

对应 Java 侧实现：

```java
@RateLimit(count = 500, fallback = "getWithMultiLevelFallback")
public Result<ProductDetailDTO> getProductDetail(Long productId) {
    // 1. Redis 缓存
    ProductDetailDTO cached = redisService.get("product:" + productId);
    if (cached != null) {
        return Result.success(cached);
    }
    // 2. 数据库查询
    ProductDetailDTO detail = productRepo.findById(productId);
    redisService.set("product:" + productId, detail, 5, TimeUnit.MINUTES);
    return Result.success(detail);
}

public Result<ProductDetailDTO> getWithMultiLevelFallback(Long productId) {
    // 降级链路：Redis → 本地缓存 → CDN边缘数据 → 占位数据
    ProductDetailDTO cached = cacheManager.get("product_fallback:" + productId);
    if (cached != null) {
        return Result.success(cached).withHint("数据来自缓存");
    }
    // 最终兜底
    ProductDetailDTO stub = new ProductDetailDTO();
    stub.setName("商品信息加载中...");
    stub.setPlaceholder(true);
    return Result.success(stub).withHint("数据更新中，请稍后刷新");
}
```

## 五、方案三：服务分级降级（重点）

企业级系统通常把服务分为核心/非核心，这是面试官最想听到的：

```java
public enum ServiceGrade {
    CORE,       // 核心服务：支付、登录，绝不降级
    IMPORTANT,  // 重要服务：商品详情，允许返回缓存
    NORMAL,     // 一般服务：推荐列表，允许返回空列表
    WEAK        // 弱依赖：广告、日志，可直接跳过
}
```

```java
@RateLimit(count = 50, fallback = "recommendFallback")
public Result<List<RecommendDTO>> getRecommend(Long userId) {
    // NORMAL 级别服务，推荐引擎慢可以直接跳过
    return Result.success(recommendEngine.recommend(userId));
}

public Result<List<RecommendDTO>> recommendFallback(Long userId) {
    // 返回热门列表作为降级，而不是报错
    return Result.success(getHotItemsFromCache());
}
```

**话术**：「对于 WEAK 级别的服务，限流触发时直接返回空结果；对于 IMPORTANT 级别的服务，返回最近一分钟的缓存快照；对于 CORE 级别的服务，预留额外资源确保可用。」

## 六、方案四：Sentinel / Resilience4j 工业级方案

面试时要主动提到业界标准方案，体现广度：

| 框架 | 特点 | 适用场景 |
|------|------|----------|
| **Sentinel** | 阿里开源，QPS/线程数/RT 多维流控，控制台可视化管理 | 分布式、服务网格 |
| **Resilience4j** | 轻量级，Java 函数式风格，无需线程池隔离 | Spring 项目首选 |
| **Hystrix** | Netflix 出品（已停更），线程池隔离经典方案 | 遗留系统维护 |

### Resilience4j 示例：

```java
@RateLimiter(name = "queryApi", fallbackMethod = "queryFallback")
public Result<List<Data>> query(String keyword) {
    return Result.success(dataService.search(keyword));
}

// Fallback方法签名必须与原方法一致，并加上异常参数
public Result<List<Data>> queryFallback(String keyword, 
                                         RequestNotPermitted ex) {
    log.warn("限流触发，使用降级方法: keyword={}", keyword);
    return Result.success(cacheService.getOrDefault(keyword));
}
```

### Sentinel 示例：

```java
@SentinelResource(value = "queryApi", 
    blockHandler = "handleBlock", 
    fallback = "handleFallback")
public Result<List<Data>> query(String keyword) {
    return Result.success(dataService.search(keyword));
}

// 限流/降级触发的处理
public Result<List<Data>> handleBlock(String keyword, BlockException ex) {
    return Result.error(429, "服务繁忙，请稍候");
}

// 业务异常的处理
public Result<List<Data>> handleFallback(String keyword, Throwable ex) {
    log.error("查询失败: keyword={}", keyword, ex);
    return Result.error(500, "服务内部错误");
}
```

## 七、面试总结话术模板

可以把以上内容组织成这样的回答：

> 「降级方法的设计要分场景看，从简单到复杂有四个层次：
>
> **第一层**是我们在项目中实现的反射调用降级，在同一个 Controller 里定义降级方法，优点是零依赖、快上手。
>
> **第二层**是静态兜底+多级缓存，不会把错误页面给用户，而是返回 Redis 缓存、本地缓存甚至预置的静态数据。核心原则是**宁可返回旧数据，也不返回错误**。
>
> **第三层**是服务分级降级，把接口分为核心/重要/一般/弱依赖四个等级，核心服务不降级，弱依赖直接跳过，这需要从架构层面梳理服务依赖关系。
>
> **第四层**是引入 Sentinel 或 Resilience4j 这类工业级框架，它们提供了熔断、限流、降级的一体化解决方案，还有可视化的监控面板，适合大型分布式系统。
>
> 选择哪一层取决于业务规模：QPS < 1000 用反射降级就够了，QPS 到万级就需要多级缓存，QPS 到十万级就必须上 Sentinel 这样的工业方案。」
