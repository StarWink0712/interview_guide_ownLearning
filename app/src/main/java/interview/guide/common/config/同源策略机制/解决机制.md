# CorsConfig 详细分析

***

## 一、作用一句话概括

**让前端（React/Vite 开发服务器，localhost:5173）能够跨域调用后端 API（localhost:8080），浏览器不会因为同源策略拦截请求。**

***

## 二、为什么需要它

浏览器有个安全机制叫**同源策略**：`http://localhost:5173`（前端页面）不能直接请求 `http://localhost:8080/api/...`（后端接口），因为**协议+域名+端口**三者必须完全一致才算"同源"。

```
前端: http://localhost:5173
后端: http://localhost:8080    ← 端口不同 → 跨域，浏览器拦截
```

CORS（Cross-Origin Resource Sharing）是一种标准机制，让后端通过响应头告诉浏览器："我允许 `http://localhost:5173` 跨域访问我"。

***

## 三、配置属性来源

[CorsProperties.java](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/java/interview/guide/common/config/CorsProperties.java)：

```java
@ConfigurationProperties(prefix = "app.cors")
public class CorsProperties {
    // 默认值 http://localhost:5173（Vite 开发服务器）
    private String allowedOrigins = "http://localhost:5173";
}
```

[application.yml#L192-L193](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/resources/application.yml#L192-L193)：

```yaml
app:
  cors:
    allowed-origins: ${CORS_ALLOWED_ORIGINS:http://localhost:5173,http://localhost:5174,http://localhost:80}
```

- 优先读取环境变量 `CORS_ALLOWED_ORIGINS`
- 没有则默认三个地址：`localhost:5173`（Vite 开发）、`localhost:5174`（备用 Vite）、`localhost:80`（Nginx 代理）

## 四、`corsFilter()` 方法逐行解析

### 4.1 允许的来源

```java
String allowedOrigins = corsProperties.getAllowedOrigins();
// → "http://localhost:5173,http://localhost:5174,http://localhost:80"

Arrays.stream(allowedOrigins.split(","))
      .map(String::trim)
      .forEach(config::addAllowedOrigin);
// → 逐个添加到 CORS 白名单
```

**效果**：后端响应头会带上：

```
Access-Control-Allow-Origin: http://localhost:5173
```

只有白名单里的来源，浏览器才会放行。

### 4.2 允许的 HTTP 方法

```java
config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE", "PATCH", "OPTIONS"));
```

**`OPTIONS`** **为什么重要？** 浏览器在发"复杂请求"（如带 `Content-Type: application/json` 的 POST）之前，会先发一个 `OPTIONS` 预检请求问："我能发 POST 吗？"。如果不允许 OPTIONS，连预检都通不过，真正的 POST 请求根本发不出去。

```
浏览器                                        后端
  │                                            │
  ├── OPTIONS /api/resume/upload ──────────────→│ 预检请求
  │   (问：能用 POST 吗？能带 Authorization 吗？)  │
  │                                            │
  │←──── 200 OK ──────────────────────────────┤ 允许
  │   Access-Control-Allow-Methods: POST        │
  │   Access-Control-Allow-Headers: *           │
  │   Access-Control-Max-Age: 3600              │
  │                                            │
  ├── POST /api/resume/upload ────────────────→│ 真正的请求
  │   Content-Type: multipart/form-data         │
  │   Authorization: Bearer xxx                 │
```

### 4.3 允许的请求头

```java
config.setAllowedHeaders(List.of("*"));
```

允许前端带任何请求头，比如 `Authorization`（JWT Token）、`Content-Type`、`X-Requested-With` 等。

**安全提示**：`*` 在生产环境偏宽松。如果项目只有特定 Header 需求，可以收敛为 `List.of("Authorization", "Content-Type")`。

### 4.4 允许携带凭证

```java
config.setAllowCredentials(true);
```

这是**最关键的一行**。设置为 `true` 后：

- 前端 `fetch` 或 `axios` 可以带上 `credentials: 'include'`
- Cookie、`Authorization` Header 能正常传递
- 后端登录态鉴权才能正常工作

**注意**：`allowCredentials=true` 时，`allowedOrigins` 不能是 `*`（通配符），必须指定具体域名。Spring 的这个配置是符合规范的。

### 4.5 预检请求缓存

```java
config.setMaxAge(3600L);
```

预检请求的结果在浏览器端缓存 3600 秒（1 小时）。意思是：

```
第一次 POST /api/resume/upload → 先发 OPTIONS 预检 → 浏览器缓存结果
之后 1 小时内再次 POST 同一路径 → 直接发请求，跳过 OPTIONS
```

减少了一次网络往返，提升体验。

### 4.6 路径作用域

```java
UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
source.registerCorsConfiguration("/api/**", config);
```

**仅对** **`/api/**`** **路径生效**，静态资源（`/static/**`）、健康检查（`/actuator/health`）等不受影响。

***

## 五、`@Configuration` 的作用

```java
@Configuration    // ← 声明这是一个 Spring 配置类
public class CorsConfig {

    @Bean        // ← 方法返回值注入 Spring 容器
    public CorsFilter corsFilter() { ... }
}
```

`CorsFilter` 是 Spring 提供的标准 Servlet Filter，注册后会被 Spring Boot 自动装配到 Filter Chain 中，**在请求到达 Controller 之前**就完成 CORS 响应头的设置。

## 六、面试话术

> 「这是一个标准的 Spring Boot CORS 配置。前端是 React + Vite 开发服务器跑在 `localhost:5173`，后端是 `localhost:8080`，不同端口就是跨域，浏览器的同源策略会拦截。
>
> 我们通过 `CorsFilter` Bean 配置了 `/api/**` 路径的跨域规则：允许的来源从 `application.yml` 读取（支持环境变量覆盖），允许所有标准 HTTP 方法和请求头，开启了凭证传递（`allowCredentials=true`），预检请求缓存 1 小时。配置属性通过 `@ConfigurationProperties` 绑定到 `CorsProperties` 类，默认值是 `localhost:5173`。
>
> 特别需要注意两个点：一是 `OPTIONS` 方法必须允许，否则浏览器的预检请求就通不过；二是 `allowCredentials=true` 时 `allowedOrigins` 不能是通配符 `*`，必须指定具体域名，Spring 这里处理得符合规范。」
