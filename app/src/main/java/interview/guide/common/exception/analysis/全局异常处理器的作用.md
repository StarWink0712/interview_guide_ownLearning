## GlobalExceptionHandler 详细笔记

### 一、核心注解

```java
@RestControllerAdvice
public class GlobalExceptionHandler { ... }
```

`@RestControllerAdvice` 是 `@ControllerAdvice` + `@ResponseBody` 的组合，表示：
- **全局拦截**：整个应用所有 Controller 抛出的异常都会经过这里
- **自动转 JSON**：每个方法的返回值自动序列化为 JSON

---

### 二、核心设计决策：HTTP 200 + 业务错误码

```java
@ResponseStatus(HttpStatus.OK)  // 所有方法统一返回 HTTP 200
```

| 为什么这么做 | 说明 |
|------------|------|
| 前端统一处理 | 前端只看 `code` 字段，0=成功，非0=失败，不用考虑 HTTP 状态码 |
| 网关兼容 | 部分网关/负载均衡器对 400/500 有特殊处理（重试、熔断），200 避免干扰 |
| 调试友好 | 浏览器 DevTools 中所有响应都是 200，可直接查看完整 JSON |

失败时的响应格式始终是：
```json
{
    "code": 2001,
    "message": "简历不存在",
    "data": null
}
```

### 三、处理 8 种异常的完整表格

| 异常类型 | 日志级别 | 前端收到 code | 前端收到 message | 触发场景 |
|---------|:-------:|:-----------:|:--------------:|---------|
| **BusinessException** | `warn` | ErrorCode 中的业务码 | ErrorCode 的默认消息或自定义消息 | 简历不存在、面试过期等业务错误 |
| **MethodArgumentNotValidException** | `warn` | 400 | 所有校验失败的提示拼接 | `@Valid` 参数校验失败 |
| **BindException** | `warn` | 400 | 所有绑定失败的提示拼接 | 请求参数绑定到对象失败 |
| **MaxUploadSizeExceededException** | `warn` | 400 | "文件大小超过限制" | 上传文件超过 `spring.servlet.multipart.max-file-size` |
| **IllegalArgumentException** | `warn` | 400 | 异常自身的 message | Service 层参数校验直接抛该异常 |
| **ResourceAccessException** | `error` | 7001/7002 | "连接失败"/"超时" | AI 服务 SSL 握手失败、Socket 超时 |
| **RestClientException** | `error` | 7004/7005 | "密钥无效"/"频率超限" | AI 服务返回 401(密钥无效) 或 429(被限流) |
| **NoResourceFoundException** | `warn` | 404 | "API 接口不存在" | 请求了不存在的 URL |
| **HttpRequestMethodNotSupportedException** | `warn` | 405 | "请求方法不支持: GET" | GET 访问了只允许 POST 的接口 |
| **Exception（兜底）** | **`error`** | 500 | "系统繁忙，请稍后重试" | NPE、数组越界等未知异常 |

### 四、异常分类详解

#### 类型 1：BusinessException（业务异常）

```java
@ExceptionHandler(BusinessException.class)
@ResponseStatus(HttpStatus.OK)
public Result<Void> handleBusinessException(BusinessException e) {
    log.warn("业务异常: code={}, message={}", e.getCode(), e.getMessage());
    return Result.error(e.getCode(), e.getMessage());
}
```

- **使用 `warn` 级别**：因为业务异常是预期中的正常错误，不是系统故障
- **code 和 message 都来自 ErrorCode 枚举**：前端通过 code 做国际化或逻辑判断
- **触发场景**：简历不存在(2001)、面试已过期(3002)、AI 超时(7002)等

#### 类型 2：参数校验异常（MethodArgumentNotValidException / BindException）

```java
@ExceptionHandler(MethodArgumentNotValidException.class)
public Result<Void> handleValidationException(MethodArgumentNotValidException e) {
    String message = e.getBindingResult().getFieldErrors().stream()
            .map(FieldError::getDefaultMessage)
            .collect(Collectors.joining(", "));
    log.warn("参数校验失败: {}", message);
    return Result.error(ErrorCode.BAD_REQUEST, message);
}
```

**逻辑**：
1. 从 `e.getBindingResult().getFieldErrors()` 获取所有校验失败的字段
2. 提取每个字段的 `@NotBlank(message="名称不能为空")` 中定义的 message
3. 用逗号拼接后返回给前端

**触发场景**：
```java
public record CreateInterviewRequest(
    @NotBlank(message = "面试标题不能为空") String title,
    @NotNull(message = "技能不能为空") String skillId
) {}
// 前端同时缺两个字段 → 收到 "面试标题不能为空, 技能不能为空"
```

#### 类型 3：AI 服务异常（ResourceAccessException / RestClientException）

**这两个处理 AI 调用中最常见的两类问题**：

```java
// 网络层问题（SSL握手失败、TCP连接超时等）
@ExceptionHandler(ResourceAccessException.class)
public Result<Void> handleResourceAccessException(ResourceAccessException e) {
    log.error("AI服务连接失败: {}", e.getMessage(), e);  // 用 error 级别
    Throwable cause = e.getCause();
    if (cause instanceof SocketTimeoutException) {
        return Result.error(ErrorCode.AI_SERVICE_TIMEOUT, "AI服务响应超时，请稍后重试");
    }
    return Result.error(ErrorCode.AI_SERVICE_UNAVAILABLE, "AI服务暂时不可用，请稍后重试");
}

// 业务层问题（API密钥无效、调用频率超限）
@ExceptionHandler(RestClientException.class)
public Result<Void> handleRestClientException(RestClientException e) {
    log.error("AI服务调用失败: {}", e.getMessage(), e);
    if (message.contains("401")) {
        return Result.error(AI_API_KEY_INVALID, "AI服务密钥无效");
    }
    if (message.contains("429")) {
        return Result.error(AI_RATE_LIMIT_EXCEEDED, "AI服务调用过于频繁");
    }
    return Result.error(AI_SERVICE_ERROR, "AI服务调用失败");
}
```

**关键点**：
- 两个方法都使用 `log.error` + 传入异常 `e`（输出完整堆栈），因为 AI 服务异常是需要运维介入的严重问题
- `ResourceAccessException` 还拆解了 SocketTimeoutException 和 SSL 握手失败，分别给出不同的前端提示文案

#### 类型 4：兜底异常（Exception.class）

```java
@ExceptionHandler(Exception.class)
public Result<Void> handleException(Exception e) {
    log.error("系统异常: {}", e.getMessage(), e);  // 记录完整堆栈
    return Result.error(ErrorCode.INTERNAL_ERROR, "系统繁忙，请稍后重试");
}
```

- **必须放在最后**：`Exception.class` 匹配所有异常，如果放在前面会覆盖更具体的处理方法
- **绝不返回原始异常信息**：防止泄漏内部实现细节（如包名、数据库表名等）
- **日志记录异常本身**：`log.error(msg, e)` 输出完整堆栈，方便开发排障

### 五、处理优先级规则

Spring 的 `@ExceptionHandler` 按**具体优先**匹配：

```
Controller 抛出异常
    ↓
Spring 查找匹配的 @ExceptionHandler 方法
    ↓
BusinessException（最具体）→ 匹配 BusinessException 处理器
NPE（没有专门处理器）    → 匹配 Exception 兜底处理器
```
