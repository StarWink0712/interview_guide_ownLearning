# 守护线程 vs 用户线程：实际影响对比

## 先看正常关闭流程（两种线程都 OK）

```
Spring Boot 收到关闭信号（Ctrl+C / SIGTERM）
        ↓
@PreDestroy 被调用 → shutdown()
        ↓
running.set(false)    ← 通知消费者线程退出循环
executorService.shutdown()
        ↓
消费者线程 while(running.get()) 返回 false → 退出 → 线程结束
        ↓
JVM 正常退出
```

在正常流程下，守护线程和用户线程**没有区别**，都是优雅关闭。

***

## 关键区别：异常关闭场景 核心 为什么用守护线程

问题出在**非正常关闭**时，比如：

| 场景                   | 守护线程       | 用户线程                     |
| -------------------- | ---------- | ------------------------ |
| `@PreDestroy` 正常执行   | ✅ 优雅退出     | ✅ 优雅退出                   |
| `@PreDestroy` 抛异常被吞掉 | ✅ JVM 仍可退出 | ❌ JVM **永远卡住**，需 kill -9 |
| Spring 上下文关闭失败       | ✅ JVM 仍可退出 | ❌ JVM **永远卡住**           |
| kill -15 后某线程卡死      | ✅ 其他线程可退出  | ❌ JVM **永远卡住**           |

***

## 用户线程的风险演示

假设把 `setDaemon(true)` 改成 `setDaemon(false)`，然后模拟 `@PreDestroy` 失效：

```java
// 假设 shutdown() 因为某种原因没被调用
// 或者 shutdown() 里抛了异常被外层吞掉

// 用户线程版本：
executorService.submit(() -> {
    while (true) {           // ← 没有 running 标志控制
        consumeMessage();    // 死循环，永不退出
    }
});

// Spring 尝试关闭...
System.out.println("Spring 关闭中...");
// ↑ 打印完这行后，JVM 就卡住了，因为用户线程还在跑
// 进程永远不会退出，运维脚本超时后只能 kill -9
```

**后果**：

- CI/CD 部署脚本超时失败
- Docker 容器无法正常停止（需要 `docker kill`）
- Kubernetes Pod 卡在 Terminating 状态

## 这个项目的保护机制

看 [shutdown()](file:///Users/ogawaaya/Desktop/学习/interview_guide/interview-guide-optimize/app/src/main/java/interview/guide/common/async/AbstractStreamConsumer.java#L101-L107) 和消费循环：

```java
// 第一层保护：运行标志
while (running.get()) {   // ← 优雅退出路径
    consumeMessages();
}

// 第二层保护：守护线程
t.setDaemon(true);        // ← 暴力退出路径（兜底）
```

两层保护的关系：

```
正常路径：
    running.set(false) → 循环退出 → 线程自然结束 → ✅
    
异常路径（@PreDestroy 失效）：
    running 没被设为 false → 循环不退出 → 
    main 线程结束 → JVM 退出 → 守护线程自动死亡 → ✅（至少进程不卡死）
```

***

## 为什么不怕数据丢失？

回到你的项目，守护线程被暴力杀死时，正在处理的消息不会丢失：

```
消费者拉取消息 → 处理中 → 

此时 JVM 退出（守护线程被杀）
        ↓
消息没有 ACK（确认）
        ↓
消息保留在 Redis Stream 的 PEL（Pending Entries List）
        ↓
下次启动时 recoverPendingMessages() 重新认领
        ↓
消息不丢，只是延迟处理
```

***

## 一句话总结

> **守护线程不是用来正常关的，是用来兜底的。正常关闭走** **`running.set(false)`** **优雅退出；万一优雅路径失效，守护线程让 JVM 至少能死掉，而不是卡在那里变成僵尸进程。用用户线程的话，一旦正常关闭路径出问题，整个进程就永远卡住了。**

面试时如果被问到这个，核心就一句话：**这是 defense-in-depth（纵深防御），正常路径靠 running 标志和 @PreDestroy 优雅关闭，异常路径靠守护线程兜底，防止 JVM 僵死。**
