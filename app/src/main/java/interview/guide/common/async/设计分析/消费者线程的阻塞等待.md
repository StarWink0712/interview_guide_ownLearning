项目启动后，Spring 容器完成依赖注入，`@PostConstruct init()` 自动触发，消费者的守护线程**立刻创建并开始从 Stream 拉消息**，不需要任何外部触发。

## 启动到消费的完整时间线

```
Spring 容器启动
    │
    ├── Bean 实例化：new AnalyzeStreamConsumer(redisService, gradingService, ...)
    │
    ├── 依赖注入完成
    │
    ▼
@PostConstruct init()   ← 自动触发
    │
    ├── ① consumerName = "analyze-consumer-a3f2b01c"
    ├── ② 创建单线程守护线程池
    └── ③ executorService.submit(this::startConsumer)
            │
            ▼
       [守护线程开始运行]
            │
       startConsumer()
            ├── createStreamGroup("resume:analyze:stream", "analyze-group")
            └── consumeLoop()
                    │
                    ▼
                while(running) {
                    streamConsumeMessages(...)
                    // → XREADGROUP GROUP analyze-group ... BLOCK 1000
                    // → 此时 Stream 里还没有消息 → 阻塞等待 1 秒超时
                    // → 超时返回空 → 循环继续，再次 XREADGROUP 阻塞等待
                    // → 直到有消息进来 → 立即拉取处理
                }
```

---

## 关键点

**消费者不会因为 Stream 为空就退出。** 它一直处于"阻塞等待 → 超时 → 重新阻塞等待"的循环中，直到有消息进来立刻处理。

类比理解：

> 外卖小哥到了餐厅，后厨还没做好。他就在取餐口等着（阻塞 1 秒），1 秒后看一眼还没有，再等 1 秒。一旦看到属于自己的那份好了，立刻拿走配送。

这和之前生产者讲的 `XADD` 完美衔接：

```
Producer: XADD resume:analyze:stream * taskId 789 resumeId 456 retryCount 0
           ↑ 消息此时进入 Stream

Consumer: XREADGROUP ... BLOCK 1000
           ↑ 正在阻塞等待
           ↓ 消息进来了 → 立即返回 → processMessage() 处理
```
