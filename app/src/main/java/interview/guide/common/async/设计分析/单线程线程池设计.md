## ThreadPoolExecutor 参数逐项分析

这是一个**单线程线程池**，用于 Redis Stream 消费者循环。各参数含义：

```java
new ThreadPoolExecutor(
    1,                          // corePoolSize：核心线程数
    1,                          // maximumPoolSize：最大线程数
    0L,                         // keepAliveTime：空闲线程存活时间
    TimeUnit.MILLISECONDS,      // keepAliveTime 的单位
    new LinkedBlockingQueue<>(), // 工作队列
    r -> {                      // 线程工厂
        Thread t = new Thread(r, threadName());
        t.setDaemon(true);
        return t;
    },
    new ThreadPoolExecutor.AbortPolicy()  // 拒绝策略
);
```

---

### 1. `corePoolSize = 1` — 核心线程数

线程池保持的最小线程数。即使没有任务，这个线程也一直存活。

### 2. `maximumPoolSize = 1` — 最大线程数

线程池允许的最大线程数。这里和核心线程数相等，意味着**线程池永远只有 1 个线程**，不会扩容。

### 3. `keepAliveTime = 0L` + `TimeUnit.MILLISECONDS`

当线程数超过核心线程数时，多余的线程空闲多久后被销毁。由于 `corePoolSize == maximumPoolSize == 1`，**永远不会有多余线程**，这个参数实际上无效，写 `0` 是占位。

### 4. `new LinkedBlockingQueue<>()` — 工作队列

无界队列（默认容量 `Integer.MAX_VALUE`）。当唯一的工作线程忙碌时，新任务进入此队列排队等待。由于消费者只提交了一个任务（`executorService.submit(this::startConsumer)`），队列不会被填满，无界是安全的。

### 5. 线程工厂 `r -> { ... }`

```java
r -> {
    Thread t = new Thread(r, threadName());  // 自定义线程名，如 "vectorize-worker"
    t.setDaemon(true);                       // 设为守护线程
    return t;
}
```

- `threadName()` 是子类实现的抽象方法，比如返回 `"vectorize-consumer-xxx"`
- `setDaemon(true)` 表示这是**守护线程**——JVM 退出时不会等待守护线程结束，直接关闭。合理，因为应用关闭时 `@PreDestroy` 会主动停消费者，不需要 JVM 等它

### 6. `AbortPolicy()` — 拒绝策略

当队列满且线程数达到最大时，如何处理新任务。`AbortPolicy` 直接抛 `RejectedExecutionException`。由于是无界队列 + 只提交一个任务，实际上不会触发，属于安全兜底。

---

### 为什么设计成单线程

注释里写了原因（第 77 行）：「确保消息顺序处理」。Redis Stream 中的消息需要顺序消费（同一任务不能并发执行），单线程保证了 `consumeLoop` 里的 `processMessage` 严格串行。四个子类（向量化、简历分析、面试评估、语音评估）各自有一个独立的单线程消费者实例。
