# 安全、异常与配置治理

## 1. 面试官：项目是否已经实现登录、权限和多租户隔离？

我的回答：

我的项目当前没有完整实现这一部分。`app/build.gradle` 没有 Spring Security 依赖，也没有 SecurityFilterChain、JWT 校验或方法级授权；部分实体虽然有 userId，语音服务还会使用默认用户，限流的 USER 维度可直接读取 `X-User-Id`，这些都不能等同于可信身份。管理控制台、Provider 配置、任务重试、文档和 WebSocket 会话目前缺少真正的所有权校验。上线前我会先引入 OIDC/JWT，从 Principal 取得 userId，把租户条件下沉到 Repository，并对管理员接口做 RBAC；WebSocket 则使用短期签名票据验证 session 归属。

## 2. 面试官：为什么业务错误仍返回 HTTP 200，这种设计有什么利弊？

我的回答：

我的项目用 `Result<T>` 统一承载 code、message、data，`GlobalExceptionHandler` 把 `BusinessException`、参数校验、限流和未知异常转换为该结构，约定业务错误也返回 HTTP 200；前端 Axios 拦截器再依据 `result.code === 200` 判断成功。优点是早期前后端处理一致，业务错误码可按模块分域；缺点是代理、浏览器、APM 和告警只看 HTTP 状态时会把失败当成功，缓存策略也可能错误。若面向正式开放 API，我会保留业务 code，同时让 HTTP 状态表达协议语义，例如校验 400、未授权 401、限流 429、服务异常 500。

代码依据：

- `app/src/main/java/interview/guide/common/result/Result.java`
- `app/src/main/java/interview/guide/common/exception/GlobalExceptionHandler.java`
- `app/src/main/java/interview/guide/common/exception/ErrorCode.java`
- `frontend/src/api/request.ts`

## 3. 面试官：项目如何统一业务异常，哪些降级方式可能掩盖故障？

我的回答：

我的项目要求 Service 抛 `BusinessException(ErrorCode, message)`，全局处理器统一映射，限流又有专用 `RateLimitExceededException`；捕获业务异常时应原样抛出，未知异常记录完整堆栈后转换，避免 Controller 各自拼错误响应。另一方面，部分 AI 场景有可用性降级：出题回退本地题、RAG 改写失败用原问题，这是合理的；但简历评分把异常包装成零分结果、TTS 返回空字节、语音 LLM 返回错误文本，可能让监控和任务状态误判成功。我的原则是区分“业务可接受降级”和“基础设施失败”，后者必须保留失败状态与错误分类。

## 4. 面试官：CORS、限流和输入清洗能否替代身份认证？

我的回答：

不能。我的项目的 CORS 只允许配置的前端 Origin，并允许 credentials；它约束的是浏览器跨域行为，非浏览器客户端仍可直接调用。`@RateLimit` 控制调用频率，PromptSanitizer 和文件校验减少恶意输入，但都不能证明调用者是谁、是否有权读取某份简历或修改 Provider。当前组合适合开发演示的风险降低，不是访问控制。生产上我会在认证后再做用户/租户限流，CORS 只开放真实域名，敏感接口增加 RBAC 和审计；同时在可信反向代理处重写转发头，避免伪造 IP 和用户标识。

## 5. 面试官：敏感配置和用户材料在项目中有哪些保护与风险？

我的回答：

我的项目把数据库、S3、邮件和 AI 密钥放在环境变量或用户目录运行时配置，实际密钥文件不应提交，仓库只提供 `.env.example`；Provider API Key 可 AES-GCM 加密并在接口响应中掩码。上传材料由对象存储保存，数据库主要保存文本和元数据，观测链路有 traceId，并尽量用哈希、长度或截断预览而非完整 Prompt。风险是 Compose 和 application 默认存在开发凭据，MinIO 初始化还把 bucket 设为公共读，API Key 强制加密默认关闭，也没有用户权限与数据保留策略。生产必须改私有 bucket、临时签名下载、密钥托管、日志脱敏和数据删除审计。

# 本章总结

项目已经有统一异常、错误码、限流、CORS、文件与 Prompt 防护、API Key 加密基础，但它们解决的是输入和运行风险，不是身份与数据授权。

最需要诚实说明的是认证、RBAC、多租户隔离尚未落地，开发默认凭据与公共 bucket 也不能直接用于生产。

# 核心主线

现有防护是安全基线，真正上线必须以可信身份和资源所有权校验补齐访问控制闭环。
