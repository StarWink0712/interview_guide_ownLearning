# 通用文件处理链路

## 1. 为什么要把文件处理能力抽成独立模块？

**回答：** 简历上传和知识库上传都需要文件大小校验、真实 MIME 类型检测、SHA-256 去重、Apache Tika 文本解析、文本清洗和 RustFS 对象存储。如果分别在业务模块中实现，会产生大量重复代码。因此项目把这些能力抽到通用文件处理模块；简历的 LLM 分析和知识库的向量化仍由各自业务模块负责，不属于文件基础设施的职责。

为什么抽象出来很简单，因为有多个不同的业务都需要做文件处理，比如简历处理，知识库文档处理等，抽取出来做成公共模块可以让代码解耦，提高代码复用程度，也方便管理和维护。

## 2. 一份新文件进入系统后的通用处理顺序是什么？

**回答：** 业务模块先调用 `FileValidationService` 校验空文件和大小，再通过 `ContentTypeDetectionService` 检测真实 MIME 类型，然后使用 `FileHashService` 计算 SHA-256 内容指纹并查重。新文件交给 `DocumentParseService` 使用 Tika 提取文本，经过 `TextCleaningService` 清洗后，再由 `FileStorageService` 上传原文件到 RustFS，最后由业务模块保存文件元数据和解析文本，并触发后续异步任务。

## 3. 简历文件和知识库文件如何复用这套能力？

**回答：** `ResumeUploadService` 通过 `ResumeParseService` 调用文件类型检测和文档解析服务，知识库上传服务也调用相同的基础设施。两者共享校验、MIME 检测、哈希、Tika、文本清洗和 RustFS 客户端；区别在后续业务：简历触发 LLM 评分，知识库触发文本分块和向量化。

## 4. 简历上传时的文件大小限制是多少？

**回答：** `FileValidationService` 先判断文件是否为空，再检查大小是否超过 10MB。当前 `MultipartFile` 哈希实现会通过 `file.getBytes()` 把文件整体读入内存，但简历上限控制在 10MB，因此内存风险暂时处于可控范围。

## 5. 简历上传的完整文件处理流程是什么？

**回答：** 用户上传简历后，系统先校验文件和真实 MIME 类型，再计算 SHA-256 查询是否已有相同文件；重复时直接返回历史分析结果。新文件通过 `DocumentParseService` 提取并清洗正文，原始文件上传到 RustFS，取得 `fileKey` 和 `fileUrl`；随后把哈希、原文件名、大小、MIME、存储键、URL 和 `resumeText` 保存到 PostgreSQL，并将 `analyzeStatus` 初始化为 `PENDING`，最后通过 Redis Stream 异步触发 LLM 分析。

## 6. 原始文件和解析文本为什么分别保存？

**回答：** RustFS 保存 PDF 或 Word 等原始二进制，便于下载、重新解析和多实例共享；PostgreSQL 保存文件元数据以及 Tika 提取的 `resumeText`，供消费者和业务查询直接使用。对象存储适合大文件，关系数据库适合结构化元数据和业务关联，两者职责不同。

## 7. 简历数据和分析记录为什么拆成两张表？

**回答：** `resumes` 表保存一份简历的基础信息和解析结果，例如主键、文件名、大小、MIME、哈希、RustFS 键与 URL、`resumeText` 和分析状态；`resume_analyses` 表通过 `resume_id` 外键保存评分结果。因为同一份简历可能被多次分析，所以基础文件与历史分析记录是一对多关系，拆表更符合数据模型。

## 8. 文件保存完成后，简历分析如何继续执行？

**回答：** `AnalyzeStreamProducer` 将任务写入 Redis Stream `resume:analyze:stream`，接口先向前端返回 PENDING。`AnalyzeStreamConsumer` 异步读取简历文本，调用 `ResumeGradingService` 和 LLM 生成五维评分、总结、优势与改进建议；结构化 JSON 通过 `StructuredOutputInvoker` 做最多 3 次重试和修复，最终保存到 `ResumeAnalysisEntity`，并把状态更新为 COMPLETED。

## 9. 简历评分的五个维度分别是什么？

**回答：** LLM 返回的结构化结果包括项目经验 40 分、技能匹配度 20 分、内容完整性 15 分、结构清晰度 15 分和表达专业性 10 分，同时还包含综合总结、优势列表和改进建议。系统 Prompt 和用户 Prompt 从 `resources/prompts/` 下的 StringTemplate 模板加载，并注入清洗后的简历全文。
