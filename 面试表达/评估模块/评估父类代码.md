`common.evaluation` 的核心是 `UnifiedEvaluationService`，它为文字面试和语音面试提供统一的面试评估能力。服务启动时会通过 `InterviewEvaluationProperties` 读取面试评估 prompt 模板路径，包括批次评估的 system/user prompt，以及二次汇总的 system/user prompt。文字面试和语音面试会将各自的数据适配成统一的 `QaRecord` 列表，然后调用 `evaluate(ChatClient, sessionId, qaRecords, resumeText, referenceContext)`。

`evaluate` 内部先对简历摘要和技能参考上下文做空值保护与长度截断，然后调用 `evaluateInBatches` 按配置的 `batchSize` 对问答记录分批处理。每个批次会把本批问题、用户回答、简历摘要和技能参考上下文渲染进用户 prompt，同时把 `BeanOutputConverter` 生成的 JSON 格式要求追加到 system prompt 中，再通过 `StructuredOutputInvoker.invoke` 调用 LLM 并解析为结构化批次报告。

批次评估完成后，服务会合并逐题评分、反馈、参考答案、优势和改进建议；如果某个批次失败，会对该批题目按 0 分兜底。随后服务会再调用一次 LLM 做二次汇总，生成更统一的综合评价、优势和改进建议；如果汇总失败，则降级使用批次聚合结果。最终构建并返回 `EvaluationReport`，包含总分、分类得分、逐题评估、综合反馈、优势、改进建议和参考答案。

这个统一服务目前被文字面试和语音面试复用；简历分析不走这套服务，而是由简历模块自己的 `ResumeGradingService` 和 `resume-analysis-*` prompt 完成。
