```
| 场景 | 机制 | 作用范围 | 目的 |
|---|---|---|---|
| 语音面试提交 | `AtomicBoolean.compareAndSet` | 单实例、单会话 | 防止重复提交同时启动多个 LLM/TTS 管线 |
| ASR 连接管理 | `synchronized` | 单实例、单会话 | 防止同一会话并发启动、停止或重连 ASR |
| TTS 音频收集 | `synchronized` | 单次 TTS 请求 | 防止回调线程和读取线程并发操作音频缓冲区 |
| LLM Provider 配置 | `ReentrantReadWriteLock` | 单实例 | 防止 Provider 配置并发读写冲突 |
| 面试提醒认领 | 数据库悲观写锁 | 所有连接同一数据库的实例 | 防止多个实例重复认领同一提醒 |
| WebSocket 发送 | `ConcurrentWebSocketSessionDecorator` | 单条前端连接 | 串行化多个线程的 WebSocket 发送 |
| TTS 并发控制 | `Semaphore` | 单实例、单会话 | 限制同时进行的 TTS 合成数量 |
```

### 4. Provider 配置的读写锁

项目使用：

```
ReentrantReadWriteLock rwLock
```

位置：\[LlmProviderConfigService.java (line 110)]\(/Users/ogawaaya/Desktop/学习/interview\_guide/interview-guide-optimize/app/src/main/java/interview/guide/modules/llmprovider/service/LlmProviderConfigService.java:110)

规则是：

```
读锁 + 读锁 → 可以并行
读锁 + 写锁 → 互斥
写锁 + 写锁 → 互斥
```

查询 Provider 使用读锁，创建、更新、删除、切换默认 Provider 使用写锁，避免配置文件和 Provider Registry 在热更新时出现不一致。

这是 JVM 锁，只能保护当前实例。

> 项目根据不同并发场景选择不同机制：语音重复提交使用 CAS，ASR 生命周期和 TTS 缓冲使用 JVM 内置锁，Provider 配置使用读写锁，WebSocket 发送使用并发安全装饰器，TTS 使用信号量限流，而跨实例的提醒任务认领使用数据库悲观行锁。Redisson 分布式锁虽然已经封装，但目前没有业务调用。
