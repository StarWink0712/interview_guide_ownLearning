QR在RAG中的作用

> 我在 RAG 知识库问答里做了 Query Rewrite。因为用户的问题经常很口语化，或者依赖上下文。比如用户第一轮问“Spring Boot 里面事务是怎么生效的？”，系统回答后，第二轮用户可能只问“那失效场景呢？”。
> 如果直接拿“那失效场景呢？”去做向量检索，语义太短，Embedding 召回可能不稳定。我的系统会先结合历史对话，把它改写成“Spring Boot 事务失效的常见场景有哪些”，再拿这个改写后的 query 去 pgvector 做相似度检索。这样召回的 chunk 更容易命中事务传播、同类方法调用、非 public 方法、异常类型不匹配这些内容。

> 这个 Query Rewrite 是可配置的，默认开启。如果改写失败，比如 LLM 超时或返回空字符串，系统不会中断问答，而是自动降级使用原始问题继续检索。
