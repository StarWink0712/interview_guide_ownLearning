简历服务较简单，有上传简历获取解析服务，获取所有简历，获取简历详情，导出简历分析报告为pdf服务等。

用户上传简历后，系统会自动创建简历分析任务，通过 Redis Stream 异步调用大模型。上传接口不会同步等待分析完成，而是先返回 PENDING 状态，前端通过轮询获取最终评分和优化建议。简历上传不会自动创建面试，只有用户主动选择面试方向、难度和题目数量，并点击开始面试后，系统才创建面试会话并生成个性化题目。面试结束后，再通过另一条 Redis Stream 异步生成综合面试报告。

核心看上传简历获取解析服务即可。前端上传完简历文件后，点击上传解析，后端controller层接收到，uploadAndAnalyze方法触发，先调用uploadService服务，获取分析结果map。进入这个分析方法，内部先记录当前时间，然后验证文件类型，获取文件原始name，文件大小，验证文件类型是否合格，比如pdf，word，md格式，然后调用persisttenceService服务验证简历是否存在，内部通过哈希算法计算哈希值，然后在数据库中查hash值是否存在来判断简历有没有重复。如果没有重复下一步回到uploadAndAnalyze服务内解析简历文本，然后保存简历原件到rustfs中，同时从rustfs中拿到简历的filekey和fileurl后把简历元数据存到数据库中，之后发布简历分析任务到redis，核心是简历id，消费者拿到简历id后，去数据库中查询到简历文本字符串，拼接成提示词发送给llm进行评估。

<br />

简历上传解析这个需求整体不算复杂，但链路还是比较完整的。前端上传文件后点解析，后端 Controller 层的 `uploadAndAnalyze` 方法先接到请求，这里做了两层限流，全局和 IP 各限制 5 次。进入 `ResumeUploadService` 的 `uploadAndAnalyze` 方法后，首先记录当前时间用于后续统计耗时，然后调 `FileValidationService` 校验文件是否为空、大小是否超过 10MB，接着通过 `ResumeParseService` 的 `detectContentType` 检测文件的真实 MIME 类型，再跟配置里允许的类型列表做比对，只放行 PDF、Word、Markdown 这些格式。文件类型校验通过之后，调 `ResumePersistenceService` 的 `findExistingResume` 做去重，核心就是 `FileHashService` 用 SHA-256 对文件内容计算哈希值，然后拿这个哈希值去数据库 `ResumeRepository` 里查，如果已存在就直接返回历史的 AI 分析结果，同时把访问次数加一，前端就能拿到之前的评分和建议，不用重复分析。

如果没有重复，就继续往下走，调 `ResumeParseService` 的 `parseResume` 用 Apache Tika 从文件里提取出纯文本字符串，这一步特别强调了扫描版 PDF 的问题，如果解析出来是空会直接抛异常。文本拿到之后，把简历原件上传到 RustFS 对象存储里，拿到 `fileKey` 和 `fileUrl`，然后把文件哈希、原始文件名、文件大小、存储地址、解析出来的简历文本这些元数据存到数据库的 `ResumeEntity` 里，状态先标记为 PENDING。这里还有一个补偿逻辑，如果入库失败了会回删 RustFS 上已上传的文件。

紧接着调 `AnalyzeStreamProducer` 的 `sendAnalyzeTask`，但这里要注意，它并不是把简历文本整段扔进 Redis Stream 的，而是先通过 `AsyncTaskService` 创建一个异步任务记录，然后只把 `taskId` 和 `resumeId` 放进 Stream 消息体里，简历文本是留在数据库里的，这样做的好处是消息体轻量、不撑 Redis 内存。

生产者发送成功后，整个同步链路就结束了，返回给前端的是 PENDING 状态的响应，前端可以轮询拿最终结果。另一边，`AnalyzeStreamConsumer` 作为 `AbstractStreamConsumer` 的子类，启动虚拟线程持续监听这个 Stream，拿到消息后解析出 `resumeId`，去数据库查 `ResumeEntity`，先从实体里取缓存的 `resumeText`，如果没缓存就从 RustFS 重新下载解析。拿到文本后调 `ResumeGradingService` 的 `analyzeResume`，这个方法里把简历文本拼接到预先写好的 Prompt 模板里，通过 `StructuredOutputInvoker` 调 LLM 做结构化输出，从内容完整性、结构清晰度、技能匹配度、表达专业性、项目经验五个维度打分，同时生成优势总结和改进建议，最终映射成 `ResumeAnalysisResponse` 对象，再由 `ResumePersistenceService` 把评分、建议这些 JSON 字段序列化存到 `ResumeAnalysisEntity` 里，同时把简历状态更新为 COMPLETED。整个消费链路支持最多三次重试，如果简历在分析期间被删了也会通过 `AsyncTaskCancelledException` 优雅终止。

<br />

***

PDF 导出的入口是 Controller 层的 `exportAnalysisPdf`，前端传简历 ID 过来，这个方法不通过 `Result` 包装响应，而是直接返回 `ResponseEntity<byte[]>` 的二进制流。里面先调 `ResumeHistoryService` 的 `exportAnalysisPdf` 方法拿到 `ExportResult`，这是一个 record，包含 PDF 字节数组和文件名。然后对文件名做 UTF-8 的 URL 编码，设置 `Content-Disposition` 响应头让浏览器以附件形式下载，Content-Type 设为 `application/pdf`，最后把字节数组塞进响应体返回给前端。异常兜底也很简洁，出错了就记日志返回 500。

重点在 `ResumeHistoryService` 里的 `exportAnalysisPdf`。这个方法先通过 `ResumePersistenceService` 查简历是否存在，不存在抛 `RESUME_NOT_FOUND` 异常；再查最新的分析记录，没有分析结果就抛 `RESUME_ANALYSIS_NOT_FOUND`。数据齐了之后，调 `PdfExportService` 的 `exportResumeAnalysis`，把 `ResumeEntity` 和 `ResumeAnalysisResponse` 传进去。PdfExportService 底层用的是 iText 8，它不是用 HTML 转 PDF 的方案，而是直接用 iText 的 API 纯代码构建文档结构。这里面有个关键点是中文字体，它从 classpath 加载了一个叫朱雀仿宋的 TTF 字体文件，用 `PdfFontFactory` 强制嵌入到 PDF 里，确保导出的报告在任何设备上中文都不会乱码。还有一个细节是 `sanitizeText` 方法，它在构建段落之前会用正则把 emoji 之类的特殊 Unicode 字符过滤掉，避免字体渲染时报错。

PDF 的排版结构是这样：先是居中大标题"简历分析报告"，接着是基本信息（文件名和上传时间），然后综合评分用 18 号大字加粗显示，并且根据分数区间做颜色区分，大于等于 80 分绿色、大于等于 60 分黄色、低于 60 分红色。下面用一个表格展示五个维度的明细得分，分别是项目经验满分 40、技能匹配度满分 20、内容完整性满分 15、结构清晰度满分 15、表达专业性满分 10，加起来正好 100 分。再往后就是简历摘要、优势亮点列表和建议列表，建议里面按优先级和分类来组织，问题描述和建议分开显示。整个文档构建在内存的 `ByteArrayOutputStream` 里完成，最后一把转成字节数组返回，整个过程没有任何落盘操作，所以并发安全性也很好。
