lua脚本在springboot启动的时候，就会加载到redis中，同时返回给服务端sha1摘要。

拦截切面的around方法会先提取被拦截的类名和方法名，用于构造rediskey，之后获取方法上的所有ratelimit注解，如果多个维度就都要满足，通过uuid生成唯一请求id。之后遍历全部的rule限流规则，生成对应的key，执行lua脚本，最后所有的规则都通过了，才能执行原方法。

<br />

`RateLimitAspect` 是我项目里限流注解的执行层。Controller 通过 `@RateLimit` 声明限流规则，比如简历上传接口同时配置 GLOBAL 和 IP 限流。请求进入时，Aspect 的 `@Around` 通知会先拦截方法，通过 `MethodSignature` 拿到类名、方法名和方法上的所有 `@RateLimit` 注解。
每条规则都会生成一个 Redis Key，格式类似 `ratelimit:{ResumeController:uploadAndAnalyze}:ip:1.2.3.4`。这里用了 Redis Cluster Hash Tag，保证同一方法派生出的 key 落在同一个 slot。然后切面通过 Redisson 的 `evalSha` 执行预加载的 Lua 脚本，Lua 内部用 String 保存当前令牌数，用 Sorted Set 保存窗口内请求记录，实现滑动时间窗口。
规则之间是 AND 关系，所有规则都通过才执行 `joinPoint.proceed()`。任意一条返回 0 或 null，就进入 `handleRateLimitExceeded`，优先调用 fallback，没有 fallback 就抛 `RateLimitExceededException`，最后由全局异常处理器统一返回错误码 8001。这个设计的核心是业务零侵入、分布式原子限流，并且把 Redis 脚本缓存、NOSCRIPT 重载、IP/USER 多维 Key 和降级处理都集中在切面里维护。

<br />

Redis 执行 Lua 脚本时是单线程原子执行的，脚本执行过程中不会穿插其他客户端命令，所以不会出现判断和扣减之间的并发竞态。

<br />

### NOSCRIPT 异常 是lua脚本缓存丢失异常。

***

## NOSCRIPT（脚本缓存丢失）

Redis 重启后，之前 `SCRIPT LOAD` 加载进去的 Lua 脚本缓存被清空。再调 `EVALSHA` 就报：

```
NOSCRIPT No matching script. Please use EVAL.
```

这个是可恢复的——代码自动重新 `SCRIPT LOAD` 再试一次就行。

***

## 非 NOSCRIPT（其他所有 Redis 故障）

```java
// RateLimitAspect 第 195-197 行
// 非 NOSCRIPT 异常直接向上抛出
throw e;
```

比如：

| 错误          | 原因            | 能自动恢复吗         |
| :---------- | :------------ | :------------- |
| 连接超时        | Redis 挂了或网络不通 | 不行，得等 Redis 恢复 |
| READONLY    | 请求打到了只读从节点    | 不行，需要切换主节点     |
| OOM         | Redis 内存满了    | 不行，得扩容或清数据     |
| CLUSTERDOWN | Redis 集群宕机    | 不行，得修集群        |

这些都是真实故障，重新加载脚本也没用，所以代码不做重试，直接抛出去由全局异常处理器兜底，返回给前端一个系统错误提示。
