# Redis Lua 滑动窗口

## 1. 为什么使用 Redis Lua 实现限流？

**回答：** 限流过程包含读取剩余令牌、清理过期记录、回收令牌、判断额度、扣减令牌和写入请求记录等多个步骤。如果这些操作由应用分多条 Redis 命令执行，会存在并发竞态；Lua 脚本在 Redis 中单线程原子执行，执行过程中不会穿插其他客户端命令，因此可以保证判断和扣减的一致性。

<br />

用redis是因为redis可以作为中间件其他实例都可以访问，作为分布式系统的缓存层。lua脚本主要是为了让查看令牌，扣减令牌封装成原子操作。避免插入其他指令。

## 2. Lua 脚本内部使用了什么数据结构？

**回答：** 每个限流 Key 前缀下维护两类数据：一个 String 类型的 value，保存当前剩余令牌数；一个 Sorted Set 类型的 permits，保存时间窗口内的历史消费记录。Sorted Set 的 Member 由 UUID 和本次请求令牌数构成唯一标识，Score 使用请求时间戳表示请求顺序。

<br />

lua限流脚本用的数据结构是一个string类型的value存剩余令牌数，另一个是zset，保存历史消息记录，时间过期的记录就把令牌归还。

## 3. 执行脚本需要传入哪些参数？

**回答：** 调用 Lua 时需要传入限流 Key，以及五个业务参数：申请的令牌数、当前毫秒时间戳、窗口大小、最大令牌数和请求唯一 ID。通常一次请求消耗一个令牌，请求唯一 ID 用于生成 Sorted Set 中的唯一 Member。

<br />

执行脚本时传入的有五个，需要的令牌数，当前毫秒级时间戳，窗口大小，最大令牌数和唯一请求id。记住这个不能死记硬背，要理解用滑动窗口算法需要哪些，一次请求需要的令牌数是必须的，然后窗口大小也是必须的，最大令牌数也是必须的，当前时间也是必须的，这个请求的id也是必须的，代表这个请求和请求的时间。

## 4. 滑动窗口算法的完整执行过程是什么？

**回答：** 脚本先从 String 中读取剩余令牌，不存在时初始化为最大令牌数；再根据“当前时间戳减窗口大小”通过 `ZRANGEBYSCORE` 找出已经过期的请求并删除，把这些请求占用的令牌归还到 value，但不超过最大值；随后判断剩余令牌是否满足本次申请，不足就返回拒绝，足够则通过 `ZADD` 写入本次请求记录，并更新剩余令牌数。

<br />

lua脚本先根据rediskey从string中读取剩余令牌数，然后从zset中用窗口大小和当前时间戳计算有没有超时的消息，令其归还令牌，然后计算剩余令牌是否足够当前需要的数目，如果够就更改string在令牌数，同时zset中也要记录这次请求，即请求id和时间还有其用到的令牌数。

## 5. Lua 如何保证判断和扣减的原子性？

**回答：** Redis 执行 Lua 脚本时是单线程的，脚本从开始到结束作为一个原子操作执行，期间不会插入其他客户端的读取或写入命令。因此不会出现两个请求同时读到相同剩余令牌，又分别扣减成功的并发问题。

<br />

最基础的问题，redis执行lua脚本时，会屏蔽外部的命令。

## 6. 为什么预加载 Lua 脚本并使用 SHA1 调用？

**回答：** Spring Boot 启动时会通过 `SCRIPT LOAD` 把本地 Lua 脚本加载到 Redis，Redis 返回脚本的 SHA1 摘要。后续切面通过 `EVALSHA` 只传递摘要和参数，不需要每次重复传输完整脚本，Redis 可以根据 SHA1 从脚本缓存中找到并执行对应 Lua。、、

<br />

SHA1摘要的作用是标识lua脚本，因为第一次上传lua脚本时会把脚本缓存到redis中，然后返回给服务端这个脚本的sha1摘要，后续再用这个脚本只需要上传这个摘要即可，避免重复上传lua脚本文件。

## 7. 为什么要给限流 Key 设置过期时间？

**回答：** String 和 Sorted Set 都需要设置过期时间，避免某个接口、IP 或用户长时间不再访问后，对应限流数据仍永久占用 Redis 内存。过期时间与滑动窗口配合，可以清理不再使用的限流状态。

<br />

都要设置过期时间，当到一定时间后，之前的请求基本上都是完成的，redis中如果不主动更新的话下次请求还要更新，所以直接设置过期时间清除，避免之后不再使用导致内存泄露。
