HNSW 的核心思想是**分层跳表 + 小世界图**。

### 直觉理解

想象你要在一百万个人里面找到和"张三"最像的人。如果每个人都认识自己行业里最牛的几个人，你再从行业大牛一层层往下找人，比一个一个问过去快得多。

### 结构：多层图，每层一个近邻图

```
层级 3：  ●────●            ← 顶层，节点很少，"高速公路"
          │
层级 2：  ●──●──●──●         ← 中层，节点稍多
          │  │  │
层级 1：  ●──●──●──●──●──●   ← 低层，节点更多
          │  │  │  │  │
层级 0：  ●──●──●──●──●──●──●──●──●  ← 底层，所有节点都在这里
```

- **层级 0**：包含所有向量，每个向量和离自己最近的几个邻居连边
- **越往上节点越少**：节点随机决定能"爬"到第几层，越高层的节点越稀疏但覆盖面越广
- **连线规则**：每个节点连向同层和下层中距离自己最近的邻居

### 检索过程

"找和查询向量 Q 最接近的 5 个向量"：

```
1. 从顶层某节点进入
2. 在这一层，贪心地往最近的邻居走，直到无法更近 → 找到了这一层的"局部最优"
3. 下探一层，以刚才的局部最优为起点，继续贪心搜索
4. 重复，直到第 0 层 → 最终找到的邻居就是全局近似最近邻
```

高层是"高速公路"——节点少、跨度大，帮你快速定位到目标区域附近。底层是"街道"——节点全、距离近，做精细比对确定最终结果。

### 和全量暴搜、IVFFlat 的对比

| <br /> | 全量暴搜     | IVFFlat     | HNSW        |
| :----- | :------- | :---------- | :---------- |
| 原理     | 一个个算     | 聚类 + 只搜附近的类 | 分层图 + 贪心搜索  |
| 精度     | 100%（精确） | 近似，依赖聚类质量   | 近似，通常 95%+  |
| 速度     | 慢（O(N)）  | 快           | 很快（O(logN)） |
| 内存     | 最小       | 中等          | 较大（存图结构）    |
| 构建时间   | 无需构建     | 需训练         | 需构建图，较慢     |

### pgvector 中的使用

你项目里配置了：

```yaml
pgvector:
  index-type: HNSW
  distance-type: COSINE_DISTANCE
  dimensions: 1024
```

PostgreSQL 建索引时调的就是 pgvector 的 HNSW 实现。查询时 `ORDER BY embedding <=> query_vector LIMIT 5` 自动走这个索引，把本来要扫全表逐行算余弦距离的 O(N) 操作变成了 O(logN) 的图搜索。
