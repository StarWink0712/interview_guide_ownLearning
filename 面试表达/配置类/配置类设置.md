llm模型和provider模型都通过配置类进行加噪，然后缓存起来，先从数据库中加载他们的配置，比如默认的模型，有哪些模型，模型的baseurl和apikey，同时apikey是被加密的，加密算法是？先从数据库中加载的话，可以不关机更改配置，数据库中没有的话再从配置文件中加载。

<br />

加密算法是 AES-256-GCM （ AES/GCM/NoPadding ），每次加密生成 12 字节随机 Nonce，密文和 Nonce 分别以 Base64 存入数据库的 apiKeyCiphertext 和 apiKeyNonce 字段；密钥通过 app.ai.security.api-key-encryption-key 配置，支持原始 AES-256 密钥或通过 SHA-256 派生的密码短语，开发环境有内置回退密钥。

配置加载链路确实是数据库优先：启动时 LlmProviderBootstrapService 若发现 llm\_provider\_config 表为空，则从 app.ai.providers YAML 种子导入并加密 API Key；运行时 LlmProviderRegistry.loadProviderOrThrow() 先查 LlmProviderRepository （数据库），查不到再回退到 LlmProviderProperties （YAML 文件），最终 ChatClient 实例缓存到 ConcurrentHashMap ，配置变更后调用 registry.reload() 即可热生效，无需重启。
