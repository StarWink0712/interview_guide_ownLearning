# 简历与方向个性化出题

## 1. generateQuestionsBySkill 的主要职责是什么？

**回答：** 方法接收 LLM Provider、skillId、难度、简历文本、题目数量、历史问题、自定义分类和 JD，加载或构造 Skill，解析难度描述，取得 Plain ChatClient，并根据是否有简历选择纯方向出题或“简历题 + 方向题”并行生成，最终返回统一的 `List<InterviewQuestionDTO>`。    

## 2. Skill 定义在出题时提供哪些信息？

**回答：** `skillService.getSkill(skillId)` 返回包含技能名称、描述、分类列表、Persona 和参考内容的 Skill。分类用于按题量计算知识领域配额，Persona 约束模型扮演的面试官角色，参考内容为出题提供考察基线；当 `skillId=custom` 且传入 `customCategories` 时，可以动态构造自定义 Skill。

skill在出题时主要给技能名称，分类，描述，比如你是一个java后端开发面试官，请出关于javase ，java并发等相关的面试题目，题目要求格式是什么什么等。

<br />

## 3. 难度参数如何转换成模型能理解的描述？

**回答：** `resolveDifficulty` 把 junior、mid、senior 等难度键转换为 Prompt 中的中文经验描述，例如“校招/0-1 年经验”“1-3 年经验”“3 年以上经验”。相比只把枚举值传给模型，明确经验范围更容易控制问题深度。

## 4. 结构化出题为什么使用 Plain ChatClient？

**回答：** 出题要求模型严格返回可转换成 DTO 的 JSON，因此通过 `llmProviderRegistry.getPlainChatClient(llmProvider)` 获取不包含 SkillsTool 和对话记忆 Advisor 的 ChatClient。这样可以避免工具调用或历史记忆消息污染结构化输出；Skill 的 Persona、分类和参考资料由后端确定性读取后主动注入 Prompt。

要在提示词中确定告诉llm生成结构化的json。json格式由提示词中传入。

## 5. 没有简历时如何生成方向题？

**回答：** 系统直接调用 `generateDirectionOnly()`，根据 Skill 分类和总题数计算每个分类的题目配额，再构建配额表、参考内容、历史问题和安全处理后的 JD，把这些变量注入方向出题 Prompt，要求 LLM 按指定难度、技能方向和分类数量生成题目。

<br />

## 6. 方向题的分类配额如何生成？

**回答：** `skillService.calculateAllocation()` 根据 Skill 的分类列表和 `questionCount` 计算每个领域的配额，例如 Java 基础 3 题、Spring 2 题、数据库 2 题。`buildAllocationDescription()` 再把结果渲染成 Markdown 表格放入 Prompt，防止模型把题目过度集中在某一个知识点。

## 7. Skill 参考资料和 JD 如何注入 Prompt？

**回答：** `buildReferenceSection()` 从 Skill 定义中读取参考内容，`buildJdSection()` 处理用户传入的岗位描述。JD 先经过 `PromptSanitizer` 清洗，再包裹在安全分隔符内，作为岗位数据而不是可执行指令注入，既提高岗位匹配度，也降低 Prompt 注入风险。

## 8. 无简历模式的系统 Prompt 如何构建？

**回答：** 系统先渲染 `skillSystemPromptTemplate`，再追加三部分：`GENERIC_MODE_SYSTEM_APPEND` 声明当前没有简历，禁止出现“你在简历中提到”等表述；`buildSkillPersonaSection()` 注入 Skill 的面试官角色；`outputConverter.getFormat()` 追加 JSON Schema 格式要求。用户 Prompt 则包含题量、追问数、难度、技能描述、配额、历史题、参考内容和 JD。

## 9. 有简历时题目比例如何分配？

**回答：** 简历题数量使用 `max(1, round(questionCount × 0.6))`，方向题数量为总题数减去简历题数。也就是大约 60% 的主问题围绕候选人简历经历，剩余题目覆盖目标技能方向，兼顾个性化深挖和基础能力考察。

## 10. 为什么简历题和方向题要并行生成？

**回答：** 两类题调用不同 Prompt，彼此没有数据依赖，而且都是等待 LLM 网络响应的 I/O 密集任务。如果串行调用，总耗时接近两次模型调用之和；使用两个 `CompletableFuture` 提交到虚拟线程执行器后并行等待，可以把整体耗时降低到较慢的那一路附近。

## 11. generateResumeQuestions 和 generateDirectionOnly 分别关注什么？

**回答：** `generateResumeQuestions` 使用简历专用的系统和用户模板，注入候选人的简历全文、技能描述和难度，生成项目经历、技术实践等个性化题目；`generateDirectionOnly` 根据 Skill 分类配额、参考资料、历史问题和 JD 生成标准方向题。两路最终都使用同一个结构化输出器。

## 12. 出题时系统提示词和用户提示词如何分工？

**回答：** 系统提示词定义模型是面试官、角色 Persona、题目约束以及必须输出的 JSON 格式；用户提示词承载本次动态数据，例如难度、题量、技能分类、配额、历史题、简历文本、JD 和参考内容。将稳定规则与动态输入分开，便于模板复用和维护。

## 13. 模型返回的 QuestionListDTO 结构是什么？

**回答：** `QuestionListDTO` 内部包含 `List<QuestionDTO>`。每个 `QuestionDTO` 包含 `question`、`type`、`category`、`topicSummary` 和 `followUps`。`BeanOutputConverter<QuestionListDTO>` 提供 JSON 格式指令，并将模型输出反序列化成该对象。

## 14. QuestionDTO 如何转换成 InterviewQuestionDTO？

**回答：** `convertToQuestions()` 过滤空题目，为主问题生成递增索引，统一把 type 转为大写，并保留分类和 `topicSummary`，标记 `isFollowUp=false`。随后清洗 followUps，过滤空项、trim 并限制到配置数量，再生成 `isFollowUp=true` 的追问题，`parentQuestionIndex` 指向对应主问题，分类标注为“原分类（追问1/2/3）”。

## 15. LLM 多生成题目时如何保证主问题数量准确？

**回答：** 转换后通过 `capToMainCount()` 按主问题数量截断。如果模型超额生成，只保留前 N 个主问题以及紧跟在它们后面的追问，后续超配额主问题和追问一并丢弃，确保最终主问题数符合请求配置。
