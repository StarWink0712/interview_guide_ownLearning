前端填写完答案点击提交后，Controller 接收 `{sessionId, questionIndex, answer}` JSON 请求体，组装为 `SubmitAnswerRequest` 调用 `InterviewSessionService.submitAnswer`。方法内先从 Redis 加载会话缓存获取预生成的问题列表，校验当前题目的 index 合法性，然后将用户答案写入内存中的问题列表，index 加一并判断是否还有下一题。紧接着**先更新 Redis**：把含答案的完整问题列表、新索引、会话状态一次性写回缓存。之后进入 try-catch 包裹的 DB 持久化阶段：调用 `saveAnswer` 按 `(sessionId, questionIndex)` 做 upsert（有则更新、无则创建），将当前这一道题的答案写入 `interview_answers` 表（**所有会话共用同一张表，每道题一行**）；随后更新会话表的当前问题索引和会话状态。每提交一题都会同步调用 `adaptiveInterviewService.evaluateAndDecideSafely(sessionId, question, answer)`，该方法从 `interview_sessions` 表加载 LLM 提供商、难度等级和历史能力画像 JSON，传给 `evaluateAndDecide` 依次执行三步：`TurnEvaluationService` 调 LLM 做单题即时评分、`AbilityProfileService` 用加权移动平均算法将本轮得分合并到累积能力画像、`AdaptiveDecisionService` 调 LLM 产出下一步策略，最后通过 `persistResult` 将评分写回 `interview_answers` 表、将画像 JSON 和追踪链 JSON 写回 `interview_sessions` 表。评估失败只打 warn 日志返回 null，不阻断主流程。**当最后一题提交后**，会话表的 `sessionStatus` 设为 COMPLETED、`evaluateStatus` 设为 PENDING，同时通过 `evaluateStreamProducer` 向 Redis Stream 投递异步评估任务，由消费者最终生成综合面试报告。方法最终返回 `SubmitAnswerResponse`，包含是否有下一题、下一题内容、当前进度、即时评分、决策和能力画像，供前端展示。

两次存答案到数据库是分开的，先存答案到数据库，然后llm评估完再存分数到数据库。

<br />

第一次写 DB（ saveAnswer ）：一开始就把用户答案、题目内容、分类落库， 分数和反馈字段设为 0 和 null ：

第二次写 DB（ updateAnswerEvaluation ）：LLM 评估完成后，通过 persistResult → updateAnswerEvaluation 根据 (sessionId, questionIndex) 找到之前那条答案记录， 把评分和反馈更新进去 。

```
第一次 INSERT: 答案文本 ✓  分数 0  反馈 null
                   ↓ LLM 评估中……
第二次 UPDATE: 答案文本 ✓  分数 85  反馈 "表达清晰，但缺少具体案例..."
```

<br />

之后就是异步评估任务：

当最后一题提交并完成同步评估后，会话 `evaluateStatus` 被设为 PENDING，`EvaluateStreamProducer.sendEvaluateTask` 被调用。Producer 先通过 `AsyncTaskService.createOrReusePendingTask` 确保同一会话不重复入队（幂等保证），再通过 `TransactionAfterCommitExecutor` 在数据库事务提交后将 `{taskId, sessionId}` 消息 XADD 到 Redis Stream。

消费者 `EvaluateStreamConsumer` 继承 `AbstractStreamConsumer` 模板，从 Redis 消费者组拉取消息。解析出 sessionId 后，标记任务和会话均为 PROCESSING，然后加载会话实体并反序列化题目 JSON，从 `interview_answers` 表读取所有答案填回对应题目，形成完整问答数据集。随后通过 `AnswerEvaluationService` 将题目转换为通用 `QaRecord` 列表，结合简历文本和 Skill 参考基线，委托 `UnifiedEvaluationService` 执行三阶段评估：**分批评估**——按配置的 batchSize 将题目分组，每组独立调用 LLM 产出逐题评分和综合反馈；**合并批次**——将各批次逐题评分按索引合并，缺失项零分兜底，优势改进去重截断；**二次汇总**——再调 LLM 基于批次中间结果生成统一的综合评价，失败则降级到批次聚合结果。评估完成得到 `InterviewReportDTO`（总分、分类得分、逐题评分反馈、优势、改进建议、参考答案）后，`persistenceService.saveReport` 将其写入 `interview_sessions` 表并将各题评分回填 `interview_answers` 表，会话状态置为 EVALUATED。

消费过程中任何异常由父类自动捕获重试（最多 3 次），超过上限进入死信终态，会话 `evaluateStatus` 标记为 FAILED。任务成功后 `markCompleted` 将任务和会话评估状态均置为 COMPLETED，前端可调用 `GET /api/interview/sessions/{sessionId}/report` 获取完整报告。

更详细版

前端填写完答案点击提交后，请求路径为 `POST /api/interview/sessions/{sessionId}/answers`，Controller 接收 `{questionIndex, answer}` JSON 请求体，将 URL 路径中的 `sessionId` 与请求体中的 `questionIndex`、`answer` 组装为 `SubmitAnswerRequest`（一个包含 `sessionId`、`questionIndex`、`answer` 三个字段的 record），调用 `InterviewSessionService.submitAnswer`。方法入口首先通过 `getOrRestoreSession` 获取会话缓存——优先从 Redis 读取 `CachedSession`，若缓存未命中则从数据库 `interview_sessions` 表恢复并重新缓存（同时刷新 TTL），会话不存在直接抛出 `BusinessException(INTERVIEW_SESSION_NOT_FOUND)`。拿到会话后，从缓存中反序列化出预先生成的问题列表 `List<InterviewQuestionDTO>`，然后通过 `request.questionIndex()` 取出当前题目索引，做边界校验：`index < 0 || index >= questions.size()` 则抛出 `BusinessException(INTERVIEW_QUESTION_NOT_FOUND)`。校验通过后，从列表取出当前题目，调用 `question.withAnswer(answer)` 生成填充了答案的不可变副本并替换回列表，然后 `newIndex = index + 1`，通过 `newIndex < questions.size()` 判断是否还有下一题，并取出 `nextQuestion` 或置为 null。接下来**先写 Redis**：调用 `sessionCache.updateQuestions` 将含最新答案的完整问题列表写回 Redis，`sessionCache.updateCurrentIndex` 更新当前题号，若已是最后一题则 `sessionCache.updateSessionStatus` 置为 `COMPLETED`。Redis 写完之后进入一个 try-catch 包裹的 DB 持久化块——即使 DB 操作全部失败也只打 warn 日志，不会中断前端响应。DB 写入分三部分：其一，`persistenceService.saveAnswer(sessionId, index, question, category, answer, 0, null)`，该方法内部按 `(sessionId, questionIndex)` 做 upsert——通过 `answerRepository.findBySession_SessionIdAndQuestionIndex` 查找已有记录，存在则覆盖内容，不存在则创建新 `InterviewAnswerEntity` 并关联会话实体，所有会话的答案存于同一张 `interview_answers` 表，`(session_id, question_index)` 上有联合唯一约束保证幂等；其二，`persistenceService.updateCurrentQuestionIndex` 更新会话表当前题号；其三，`persistenceService.updateSessionStatus` 更新会话状态（`IN_PROGRESS` 或 `COMPLETED`，进入 COMPLETED 或 EVALUATED 时会自动记录 `completedAt` 时间戳）。DB 写完后立即进行同步单题评估：调用 `adaptiveInterviewService.evaluateAndDecideSafely(sessionId, question, answer)`，该方法内部同样 try-catch 兜底，失败返回 null 不抛异常。Safely 方法先从 `interview_sessions` 表加载会话实体，读取三个关键字段：`llmProvider`（LLM 提供商标识，用于路由 ChatClient）、`difficulty`（当前难度等级，如 junior/mid/senior）、`abilityProfileJson`（历史累积能力画像 JSON）。拿到后调用核心编排方法 `evaluateAndDecide(llmProvider, difficulty, abilityProfileJson, question, answer)`，依次执行三步：第一步，`TurnEvaluationService.evaluateTurn` 以当前题目、用户答案、难度等级等上下文注入 Prompt 模板，调用 LLM 产出 `TurnEvaluationDTO`，包含评分（0-100）、深度等级、缺失知识点列表、追问建议和能力分类；第二步，`AbilityProfileService.updateProfile` 将上轮画像 JSON 反序列化，按能力分类定位对应维度，使用加权移动平均算法合并本轮得分（`新分 = (历史分 × 历史次数 + 本轮分) ÷ (历史次数 + 1)`），同时更新置信度（`min(1.0, 0.25 + 次数 × 0.15)`）、合并薄弱关键词（去重保留顺序，截断至 8 个），生成包含各维度详情、综合均分和文字摘要的新 `AbilityProfileDTO`；第三步，`AdaptiveDecisionService.decideNextStep` 将本轮上下文（题目、答案、评分、画像）注入 Prompt 模板，由 LLM 产出 `AdaptiveDecisionDTO`（包含动作、目标分类、下一难度、决策理由、追问题目），若 LLM 调用失败则降级到 `fallbackDecision` 的本地规则（得分≥85 提难度、<70 或有缺失知识点则追问、其他切换分类）。evaluateAndDecide 完成后返回 `AdaptiveInterviewResultDTO`（评估+画像+决策三合一），Safely 方法拿到结果后调用 `persistResult`：先将评分和反馈通过 `updateAnswerEvaluation` 写回 `interview_answers` 表对应题目行，再将画像 JSON 和追踪链 JSON（历史链追加本轮记录后序列化）通过 `updateAdaptiveState` 写回 `interview_sessions` 表。至此单题同步评估完成。回到 submitAnswer，判断如果是最后一题（`!hasNextQuestion`），执行两项收尾操作：`persistenceService.updateEvaluateStatus(sessionId, PENDING, null)` 将评估状态字段独立置为 PENDING（与会话状态 COMPLETED 是两个不同字段），然后调用 `evaluateStreamProducer.sendEvaluateTask(sessionId)` 投递异步评估任务——Producer 内部先通过 `AsyncTaskService.createOrReusePendingTask` 按 activeFlag 机制确保同一会话不会重复入队（幂等保证），然后在数据库事务提交后通过 `TransactionAfterCommitExecutor` 将 `{taskId, sessionId, retryCount:0}` 负载 XADD 到 Redis Stream，由 `EvaluateStreamConsumer` 异步消费，加载该会话全部题目和答案后调用 `AnswerEvaluationService` 执行 LLM 综合评估，生成包含总分、各类别得分、逐题详情、总体评价、优势、改进建议、参考答案的 `InterviewReportDTO`，再通过 `attachAdaptiveAnalysis` 从会话表反序列化能力画像和追踪链注入报告，最终持久化到会话表并标记评估状态为 COMPLETED（消费者支持失败重试最多 3 次）。所有操作完成后，`submitAnswer` 返回 `SubmitAnswerResponse`，包含 `hasNextQuestion`（是否还有下一题）、`nextQuestion`（下一题 DTO，无则为 null）、`newIndex`（当前进度索引）、`totalQuestions`（总题数）、`turnEvaluation`（即时评分）、`adaptiveDecision`（决策）、`abilityProfile`（能力画像），前端据此展示评分反馈并推进到下一题界面。
