这里是spring启动后，自动配置服务端与TTS端的连接设置，但是并没有连接。而是每次llm生成文本后，临时建立websocket连接。即短连接，至于为什么用短连接是因为服务端把文本推送给tts后，同步等待语音，之后就结束了，没有连接存在的意义了，所以不需要用map缓存websocket连接。

```
用户点击提交
  │
  ├─ 取出 mergeBuffer 中的 ASR 累积文本
  │
  ├─ 流式调用 LLM（chatStreamSentences）
  │     │
  │     ├─ 每收到一个 token：
  │     │   ├─ ① 检查是否包含终止标点 → 是则启动异步 TTS（CompletableFuture）
  │     │   └─ ② 节流推送实时字幕给前端（≥180ms 间隔 且 ≥12 字符增量）
  │     │
  │     └─ 流结束 → ③ 尾句兜底（不以标点结尾的剩余文本也送 TTS）
  │
  ├─ ④ 保存消息到数据库（userText + aiReply）
  │
  ├─ ⑤ 等待所有 TTS Future 完成
  │     ├─ 分块模式：每句 TTS 完成 → 立即推 WAV 音频给前端
  │     └─ 合并模式：所有 TTS 完成后 → 合并 PCM → 一次性推送
  │
  └─ ⑥ 记录整轮指标（turn.duration / turn.completed）
```

这个是TTS语音合成服务的设置，核心就是项目启动后就设置好相关配置，如连接参数等信息。

要知道tts语音合成是在用户说完话之后，ASR识别成文本并积累，之后用户点击提交，然后先流式调用llm生成答案，然后对答案进行分割遇到标点符号就算一句话，然后把这句话推送给前端作为字幕显示，同时调用TTS语音合成生成这句话的语音返回给前端播放。

springboot启动后，其postconsruct方法启动，验证一下配置文件中的apikey是否为空。然后进入synthesize方法，第一阶段先检查一下需要转语音的文本是否为空，然后构造一个countdownlatch同步等待工具，将异步websocket转为同步阻塞等待（tts要把文本转语音，所以需要即时把语音给前端，如果不同步等待的话，返回的就是空语音，而sst不需要，因为sst是一直在进行转换，是流式的，是通过三个回调处理的，而tts是直接通过synthesize方法要结果的），其实就是等待TTS合成完毕拿到完整的语音字节数组。

阶段二是构建连接参数，其实整个流程和ASR与服务端连接时差不多，包括模型，apikey等信息；然后创建websocket事件回调，是那个回调，建立成功的回调，收到TTS端推送语音的，关闭的。建立成功的就打印一下日志，收到推送的和sst一样，\*\*\*进入到handlerServerEvent方法，\*\*\*onclose的也是关闭注册。之后就是阶段三建立websocket连接拿到QwenTtsrealtime，代表封装的tts的客户端对象。阶段四配置tts会话参数，比如音色，模式，语言类型中英文等，语速，音量等配置。

阶段五就是调用客户端对象的append方法把文本传给tts进行合成，然后commit提交。阶段六是同步等待tts完成合成返回字节数组格式的音频分片（用一个字节数组容器存储audioContainer,由handlerServerEvent方法将pcm拼到容器中（仍是pcm）），设置30秒超时时间（通过countdownlatch让这个虚拟线程等待阻塞30s，等onevent回调中处理完让countdownlatch-1），足够合成300字长文本了。用户强制结束时会触发onclose回调关闭websocket连接。

<br />

现在进入handlerServerEvent方法内部：方法内部同sst的处理方法一样，也是用case路由不同的情况，根据tts服务端返回的json中的事件类型字段进行路由。如果收到了一个pcm分片，就base64解码为原始PCM字节，然后追加到audioContainer容器中。如果是合成完成了的字段，就把countdownlatch-1，即完成了等待，可以返回给上层handler了，如果报错了也countdownlatch--避免主线程一直等待。但是要知道容器中仍然是pcm，之后在handler层才会通过convertPcmToWav方法手动添加44字节的wav文件头转成wav数组。然后回到triggerOpeningQuestionIfNeeded方法内，将wav格式的语音字节数组给sendaudio，推送给前端。到这就是

```
用户开口说话
  → 前端采集音频，Base64 编码，WebSocket 文本帧发送
    → handleTextMessage() 触发

用户继续说话 → 循环往复...
```
