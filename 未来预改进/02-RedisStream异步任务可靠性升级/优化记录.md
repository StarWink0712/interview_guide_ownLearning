# 优化记录：Redis Stream 异步任务可靠性升级

日期：2026-05-14

## 一、优化目标

根据 `AI实施计划.md`，本次优化将原有 Redis Stream 异步任务从“基础可用”
升级为“可追踪、轻量化、可恢复、可重试、可管理”的最小可用版本。

重点目标：

- 修复简历分析消费者中 Javadoc 未闭合导致真实实现被注释的问题。
- Stream 消息不再保存简历/知识库大段全文。
- 新增统一异步任务表，记录任务状态、重试次数、失败原因和 Stream 消息 ID。
- 支持 pending 消息超时恢复。
- 支持任务查询、手动重试、手动取消接口。
- 超过最大重试次数后进入 `DEAD_LETTER` 状态。

## 四、统一任务表设计

`AsyncTaskEntity` 记录字段包括：

- `taskType`
- `businessId`
- `streamKey`
- `messageId`
- `status`
- `retryCount`
- `maxRetryCount`
- `nextRetryAt`
- `lastError`
- `payloadJson`
- `parentTaskId`
- `activeFlag`
- `activeKey`
- `createdAt`
- `updatedAt`

幂等策略：

- 入队前通过 `taskType + businessId + active status` 查找活跃任务。
- 已存在 `PENDING/PROCESSING` 任务时复用旧任务并跳过重复入队。
- 新任务写入 `activeKey = taskType + ":" + businessId`。
- 任务完成、取消、失败或死信后清空 `activeKey`，允许后续重新创建任务。

## 五、Stream 消息轻量化

改造生产者：

```text
app/src/main/java/interview/guide/modules/resume/listener/AnalyzeStreamProducer.java
app/src/main/java/interview/guide/modules/knowledgebase/listener/VectorizeStreamProducer.java
app/src/main/java/interview/guide/modules/interview/listener/EvaluateStreamProducer.java
app/src/main/java/interview/guide/modules/voiceinterview/listener/VoiceEvaluateStreamProducer.java
```

新消息格式：

```text
taskId
businessId
retryCount
resumeId/kbId/sessionId/voiceSessionId
```

优化点：

- 简历分析不再把 `resumeText` 写入 Redis Stream。
- 知识库向量化不再把文档全文写入 Redis Stream。
- `payloadJson` 只记录必要摘要，例如 `contentLength`。
- 发送失败时同时更新业务实体状态和统一任务状态。

## 六、消费者按 ID 加载内容

改造消费者：

```text
app/src/main/java/interview/guide/modules/resume/listener/AnalyzeStreamConsumer.java
app/src/main/java/interview/guide/modules/knowledgebase/listener/VectorizeStreamConsumer.java
app/src/main/java/interview/guide/modules/interview/listener/EvaluateStreamConsumer.java
app/src/main/java/interview/guide/modules/voiceinterview/listener/VoiceEvaluateStreamConsumer.java
```

具体变化：

- 简历分析根据 `resumeId` 从数据库读取 `resumeText`，为空时从对象存储重新解析。
- 知识库向量化根据 `kbId` 从对象存储下载并解析内容。
- 面试评估根据 `sessionId` 查询问题、答案和会话配置。
- 语音面试评估根据 `sessionId` 查询会话和消息。
- 业务实体不存在时抛出 `AsyncTaskCancelledException`，任务 ACK 后标记为 `CANCELLED`。
- 消费成功后统一任务状态标记为 `COMPLETED`。
- 超过最大重试次数后统一任务状态标记为 `DEAD_LETTER`。

## 七、Pending 消息恢复

改造文件：

```text
app/src/main/java/interview/guide/infrastructure/redis/RedisService.java
app/src/main/java/interview/guide/common/async/AbstractStreamConsumer.java
app/src/main/java/interview/guide/modules/asynctask/service/PendingMessageRecoveryService.java
```

新增能力：

- `RedisService.streamAutoClaim(...)` 封装 Redisson `XAUTOCLAIM` 能力。
- `AbstractStreamConsumer.recoverPendingMessages(...)` 支持 claim 并重新处理 pending 消息。
- `PendingMessageRecoveryService` 在应用启动后和定时任务中扫描所有消费者。
- idle 超过阈值的 pending 消息会被 claim 到当前消费者继续处理。

当前默认：

- pending idle 阈值：`60_000ms`
- 单次恢复批量：`10`

## 八、死信与手动重试

新增接口：

```text
GET  /api/async-tasks
GET  /api/async-tasks/{id}
POST /api/async-tasks/{id}/retry
POST /api/async-tasks/{id}/cancel
```

实现规则：

- `GET /api/async-tasks` 支持按 `taskType`、`status` 查询。
- `retry` 只允许 `FAILED/CANCELLED/DEAD_LETTER` 状态。
- 手动重试会重置 `retryCount`，重新发送轻量 Stream 消息。
- `cancel` 只允许 `PENDING/PROCESSING` 状态。
- 自动重试超过 `AsyncTaskStreamConstants.MAX_RETRY_COUNT` 后进入 `DEAD_LETTER`。

## 九、幂等保护

本次实现的幂等点：

- 生产者入队前调用 `AsyncTaskService.createOrReusePendingTask(...)`。
- 同类型同业务对象已有活跃任务时，跳过重复入队。
- 消费者侧对已完成的简历分析、知识库向量化、面试评估、语音评估做基础跳过保护。
- 手动重试复用原 taskId，不额外创建新任务。

## 十一、后续可继续优化

建议后续迭代：

- 增加指数退避重试，根据 `nextRetryAt` 延迟重试。
- 新增单独死信表或 DLQ Stream，保存不可恢复任务快照。
- 在前端管理控制台展示 `/api/async-tasks` 列表、失败原因、重试和取消按钮。
- 对 pending 恢复增加更细的指标统计和告警。
- 对手动取消中的 `PROCESSING` 任务增加业务级中断检查，避免长任务完成后覆盖取消状态。
