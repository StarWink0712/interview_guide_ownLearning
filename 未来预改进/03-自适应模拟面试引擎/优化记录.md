# 自适应模拟面试引擎优化记录

日期：2026-05-14

## 本次优化目标

按照 `AI实施计划.md` 将模拟面试从纯静态题单增强为“静态题单 + 单轮即时评估 + 能力画像 + 自适应决策”的增量方案，确保新能力失败时不影响原有答题、交卷和报告流程。

## 已完成优化

1. 补全自适应模型
   - 新增 `AdaptiveTraceDTO`，用于记录每轮题目的即时评估与自适应决策。
   - 保留并接入 `TurnEvaluationDTO`、`AdaptiveDecisionDTO`、`AbilityProfileDTO`、`AbilityDimensionDTO`。

2. 修正并完善 Prompt
   - 修正 `interview-turn-evaluation-user.st` 和 `interview-adaptive-decision-user.st` 的占位符格式。
   - 将错误的 `<question>` / `<answer>` 风格改为 Spring `PromptTemplate` 可渲染的 `{question}` / `{answer}` 风格。
   - 保持结构化 JSON 输出要求，继续通过 `StructuredOutputInvoker` 调用。

3. 增强即时评估服务
   - `TurnEvaluationService` 增加结果规范化：
     - 分数限制在 0-100。
     - 回答深度限制在 1-5。
     - 缺失关键点过滤空值。
     - category 缺失时回退到当前题目分类。

4. 增强自适应决策服务
   - `AdaptiveDecisionService` 对 LLM 决策结果做 action、目标分类、难度和下一题文本规范化。
   - 保留本地兜底策略：
     - 高分回答生成 `RAISE_DIFFICULTY`。
     - 低分或缺失关键点生成 `FOLLOW_UP`。
     - 普通回答生成 `NEXT_CATEGORY`。

5. 接入答题提交流程
   - `InterviewSessionService.submitAnswer()` 在保存原始答案后调用自适应编排。
   - 返回体 `SubmitAnswerResponse` 增加：
     - `turnEvaluation`
     - `adaptiveDecision`
     - `abilityProfile`
   - 如果即时评估或自适应决策失败，只记录 warn 日志，不阻断原有答题流程。

6. 轻量持久化自适应状态
   - `InterviewSessionEntity` 增加：
     - `abilityProfileJson`
     - `adaptiveTraceJson`
   - `InterviewPersistenceService` 增加：
     - `updateAdaptiveState()`
     - `updateAnswerEvaluation()`
   - 单轮即时分数与反馈会先写入答案记录，最终完整报告仍可覆盖为全局评估结果。

7. 报告和详情返回自适应分析
   - `InterviewReportDTO` 增加：
     - `abilityProfile`
     - `adaptiveTrace`
   - `InterviewDetailDTO` 增加：
     - `abilityProfile`
     - `adaptiveTrace`
   - `InterviewHistoryService` 和 `InterviewMapper` 已接入自适应 JSON 解析与映射。

8. 前端类型补齐
   - `frontend/src/types/interview.ts` 增加自适应评估、决策、画像和 trace 类型。
   - `frontend/src/api/history.ts` 增加历史详情中的自适应字段类型。
   - 本次未新增 UI 页面，只保证接口字段可被前端安全消费。

9. 新增测试
   - `TurnEvaluationServiceTest`
   - `AbilityProfileServiceTest`
   - `AdaptiveDecisionServiceTest`
   - `AdaptiveInterviewServiceTest`

## 当前效果

提交答案后，系统会尝试完成以下增强流程：

```text
保存原始答案
-> 单轮即时评估
-> 更新能力画像
-> 生成自适应追问/升降难度/切换分类决策
-> 持久化 abilityProfileJson 与 adaptiveTraceJson
-> 在提交响应、报告和历史详情中返回自适应分析
```

如果 LLM 即时评估失败：

```text
原有提交答案、下一题跳转、交卷和异步评估流程继续执行
```

## 后续建议

1. 前端可新增“自适应分析”面板，展示每轮即时分数、追问原因和能力画像。
2. 后续可将 `adaptiveDecision.nextQuestion` 真正插入题单，形成动态追问题流。
3. 可将 `AdaptiveTraceDTO` 升级为独立实体表，便于按题目、能力维度和时间查询。
4. 可在 PDF 导出中加入能力画像与自适应追问记录。
