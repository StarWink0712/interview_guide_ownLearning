# 自适应模拟面试引擎 - 改进详述

## 一、为什么做

当前模拟面试模块已经支持 Skill 出题、简历题、追问、历史题去重和评估报告。但整体仍偏“预生成题单”：

- 面试开始前生成一批题，后续不太根据候选人表现动态调整。
- 追问主要由模型提前生成，不一定紧贴用户刚刚回答的薄弱点。
- 最终报告有评分，但缺少过程中的能力画像演进。

真实面试里，面试官会根据回答实时调整：

- 回答扎实，就提高难度或进入系统设计。
- 回答含糊，就追问细节和真实项目经验。
- 回答跑题，就拉回主题。
- 某个能力薄弱，就多问几题验证。

这个模块目标是把模拟面试从“静态题单”升级成“自适应面试官”。

## 二、目标效果

实现后，面试流程变为：

```text
当前问题
-> 用户回答
-> 即时评分与薄弱点识别
-> 更新能力画像
-> 决定下一步：追问 / 提升难度 / 降低难度 / 切换分类
-> 生成下一题
```

最终报告不只展示总分，还展示：

- 每个能力维度的趋势。
- 哪些问题触发了追问。
- 哪些方向表现稳定。
- 哪些方向需要复习。
- 下一轮练习推荐。

## 三、核心设计

### InterviewAbilityProfile

能力画像，可按分类维护。

示例维度：

- Java 基础
- Spring
- 数据库
- Redis
- 分布式
- 项目深度
- 系统设计
- 沟通表达

每个维度记录：

- 当前分数
- 置信度
- 已问题数
- 最近表现
- 薄弱关键词

### AdaptiveDecision

每轮回答后生成一个决策。

建议字段：

- `action`
- `targetCategory`
- `nextDifficulty`
- `reason`
- `followUpFocus`

Action 可以包括：

- `FOLLOW_UP`
- `NEXT_CATEGORY`
- `RAISE_DIFFICULTY`
- `LOWER_DIFFICULTY`
- `DEEP_DIVE_PROJECT`
- `END_PHASE`

### TurnEvaluation

单轮即时评估。

建议字段：

- `score`
- `understood`
- `keyMissingPoints`
- `depthLevel`
- `hasRealExperience`
- `suggestedFollowUp`

## 四、技术亮点

### 亮点 1：动态追问

面试表达：

> 不是提前生成固定追问，而是根据候选人的当前回答做即时评估，再决定追问方向。例如回答 Redis 缓存一致性时只讲了删除缓存，没有讲并发写，我会让系统自动追问延迟双删、binlog 监听或互斥锁方案。

### 亮点 2：能力画像

面试表达：

> 每一轮回答都会更新候选人的能力画像，最终报告不是简单平均分，而是按能力维度展示强弱项和变化趋势。

### 亮点 3：面试策略引擎

面试表达：

> 我把面试流程抽象成策略引擎，根据得分、题目分类、历史表现和剩余时间决定下一题，这比固定题单更接近真实面试。

## 五、推荐最小版本

第一版不要把全部面试流程重写。建议先做：

- 保留现有题单模式。
- 在每次回答后新增即时评估。
- 根据即时评估动态生成一条追问。
- 维护一个简单能力画像。
- 报告中增加“自适应追问记录”和“能力画像”。

第二版再做真正的动态下一题。
