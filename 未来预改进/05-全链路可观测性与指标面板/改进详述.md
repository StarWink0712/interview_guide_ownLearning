# 全链路可观测性与指标面板 - 改进详述

## 一、为什么做

这个项目已经有不少耗时较长和容易失败的链路：

- 文件解析。
- S3 上传下载。
- Redis Stream 异步任务。
- LLM 调用。
- Embedding 向量化。
- RAG 检索。
- SSE 流式输出。
- WebSocket 语音面试。

如果没有指标和链路追踪，出现“慢”“失败”“卡住”时只能看日志。这个模块目标是让项目具备生产级可观测能力。

## 二、目标效果

实现后，可以回答：

- 简历分析平均耗时是多少？
- 哪个 provider 失败率最高？
- RAG 检索耗时和 LLM 回答耗时分别是多少？
- 语音面试首 token 延迟、TTS 延迟、ASR final segment 数是多少？
- Redis Stream 当前积压多少任务？
- 最近 24 小时失败最多的任务类型是什么？

## 三、指标设计

### AI 指标

- `app.ai.invocation.count`
- `app.ai.invocation.latency`
- `app.ai.structured_output.retry.count`
- `app.ai.structured_output.failure.count`

标签：

- `scenario`
- `provider`
- `model`
- `status`

### RAG 指标

- `app.rag.retrieval.latency`
- `app.rag.retrieval.hit.count`
- `app.rag.answer.latency`
- `app.rag.no_result.count`

标签：

- `rewrite_enabled`
- `top_k`
- `status`

### 异步任务指标

- `app.async.task.created`
- `app.async.task.completed`
- `app.async.task.failed`
- `app.async.task.retry`
- `app.async.stream.length`

标签：

- `task_type`
- `stream`

### 语音指标

项目里已经有部分 Micrometer 计数和耗时记录，可以继续统一：

- `app.voice.interview.asr.latency`
- `app.voice.interview.llm.first_token_latency`
- `app.voice.interview.tts.latency`
- `app.voice.interview.turn.latency`
- `app.voice.interview.websocket.disconnect.count`

## 四、链路追踪设计

建议引入 traceId：

- HTTP 请求进入时生成或读取 `X-Trace-Id`。
- RAG 查询、AI 调用、异步任务沿用 traceId。
- Stream 消息中携带 traceId。
- 日志中打印 traceId。

后续可以接入 OpenTelemetry：

- HTTP span。
- DB span。
- Redis span。
- LLM custom span。
- Vector search custom span。

## 五、技术亮点

面试表达：

> 我给 AI 后端链路加了业务级可观测性，不只是 JVM 和 HTTP 指标，还包括 LLM 调用耗时、结构化输出重试、RAG 命中数量、异步任务失败率和语音首包延迟。这样能定位 AI 应用里最常见的质量和性能问题。

## 六、推荐最小版本

第一版：

- 统一 Meter 名称。
- 给 RAG 检索、LLM 调用、异步任务加指标。
- 增加 `/api/metrics/business-summary` 返回业务摘要。
- 日志 MDC 增加 traceId。

第二版：

- 接入 OpenTelemetry。
- 增加 Grafana Dashboard。
- 前端设置页或运维页展示关键指标。
