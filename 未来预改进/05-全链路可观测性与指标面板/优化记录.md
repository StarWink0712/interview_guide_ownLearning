# 全链路可观测性与指标面板优化记录

日期：2026-05-15

## 本次优化目标

按照 `AI实施计划.md` 先做轻量版业务可观测性，不引入复杂监控栈。重点实现 traceId、Micrometer 业务指标、AI/RAG/异步任务/语音链路指标接入，以及可直接访问的业务摘要接口。

## 已完成优化

1. 新增 TraceIdFilter
   - 新增 `common/observability/TraceIdFilter.java`。
   - 从请求头读取 `X-Trace-Id`。
   - 请求头不存在时自动生成 UUID。
   - 写入 MDC 的 `traceId`。
   - 响应头返回 `X-Trace-Id`。
   - 请求结束后清理 MDC，避免线程复用污染。

2. 日志增加 traceId
   - 更新 `logback-spring.xml`。
   - 日志级别模式增加 `traceId:%X{traceId:-}`，方便从日志中串起单次请求链路。

3. 新增指标记录器
   - `AiMetricsRecorder`
   - `RagMetricsRecorder`
   - `AsyncTaskMetricsRecorder`
   - `VoiceMetricsRecorder`
   - 这些 Recorder 都支持 `MeterRegistry` 缺失时 no-op，不影响业务主流程。

4. AI 指标接入
   - 改造 `StructuredOutputInvoker`。
   - 优先沿用 MDC 中的 HTTP traceId；没有 HTTP traceId 时继续生成 AI 调用 traceId。
   - 记录：
     - `app.ai.invocation.count`
     - `app.ai.invocation.latency`
     - `app.ai.structured_output.retry.count`
     - `app.ai.structured_output.failure.count`
   - 标签包含 scenario、provider、model、status。

5. RAG 指标接入
   - 改造 `KnowledgeBaseQueryService`。
   - 记录：
     - query rewrite 次数与耗时。
     - vector retrieval 耗时。
     - retrieval hit count。
     - no result 次数。
     - 同步/流式 answer 次数与耗时。
   - 失败路径也会记录指标。

6. 异步任务指标接入
   - 改造 `AbstractStreamProducer` 和 `AbstractStreamConsumer`。
   - Producer 发送成功记录 created，发送失败记录 failed。
   - Consumer 处理中记录 processing，完成记录 completed，失败记录 failed，重试记录 retry。
   - Stream 消息会携带当前 MDC traceId，Consumer 消费时恢复到 MDC，便于异步日志串联。

7. 语音指标统一封装
   - `VoiceInterviewWebSocketHandler` 原有 Micrometer 计数和耗时记录改为委托 `VoiceMetricsRecorder`。
   - 保留现有语音指标名称，避免破坏已有观测口径。

8. 新增业务摘要接口
   - 新增 `modules/monitoring/MonitoringController.java`。
   - 新增 `BusinessMetricsQueryService` 和 `BusinessMetricsSummaryDTO`。
   - 接口：

```text
GET /api/monitoring/business-summary
```

返回最近 24 小时摘要：

- recentTaskCount
- failedTaskCount
- aiInvocationCount
- aiSuccessRate
- ragQueryCount
- ragAverageHitCount
- voiceAverageTurnLatencyMs

数据来源：

- 异步任务表。
- AI 调用日志表。
- RAG retrieval 日志表。
- 内存 MeterRegistry 中的语音 turn timer。

## 当前效果

HTTP 请求链路：

```text
HTTP Request
-> TraceIdFilter 生成/读取 X-Trace-Id
-> MDC 写入 traceId
-> 日志输出 traceId
-> HTTP Response 返回 X-Trace-Id
```

异步任务链路：

```text
Producer 从 MDC 读取 traceId
-> Stream 消息携带 traceId
-> Consumer 恢复 traceId 到 MDC
-> 异步处理日志可串回原请求
```

业务指标链路：

```text
AI / RAG / AsyncTask / Voice
-> MetricsRecorder
-> MeterRegistry
-> /api/monitoring/business-summary 聚合关键摘要
```

## 后续建议

1. 接入 Spring Boot Actuator 的 Prometheus endpoint，暴露 Micrometer 指标。
2. 基于 Grafana 做 AI 调用成功率、RAG 命中率、异步任务失败率和语音延迟面板。
3. 引入 OpenTelemetry Java Agent，补齐 HTTP、DB、Redis、LLM 和 VectorStore span。
4. Stream retry 消息可进一步继承原 traceId，保证多次重试链路完全连续。
5. 前端 07 管理控制台可以新增“业务监控”页面调用 `/api/monitoring/business-summary`。
