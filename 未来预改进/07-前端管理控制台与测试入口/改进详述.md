# 前端管理控制台与测试入口 - 改进详述

## 一、为什么做

前面 6 个改进模块大多偏后端和工程化。如果没有前端入口，会出现几个问题：

- 后端能力做完后只能用 Swagger 或 curl 测试，演示效果弱。
- 面试官很难直观看到 AI 调用链路、RAG 命中文档、任务重试等亮点。
- 前后端字段不对齐时，问题发现得晚。
- 异步任务、评测集、监控指标这些能力没有管理入口，日常调试成本高。

这个模块的目标是新增一套“管理控制台 + 测试入口”，让每个后端改进都能在前端看见、点到、验证到。

## 二、目标效果

新增一个后台入口，例如：

```text
/admin
/admin/ai-traces
/admin/rag-eval
/admin/async-tasks
/admin/monitoring
/admin/interview-adaptive
```

也可以复用现有 `SettingsPage`，但更推荐新增独立管理控制台，避免设置页过重。

## 三、与后端模块的对应关系

### 01-AI调用观测与RAG评测中心

前端页面：

- AI 调用记录列表。
- 单次调用详情。
- RAG 检索链路详情。
- 命中文档片段展示。
- RAG 评测集列表。
- RAG 评测运行结果。

用户可以看到：

- 原始问题。
- 改写问题。
- TopK/minScore。
- 命中的知识库片段。
- 模型耗时。
- 结构化输出重试次数。

### 02-RedisStream异步任务可靠性升级

前端页面：

- 异步任务列表。
- 任务详情。
- 失败任务重试按钮。
- 任务取消按钮。
- Dead Letter 任务查看。

用户可以看到：

- 任务类型。
- 业务 ID。
- 当前状态。
- 重试次数。
- 最后错误。
- 创建时间和更新时间。

### 03-自适应模拟面试引擎

前端页面：

- 面试中展示动态追问原因。
- 面试后展示能力画像。
- 自适应决策时间线。
- 能力雷达图。

用户可以看到：

- 为什么系统追问这一题。
- 哪个能力维度被判定薄弱。
- 难度是否提升或降低。
- 最终推荐复习方向。

### 04-事务边界与数据一致性

这个模块本身偏后端，不一定需要独立前端页面。

可选前端入口：

- 文件上传补偿状态展示。
- Outbox 事件列表。
- 任务入队状态展示。

如果实现 Outbox，则需要：

- Outbox 事件列表。
- 手动重新发布按钮。

### 05-全链路可观测性与指标面板

前端页面：

- 业务指标 Dashboard。
- AI 成功率/失败率。
- RAG 平均命中数。
- 异步任务成功率。
- 语音面试平均延迟。

第一版可以用简单数字卡片和表格，不必一开始做复杂图表。

### 06-Testcontainers与质量保障

这个模块主要是后端测试，不强依赖前端。

可选前端入口：

- 测试数据生成按钮。
- RAG demo 数据导入。
- 清理测试数据。

## 五、设计原则

### 1. 前端先做测试入口，不做复杂运营后台

第一版目标是：

- 能查。
- 能看懂。
- 能点击重试。
- 能跑评测。
- 能辅助面试演示。

不要一开始追求复杂权限、复杂图表和复杂筛选。

### 2. 与后端 DTO 严格对齐

每个后端接口都要有 TypeScript interface。

例如：

```ts
export interface AiInvocationLog {
  id: number;
  traceId: string;
  scenario: string;
  providerId: string;
  model: string;
  success: boolean;
  latencyMs: number;
  createdAt: string;
}
```

### 3. 状态展示统一

任务状态、评测状态、AI 调用状态都用统一 `StatusBadge`。

状态颜色建议：

- `PENDING`：灰色。
- `PROCESSING`：蓝色。
- `COMPLETED` / success：绿色。
- `FAILED`：红色。
- `DEAD_LETTER`：紫色或深红。

### 4. 测试动作要有确认

危险操作需要确认：

- 任务重试。
- 任务取消。
- 重新发布 Outbox。
- 清理测试数据。

## 六、技术亮点

面试表达：

> 我不仅做了后端的 AI 调用观测、RAG 评测和异步任务治理，还补了前端管理入口，可以直接查看一次 RAG 问答命中了哪些文档、某个异步任务为什么失败、以及不同检索策略的评测结果。这样项目不只是代码层面能跑，也方便演示、调试和验证。

## 七、推荐最小版本

第一版只做 3 个页面：

1. `AiTracePage`
   - 最近 AI 调用列表。
   - RAG trace 详情。
   - 命中文档片段。

2. `AsyncTaskPage`
   - 任务列表。
   - 失败任务重试。

3. `RagEvalPage`
   - 评测集列表。
   - 运行评测。
   - 查看结果。

第二版再做：

- Monitoring Dashboard。
- 自适应面试洞察页。
- Outbox 管理页。

## 八、验收方式

后端实现某个模块后，前端必须能完成对应验证：

- AI trace：发起一次知识库问答，前端能查到 trace。
- RAG eval：前端能创建 case 并运行评测。
- Async task：上传简历或知识库后，前端能看到任务状态。
- 失败重试：模拟失败任务后，前端能点击重试。
- Adaptive interview：完成一次面试后，前端能看到能力画像。
