# 未来预改进总览

这个目录用于沉淀本项目未来可以逐步实现的技术增强方案。每个子目录都是一个相对独立的改进模块，包含两份文档：

- `改进详述.md`：面向人阅读，说明为什么做、做成什么样、技术亮点和面试表达。
- `AI实施计划.md`：面向未来的编码智能体阅读，说明改哪些文件、按什么步骤做、如何验收。

建议优先级：

1. `01-AI调用观测与RAG评测中心`
2. `02-RedisStream异步任务可靠性升级`
3. `04-事务边界与数据一致性`
4. `06-Testcontainers与质量保障`
5. `07-前端管理控制台与测试入口`
6. `03-自适应模拟面试引擎`
7. `05-全链路可观测性与指标面板`

推荐执行方式：

```text
先修稳定性 -> 再做观测与评测 -> 再做智能化体验 -> 最后做工程质量闭环
```

不要一次性全部实现。每个模块都可以作为一次独立迭代，完成后补测试、补 README、跑通核心链路，再进入下一个模块。

## 模块一览

### 01-AI调用观测与RAG评测中心

把 AI 调用、Prompt、RAG 检索、结构化输出重试记录下来，并提供离线评测能力。目标是让项目从“调模型”升级为“可解释、可评估、可回放的 AI 工程系统”。

### 02-RedisStream异步任务可靠性升级

增强 Redis Stream 异步任务系统，支持 pending 消息恢复、死信队列、任务幂等、任务管理接口。目标是把异步任务从“能跑”升级成“可恢复、可追踪、可重试”。

### 03-自适应模拟面试引擎

让模拟面试根据候选人回答动态调整追问方向和难度，生成能力画像。目标是让面试不再只是静态题单，而是更接近真实面试官。

### 04-事务边界与数据一致性

梳理外部 API、对象存储、LLM、Embedding、Redis 入队与数据库事务的边界。目标是降低长事务、脏状态、中间状态和重复处理风险。

### 05-全链路可观测性与指标面板

引入业务指标、耗时指标、错误指标和链路追踪。目标是能回答“慢在哪里、失败在哪里、哪类任务最多、哪类模型最不稳定”。

### 06-Testcontainers与质量保障

用真实 PostgreSQL + pgvector、Redis、S3 兼容存储做集成测试，补齐异步任务和 RAG 的关键测试。目标是让项目质量从“能手测”升级为“能自动验证”。

### 07-前端管理控制台与测试入口

为前面几个后端增强模块补齐前端入口，包括 AI 调用链路查看、RAG 命中文档展示、异步任务管理、评测集管理、指标面板、能力画像展示等。目标是让后端能力可以被测试、演示和面试讲解。
