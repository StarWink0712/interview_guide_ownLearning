# AI 调用观测与 RAG 评测中心 - 改进详述

## 一、为什么做

当前项目已经具备 Spring AI、多 Provider、结构化输出、RAG 检索、SSE 流式回答等能力，但 AI 调用过程仍偏黑盒：

- 不容易知道一次回答到底用了哪个 provider、哪个 model、哪个 prompt。
- 不容易追踪结构化输出失败了几次、失败原因是什么。
- RAG 问答无法直观看到 query rewrite 后的问题、命中的文档片段、相似度分数。
- 调整 TopK、minScore、rewrite 开关后，缺少可量化对比。
- 面试时容易被追问：“你怎么证明 RAG 效果变好了？”

这个模块的目标是把 AI 系统从“能调用模型”升级成“可解释、可回放、可评估”的 AI 工程系统。

## 二、目标效果

实现后，可以做到：

- 每次 AI 调用都有调用日志，包括 provider、model、场景、耗时、成功/失败、重试次数。
- 每次结构化输出失败都能记录解析错误、重试次数、最终是否成功。
- 每次 RAG 查询能看到原始问题、改写问题、检索参数、命中文档、相似度分数。
- 可以创建 RAG 评测集，批量运行问题，比较不同检索策略的命中率和回答质量。
- 可以在后台页面或接口中查看一次问答的完整链路。

## 三、核心概念

### AIInvocationLog

记录一次 AI 调用。适用于简历分析、面试出题、面试评估、RAG 问答、面试邀约解析等场景。

建议字段：

- `id`
- `traceId`
- `scenario`
- `providerId`
- `model`
- `promptVersion`
- `streaming`
- `structuredOutput`
- `attemptCount`
- `success`
- `latencyMs`
- `errorCode`
- `errorMessage`
- `createdAt`

### RagRetrievalLog

记录一次 RAG 检索过程。

建议字段：

- `id`
- `traceId`
- `sessionId`
- `question`
- `rewrittenQuestion`
- `candidateQueriesJson`
- `knowledgeBaseIdsJson`
- `topK`
- `minScore`
- `hitCount`
- `latencyMs`
- `createdAt`

### RagRetrievedChunkLog

记录某次检索命中的每个文档片段。

建议字段：

- `id`
- `retrievalLogId`
- `knowledgeBaseId`
- `chunkTextPreview`
- `score`
- `rank`
- `metadataJson`

### RagEvalDataset / RagEvalCase / RagEvalRun

用于离线评测。

- Dataset：一组评测集，例如“Java 基础知识库评测集”。
- Case：单个标准问题、期望关键词、关联知识库。
- Run：一次批量评测运行，记录策略和结果。

## 四、技术亮点

### 亮点 1：AI 调用可追踪

面试表达：

> 我没有把大模型当成黑盒，而是给每次 AI 调用建立 traceId，记录 provider、model、prompt version、耗时、重试次数和错误信息，方便排查模型不稳定和结构化输出失败问题。

### 亮点 2：RAG 检索可解释

面试表达：

> RAG 回答不仅返回答案，还能回看当时改写后的 query、TopK/minScore 参数、命中的知识片段和排序。这样可以定位回答错误到底是检索没命中，还是模型总结失败。

### 亮点 3：RAG 策略可评测

面试表达：

> 我设计了离线评测集，能比较 query rewrite 开关、TopK、相似度阈值对命中率和延迟的影响，而不是凭感觉调参数。

## 五、推荐最小版本

第一版不要做太复杂，先完成：

- 记录 AI 调用日志。
- 记录 RAG 检索日志和命中文档。
- 提供一个查询接口：按 `traceId` 查看一次完整链路。
- 提供一个简单评测接口：给定一组问题，批量跑 RAG 并输出命中情况。

前端页面可以后做，先用 Swagger 或接口返回 JSON 展示即可。

## 七、风险与边界

- 不要保存完整 API Key。
- Prompt 可以先保存 hash、版本号和摘要，避免日志表过大。
- 文档片段可以保存 preview，不一定保存完整 chunk。
- 流式回答不要每个 token 都写 DB，应该只记录整体调用和最终结果。
- 评测结果不要依赖模型自评作为唯一标准，可以先用关键词命中和检索命中率。
