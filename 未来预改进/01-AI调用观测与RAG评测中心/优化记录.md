# 优化记录：AI 调用观测与 RAG 评测中心

日期：2026-05-14

## 一、优化目标

根据 `AI实施计划.md`，本次优化将现有 AI/RAG 调用链路从“只执行调用”升级为
“可追踪、可解释、可查询、可基础评测”的最小可用版本。

重点目标：

- 记录结构化输出调用的成功/失败、重试次数、耗时和错误信息。
- 记录 RAG 检索过程中的 query rewrite、候选 query、TopK/minScore 和命中文档片段。
- 提供后端接口查询 AI 调用日志、RAG trace 和最近 RAG trace。
- 提供 RAG 评测集、评测用例、批量运行和运行结果查询能力。
- 保证观测日志写入失败时不影响主业务流程。

## 三、AI 调用观测优化

改造文件：

```text
app/src/main/java/interview/guide/common/ai/StructuredOutputInvoker.java
```

新增能力：

- 每次结构化输出最终成功或失败后，写入一条 AI 调用日志。
- 记录 `traceId`、业务场景、providerId、model、promptVersion、是否结构化输出。
- 记录 `attemptCount`、`success`、`latencyMs`、`errorCode`、`errorMessage`。
- 不保存完整 prompt，只保存 prompt hash 和 prompt 长度，避免日志表保存敏感或过长内容。
- 日志写入失败时只输出 warn，不影响原 AI 调用结果。

说明：

- provider/model 当前按默认 provider 配置记录，能覆盖项目现有默认结构化输出调用场景。
- 原有 Micrometer 指标逻辑保留。

## 四、RAG 检索观测优化

改造文件：

```text
app/src/main/java/interview/guide/modules/knowledgebase/service/KnowledgeBaseQueryService.java
app/src/main/java/interview/guide/modules/knowledgebase/service/RagChatSessionService.java
app/src/main/java/interview/guide/modules/knowledgebase/model/QueryResponse.java
frontend/src/api/knowledgebase.ts
```

新增能力：

- 同步和流式 RAG 查询都会生成 `traceId`。
- 同步知识库问答响应新增 `traceId` 字段，便于前端或接口使用 traceId 回查链路。
- RAG 聊天流式查询会把 `sessionId` 写入 RAG trace。
- 记录原始问题、改写问题、候选 query、知识库 ID 列表、TopK、minScore。
- 记录检索命中数量、检索耗时。
- 记录每个命中文档片段的 rank、knowledgeBaseId、score、metadataJson、chunk preview。
- 命中文档只保存 preview，不保存完整 chunk，避免日志表过大。

## 六、RAG 评测最小版本

新增服务：

```text
app/src/main/java/interview/guide/modules/aiobservability/service/RagEvaluationService.java
```

新增接口：

```text
POST /api/ai-observability/rag-eval/datasets
POST /api/ai-observability/rag-eval/datasets/{id}/cases
POST /api/ai-observability/rag-eval/datasets/{id}/runs
GET  /api/ai-observability/rag-eval/runs/{runId}
```

实现能力：

- 创建 RAG 评测集。
- 添加评测问题、期望关键词和关联知识库。
- 批量运行某个评测集。
- 对每个 case 记录命中 chunk 数、关键词命中数量、是否命中期望关键词、耗时。
- 保存每个 case 的检索 preview，便于排查检索质量。

说明：

- 第一版评测聚焦检索质量，不依赖 LLM 自评。
- 通过关键词命中和检索命中数量提供可重复、低成本的基础评测。

## 七、可靠性与边界处理

本次实现遵守以下边界：

- AI 调用日志和 RAG 检索日志写入失败，不影响主业务调用。
- 日志服务内部捕获异常并输出 warn。
- 不保存完整 prompt。
- 不保存完整 chunk，只保存 preview。
- Controller 只负责路由和委托。
- Service 负责业务编排。
- Repository 只负责数据访问。
- 新增接口不直接返回 Entity。

## 九、后续可继续优化

建议后续迭代：

- 在前端新增 AI 观测管理页，展示调用日志与 RAG trace。

- 将 AI 调用日志进一步接入统一链路追踪或指标面板。
