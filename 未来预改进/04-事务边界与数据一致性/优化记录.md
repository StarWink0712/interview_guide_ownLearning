# 事务边界与数据一致性优化记录

日期：2026-05-15

## 本次优化目标

按照 `AI实施计划.md` 缩小事务范围，避免事务方法中执行对象存储、Embedding/VectorStore、Redis Stream 入队等外部 IO，并补齐上传失败补偿与 afterCommit 入队能力。

## 已完成优化

1. 新增事务审计文档
   - 新增 `docs/transaction-boundary-audit.md`。
   - 按纯 DB 操作、已拆分风险点、已补偿一致性风险点、afterCommit 入队和剩余观察点分类记录。

2. 新增 afterCommit 执行器
   - 新增 `TransactionAfterCommitExecutor`。
   - 当前没有事务时直接执行。
   - 当前存在事务同步时注册 `afterCommit` 回调。
   - 事务回滚时不会执行任务。

3. 异步任务入队改为 afterCommit 语义
   - `AnalyzeStreamProducer`
   - `VectorizeStreamProducer`
   - `EvaluateStreamProducer`
   - `VoiceEvaluateStreamProducer`
   - 这些 Producer 现在会在事务提交后才写 Redis Stream，并在发送成功后更新统一异步任务的 `messageId`。

4. 简历重新分析事务边界优化
   - 移除 `ResumeUploadService.reanalyze` 的大事务。
   - 对象存储下载和文本解析保持在事务外。
   - 新增 `ResumePersistenceService.prepareReanalyze(...)`，只在短事务内更新 `resumeText`、`PENDING` 状态和错误信息。
   - 重新分析任务入队由 Producer afterCommit 保护。

5. 简历上传补偿
   - `ResumeUploadService.uploadAndAnalyze` 在 RustFS 上传成功后，如果 DB 保存失败，会补偿删除刚上传的简历文件。
   - 补偿删除失败只记录 warn，不覆盖原始 DB 异常。

6. 知识库重新向量化事务边界优化
   - 对象存储下载和解析保持在事务外。
   - 状态更新继续通过 `KnowledgeBasePersistenceService.updateVectorStatusToPending` 短事务完成。
   - 向量化任务入队由 Producer afterCommit 保护。

7. 知识库上传补偿
   - `KnowledgeBaseUploadService.uploadKnowledgeBase` 在 RustFS 上传成功后，如果 DB 保存失败，会补偿删除刚上传的知识库文件。
   - 补偿删除失败只记录 warn，不覆盖原始 DB 异常。

8. 向量化长事务拆除
   - 移除 `KnowledgeBaseVectorService.vectorizeAndStore` 的方法级 `@Transactional`。
   - 保留 `deleteByKnowledgeBaseId` 的短事务。
   - `vectorStore.add(batch)` 不再被外层事务包裹，降低 Embedding/VectorStore 操作占用 DB 连接的风险。

9. 知识库删除事务边界收敛
   - 移除 `KnowledgeBaseDeleteService.deleteKnowledgeBase` 的方法级事务。
   - 避免对象存储删除运行在长事务中。

## 当前效果

关键链路调整后：

```text
上传文件到对象存储
-> DB 保存
-> DB 成功后入队
-> DB 失败则补偿删除对象存储文件
```

重新分析和重新向量化调整后：

```text
事务外下载/解析
-> 短事务更新状态
-> 事务提交后 Redis Stream 入队
```

向量化调整后：

```text
短事务删除旧向量
-> 事务外分块与 VectorStore.add
-> Consumer 负责最终 COMPLETED/FAILED 状态更新
```

## 后续建议

1. 引入 Outbox Pattern，进一步保证 DB 状态与 Redis Stream 发送的最终一致性。
2. 为知识库向量增加 `vector_version` 或 active version，避免旧向量删除后新向量写入失败导致短暂不可检索。
3. 增加对象存储孤儿文件扫描与清理任务，补偿删除失败时可后台恢复。
4. 知识库删除可升级为“标记删除中 + afterCommit 删除对象 + 失败补偿任务”的两阶段删除流程。
