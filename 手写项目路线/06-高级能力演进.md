# 06 高级能力演进

## 核心原则

高级能力不是同时加入，而是一次只改变一个变量。

每个阶段都执行：

```text
保留原同步实现
  → 增加新实现
  → 测试新实现
  → 切换流量
  → 验证失败和恢复
  → 再删除旧实现
```

## A. Redis 基础

先只加入 Redis 客户端和 `RedisService`，练习：

```text
String
Hash
过期时间
删除
原子自增
```

验收：

- Redis 不可用时错误清晰。
- Key 有统一前缀。
- 测试数据有过期时间。
- 业务 Service 不直接散落 Redisson API。

## B. Redis Stream 异步任务

先只改造“简历 AI 分析”，不要三个任务一起迁移。

创建顺序：

```text
AsyncTaskStatus
AsyncTaskType
AsyncTaskEntity
AsyncTaskRepository
AsyncTaskService
AbstractStreamProducer
AbstractStreamConsumer
AnalyzeStreamProducer
AnalyzeStreamConsumer
任务状态查询接口
```

流程：

```text
上传简历
  → 数据库创建 PENDING 任务
  → 事务提交后发送 Stream 消息
  → 消费者标记 RUNNING
  → 调用 AI
  → 保存结果
  → 标记 SUCCESS
```

必须处理：

```text
重复消费
消费者崩溃
最大三次重试
任务实体已删除
消息 ACK 失败
Pending Entries List
```

验收后，再迁移面试评估和知识库向量化。

## C. 对象存储

本地文件存储稳定后，再用 S3/RustFS 替换。

先抽象接口：

```java
public interface FileStorageService {

  String upload(...);

  InputStream download(...);

  void delete(...);
}
```

实现：

```text
LocalFileStorageService
S3FileStorageService
```

通过配置选择实现。业务上传逻辑不应该知道 AWS SDK。

## D. 知识库基础版

先不做向量搜索。

第一轮：

```text

```

先理解切片、来源和检索结果，再加入 embedding。

## E. pgvector 和 RAG

分四步：

```text
1. 单独验证 embedding 能生成 1024 维向量
2. 单独验证 pgvector 能保存和相似度查询
3. 把文档切片批量向量化
4. 把检索结果放入 LLM 上下文生成回答
```

RAG 请求链路：

```text
用户问题
  → 可选的问题改写
  → embedding
  → pgvector TopK 检索
  → 分数过滤
  → 拼接上下文
  → ChatClient
  → 返回答案和来源
```

每一步都要记录：

```text
原始问题
改写问题
检索到的 chunk
相似度分数
最终引用来源
模型耗时
```

没有这些信息，RAG 答错时很难定位。

```text

```

## G. PDF 导出

## I. 可观测性

先记录最有用的指标：

```text
AI 调用次数
AI 成功率
AI 调用耗时
异步任务成功率
异步任务等待时间
RAG 检索耗时
检索 chunk 数
```

日志至少包含：

```text
traceId
sessionId/taskId
provider
model
duration
result status
```

不要记录完整 API Key、完整简历或敏感音频内容。

## J. 自适应面试

普通三题面试稳定后再加入：

```text
单轮能力评价
能力维度
能力画像
下一题难度决策
追问决策
决策轨迹
最终统一评价
```

先用确定性规则实现决策，再让 LLM 参与决策。否则无法判断问题来自业务状态还是模型随机性。

## K. WebSocket 语音面试

最后实现，因为它同时涉及：

```text
WebSocket
音频编码
ASR
VAD
LLM
TTS
并发状态
断线恢复
异步评估
资源清理
```

拆分顺序：

```text
1. WebSocket 文本回声
2. WebSocket 会话生命周期
3. 浏览器录音并上传音频帧
4. ASR：音频转文字
5. 文本进入已有文字面试服务
6. TTS：面试官文字转音频
7. 实时字幕
8. 打断、暂停、恢复
9. 会话结束后的异步总评
10. 并发、限流和资源清理
```

不要直接从“录音”跳到完整实时语音面试。
