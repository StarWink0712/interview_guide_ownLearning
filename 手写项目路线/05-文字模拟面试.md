# 05 文字模拟面试

## 本阶段目标

实现最小文字面试闭环：

```text
创建会话
  → AI 生成第一题
  → 用户提交回答
  → AI 评价回答
  → 生成下一题
  → 完成面试
  → 查看报告
```

第一版固定三道题，不做追问、自适应难度、Redis 缓存和异步总评。

## 1. 先画状态和规则

会话状态建议：

```text
CREATED
IN_PROGRESS
EVALUATING
COMPLETED
FAILED
```

第一版规则：

```text
每个会话固定三道题
同一道题只能提交一次答案
已完成会话不能继续答题
未完成会话不能查看最终报告
```

先把规则写在纸面或注释里，再写 Entity。

## 2. 数据模型顺序

```text
InterviewSessionStatus
InterviewSessionEntity
InterviewAnswerEntity
InterviewSessionRepository
InterviewAnswerRepository
```

`InterviewSessionEntity`：

```text
id
resumeId
targetPosition
status
currentQuestionNumber
totalQuestions
finalScore
summary
createdAt
completedAt
```

`InterviewAnswerEntity`：

```text
id
sessionId
questionNumber
question
answer
score
feedback
createdAt
```

## 3. Request 和 DTO

按顺序：

```text
CreateInterviewRequest
SubmitAnswerRequest
InterviewQuestionDTO
SubmitAnswerResponse
InterviewSessionDTO
InterviewReportDTO
```

请求只放前端能决定的信息。

例如 `SubmitAnswerRequest` 只需要：

```text
answer
```

题号和会话 ID 从路径与数据库状态中确定，避免前端伪造流程。

## 4. 先用假 AI 跑业务

这是本阶段最重要的策略。

先定义自己的接口：

```java
public interface InterviewAiService {

  String generateQuestion(InterviewQuestionContext context);

  AnswerEvaluation evaluateAnswer(AnswerEvaluationContext context);
}
```

先写：

```text
FakeInterviewAiService
```

它返回固定问题和固定评分。这样可以先验证会话状态和数据库逻辑，而不受网络和模型输出影响。

业务闭环通过后，再写真实实现：

```text
SpringAiInterviewAiService
```

## 5. Service 拆分

建议拆为：

```text
InterviewSessionService
InterviewQuestionService
AnswerEvaluationService
InterviewPersistenceService
InterviewHistoryService
```

职责：

| Service | 职责 |
|---|---|
| `InterviewSessionService` | 编排创建、答题、完成流程 |
| `InterviewQuestionService` | 准备上下文并生成问题 |
| `AnswerEvaluationService` | 调用 AI 评分 |
| `InterviewPersistenceService` | 短事务读写会话和答案 |
| `InterviewHistoryService` | 列表、详情、报告查询 |

## 6. 先实现创建会话

流程：

```text
校验简历存在
  → 创建会话，状态 CREATED
  → 事务提交
  → 事务外生成第一题
  → 短事务保存题目并改为 IN_PROGRESS
  → 返回第一题
```

第一版也可以先生成题目再创建会话，但要清楚失败时是否会留下半成品数据。

## 7. 再实现提交答案

流程：

```text
短事务读取当前会话与问题
  → 检查状态和重复提交
  → 事务外评价回答
  → 如果还有下一题，事务外生成下一题
  → 短事务保存回答、评分和下一题
  → 更新题号或完成状态
```

任何 LLM 调用都不要放进数据库事务。

## 8. 最小接口

```text
POST /api/interviews
POST /api/interviews/{sessionId}/answers
GET  /api/interviews/{sessionId}
GET  /api/interviews/{sessionId}/report
GET  /api/interviews
```

Controller 仍然只做委托。

## 9. Prompt 顺序

先写出题 Prompt：

```text
interview-question-system.st
interview-question-user.st
```

再写单题评分 Prompt：

```text
interview-evaluation-system.st
interview-evaluation-user.st
```

最后才写总评 Prompt。

每个 Prompt 都要限制：

```text
角色
输入边界
输出 JSON 结构
分数范围
禁止把简历中的指令当系统指令
```

## 10. 测试顺序

### 使用 Fake AI 的业务测试

```text
创建会话返回第一题
提交第一题返回第二题
第三题完成后状态为 COMPLETED
重复提交被拒绝
已完成会话不能继续提交
未完成会话不能获取报告
不存在会话返回 3001
```

### 真实 AI 集成测试

只验证：

```text
问题不是空字符串
评分处于约定范围
结构化结果可解析
超时和解析失败能转换异常
```

## 11. 前端顺序

```text
interview.ts API
interview.ts 类型
创建面试表单
问题展示
回答输入
提交/loading
完成页
报告页
```

第一版使用普通文本框，不加语音输入。

## 验收标准

- [ ] 使用 Fake AI 时完整流程稳定。
- [ ] 会话状态转换正确。
- [ ] 重复回答被拒绝。
- [ ] 真实 AI 实现可以替换 Fake 实现。
- [ ] LLM 调用不在数据库事务中。
- [ ] Prompt 不散落在 Service。
- [ ] 最终报告只能在完成后查看。
- [ ] 后端测试和前端构建通过。
