# AI 面试平台手写路线

这套文档用于从零手写一个缩小版 AI 面试平台，并逐步演进到当前项目的完整能力。

目标不是逐文件抄写现有项目，而是理解每一层为什么出现、依赖谁、如何验证。

## 使用规则

1. 严格按文档编号执行，不要跳阶段。
2. 每次只完成一个可以运行的小闭环。
3. 每写完一个类，先解释它的职责，再运行或测试。
4. 当前阶段的验收项没有全部通过，不进入下一阶段。
5. 第一遍追求正确和清楚，暂时不要追求功能数量。
6. 遇到问题先看请求经过了哪一层，再看日志，不要直接复制现项目代码。

## 项目演进顺序

```text
Spring Boot 启动
  ↓
统一响应与异常处理
  ↓
面试日程 CRUD
  ↓
React 前后端闭环
  ↓
简历上传、解析、持久化
  ↓
单 Provider AI 调用
  ↓
文字模拟面试
  ↓
Redis Stream 异步任务
  ↓
知识库、向量化、RAG
  ↓
限流、对象存储、PDF、监控
  ↓
WebSocket 语音面试
```

## 每个模块固定写法

以后每个业务模块都尽量遵循下面的顺序：

```text
1. 先写业务用例和接口草图
2. 枚举和值对象
3. Entity
4. Repository
5. Request
6. DTO/Response
7. Mapper 或转换方法
8. Service
9. Controller
10. Service 单元测试
11. Controller 或集成测试
12. 前端类型
13. 前端 API
14. 前端页面
```

## 第一遍暂时不写的内容

以下能力都很有价值，但会让入门阶段同时面对过多问题：

- 多 LLM Provider 动态配置
- Redis Stream
- pgvector
- S3/RustFS
- WebSocket
- ASR/TTS
- 分布式限流
- PDF 导出
- 可观测性
- 自适应面试

等同步业务闭环稳定后，再逐个加入。
