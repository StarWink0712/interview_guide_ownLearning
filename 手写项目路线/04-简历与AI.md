# 04 简历与 AI

## 本阶段目标

分两轮完成简历模块：

```text
第一轮：上传 → 校验 → 本地保存 → 文本解析 → 数据库保存
第二轮：读取文本 → 调用一个 LLM → 解析结果 → 数据库保存
```

必须先完成无 AI 版本，再接入 AI。

## 第一轮：文件闭环

### 1. 先写数据模型

创建顺序：

```text
ResumeEntity
ResumeAnalysisEntity
ResumeRepository
ResumeAnalysisRepository
ResumeListItemDTO
ResumeDetailDTO
```

`ResumeEntity` 第一版字段：

```text
id
originalFileName
storagePath
contentType
fileSize
fileHash
parsedText
createdAt
updatedAt
```

`ResumeAnalysisEntity` 第一版字段：

```text
id
resumeId
score
summary
strengths
weaknesses
createdAt
```

第一遍可以先不建立复杂对象关系，用 `resumeId` 表达关联。理解清楚后再决定是否使用 JPA 关联。

### 2. 写基础设施服务

按顺序创建：

```text
FileValidationService
FileHashService
FileStorageService
TextCleaningService
DocumentParseService
```

每个类只负责一件事：

| 类 | 职责 |
|---|---|
| `FileValidationService` | 校验大小、扩展名、Content-Type |
| `FileHashService` | 计算 SHA-256，用于去重 |
| `FileStorageService` | 保存、读取、删除本地文件 |
| `TextCleaningService` | 清理空白、控制字符等 |
| `DocumentParseService` | 使用 Tika 提取文本 |

此时加入 Apache Tika 依赖：

```groovy
implementation 'org.apache.tika:tika-core:2.9.2'
implementation 'org.apache.tika:tika-parsers-standard-package:2.9.2'
```

先分别为这些小服务写测试，再写上传业务。

### 3. 拆分业务 Service

不要写成一个几百行的 `ResumeService`。

建议：

```text
ResumeUploadService
ResumeParseService
ResumePersistenceService
ResumeHistoryService
ResumeDeleteService
```

职责示例：

```text
ResumeUploadService
  → 校验文件
  → 计算哈希
  → 检查重复
  → 保存文件
  → 调用解析服务
  → 调用持久化服务
```

### 4. 注意事务与文件系统

文件保存属于外部 I/O，不能简单地把整个上传方法放进长事务。

建议流程：

```text
校验文件
  → 保存本地文件
  → 解析文本
  → 开启短事务保存数据库
```

数据库保存失败时，要考虑删除已经保存的文件。

第一遍至少把补偿逻辑写清楚，并记录完整异常堆栈。

### 5. 写 Controller

第一版接口：

```text
POST   /api/resumes
GET    /api/resumes
GET    /api/resumes/{id}
DELETE /api/resumes/{id}
```

上传接口接收：

```java
@RequestPart("file") MultipartFile file
```

仍然只返回 DTO，不返回 Entity。

### 文件闭环验收

- [ ] TXT 文件上传成功。
- [ ] PDF 或 DOCX 至少一种解析成功。
- [ ] 不支持的类型被拒绝。
- [ ] 超限文件被拒绝。
- [ ] 相同文件哈希可以识别重复。
- [ ] 数据库记录和本地文件一致。
- [ ] 列表和详情不返回 Entity。
- [ ] 文件相关测试通过。

## 第二轮：接入一个 AI Provider

### 1. 先定义 AI 输入输出

不要先写 ChatClient 配置。先明确：

输入：

```text
清理后的简历文本
```

输出：

```text
总分
总结
优势列表
改进建议列表
```

用不可变 `record` 定义输出：

```text
ResumeAnalysisResponse
```

### 2. 加入 Spring AI

只接一个 OpenAI 兼容 Provider：

```groovy
implementation 'org.springframework.ai:spring-ai-starter-model-openai:2.0.0-M4'
```

API Key 放环境变量，不写进 Git：

```text
AI_API_KEY
```

第一版只需要：

```text
一个 base URL
一个 API Key
一个 model
一个 ChatClient
```

暂时不要写：

- 数据库动态 Provider
- Provider 注册中心
- API Key 加密
- Provider 连通性管理页面
- Embedding Provider

### 3. Prompt 文件化

创建：

```text
src/main/resources/prompts/resume-analysis-system.st
src/main/resources/prompts/resume-analysis-user.st
```

System Prompt 负责：

```text
角色
评分原则
输出格式
安全边界
```

User Prompt 只负责放入简历文本。

不要在 Service 中拼接超长字符串。

### 4. 写 `ResumeGradingService`

职责：

```text
读取 Prompt
调用 ChatClient
解析结构化结果
把调用异常转成 BusinessException
```

先写最简单的一次调用。成功后再增加结构化输出重试。

### 5. 正确划分调用流程

禁止：

```text
开启数据库事务
  → 调用 LLM 等待数秒
  → 保存结果
  → 提交事务
```

正确拆分：

```text
事务 1：读取并确认简历存在
  ↓
事务外：调用 LLM
  ↓
事务 2：保存分析结果
```

可以使用独立的 `ResumePersistenceService` 承担事务写入，避免同类内部调用事务方法。

### 6. 先同步，再异步

第一版接口可以同步：

```text
POST /api/resumes/{id}/analyze
```

同步流程稳定后，才在高级阶段迁移到 Redis Stream。

### 7. AI 测试

单元测试不要真实调用模型。Mock `ChatClient` 或封装后的 AI 客户端，验证：

```text
正常结果可以保存
简历不存在时不调用 AI
AI 超时时返回 AI_SERVICE_TIMEOUT
输出无法解析时返回 AI_SERVICE_ERROR
数据库事务不包住外部调用
```

另建一个手动或集成测试验证真实 Provider，但不要让它默认随全部单元测试执行。

## 完整验收

- [ ] 无 AI 的文件流程先独立通过。
- [ ] API Key 未硬编码。
- [ ] Prompt 位于 resources。
- [ ] 只接入一个 Provider。
- [ ] AI 调用发生在数据库事务之外。
- [ ] AI 结果保存使用短事务。
- [ ] AI 异常转换为 `BusinessException`。
- [ ] 前端能看到简历分析结果。

全部完成后，进入 [05-文字模拟面试.md](05-文字模拟面试.md)。
